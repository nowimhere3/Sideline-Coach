## Phone flow and desktop compatibility

Previously, the remote eligibility answer led to “Preview opens on your computer.” Now the existing GET eligibility response with `reason: remote-viewer` and `remotePreview: true` triggers POST `/api/games/preview/remote`. The existing `api` helper supplies `X-Sideline-Action: 1`, JSON content type, and same-origin credentials; the browser supplies normal same-origin mutation Origin behavior. POST carries only `gameId` and optional selected `staticEntrypoint`.

Preview Work loads the server-returned `remote.frameUrl` directly into the existing iframe, bypassing local loopback rewriting. Explicit Open in new tab uses `remote.openUrl`; page selection uses the returned `page.remoteUrl` for the frame and explicit link without changing canonical home. A static ambiguity choice re-POSTs the selected entrypoint.

The browser does not construct Preview origins, derive Game tags, create grants, handle cookie secrets, or display target ports/Stadium identity/local URLs. The iframe sandbox and no-referrer policy are unchanged. The original Sideline location is never assigned; the existing synchronous second Sideline viewer tab still owns Preview. No raw Game tab opens automatically.

Desktop retains its local GET resolution, `previewFrameUrl` mapping, Desktop/Tablet/Phone/Rotate controls, directTabOnly handling and explicit raw-Game link. Remote presentation defaults to the existing fill preset and hides Tablet/Phone and Rotate, as S57.45 S6 specifies. Stage/iframe CSS was not changed, preserving the S57.43B vertical layout.
