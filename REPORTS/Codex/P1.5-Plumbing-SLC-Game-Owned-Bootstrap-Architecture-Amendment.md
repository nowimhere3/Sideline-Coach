**NOT RECOMMENDED:** a `plumbingRoot` contract field, a second filesystem owner, S7/S9 special cases, root-level `Diagnostics/`, speculative empty folders, or migration of any established Game.

# 3. CORE OWNERSHIP RULE

A Game-visible folder belongs under `Plumbing SLC/` by default only when all of the following are true:

1. it exists primarily to operate Sideline Coach for this Game rather than to implement or document the Game itself;
2. Sideline can name its purpose and lifecycle narrowly;
3. the GameFilesystemContract or another approved Game-scoped contract owns the coordinate;
4. the exact authoritative Stadium can create or verify it without escaping the Game; and
5. adoption of existing Game-owned material has already been considered.

Therefore the new canonical Sideline report workspace, the approved Sideline SOP/onboarding workspace, future explicitly approved diagnostics, and intentionally Game-visible Sideline operational artifacts may live beneath `Plumbing SLC/`.

Project code, `src/`, project-native `docs/`, README files, product assets, project-native reports, and pre-existing onboarding/SOP material remain the Game's own furniture. Sideline may adopt their coordinates when evidence or the human selects them, but it must not relocate, rename, merge, or claim ownership of them.

# 4. NEW-GAME BOOTSTRAP RULE

Recommend **Option B**: bootstrap one coherent approved workspace containing both `Plumbing SLC/Reports` and `Plumbing SLC/SOP`.

For this rule, **NEW** means filesystem-unconfigured for Sideline: there is no authoritative human/adopted/created Reports or SOP coordinate, fresh exact-Game evidence finds no competing meaningful candidate, and no collision or unsafe path blocks the reserved topology. It does not mean “the Git repository has few files” or require Sideline to infer a repository's age.

The decision order is:

1. preserve and verify any durable human/adopted/created coordinate;
2. inspect and adopt existing Reports and SOP evidence independently;
3. surface ambiguity or Needs Attention without mutation;
4. only when nothing relevant exists, authorize the `Plumbing SLC` bootstrap plan;
5. if a recognizable partial `Plumbing SLC` workspace exists, complete only the missing approved child when that dimension is unambiguous and safe.

“Atomic workspace” means one coherent bootstrap decision and one bounded, idempotent ensure plan. It does **not** mean destructive transactional rollback. The Stadium must preflight every required path before the first create. A race or I/O failure may still leave a truthful partial structure; Sideline records the successful coordinates and Needs Attention for the failure, then retries safely. It never deletes a successfully created directory to simulate rollback.

# 5. EXISTING-GAME COMPATIBILITY RULE

Existing coordinates win over the new default.

- `REPORTS/` plus `Project SOP/`: adopt both, create nothing, leave `Plumbing SLC/` absent.
- `Reports-SLC/` plus `Onboarding-Docs/`: preserve both, create nothing, migrate nothing.
- `Plumbing SLC/Reports/` plus `Project SOP/`: adopt `Plumbing SLC/Reports` for Reports and `Project SOP` for SOP. Do not force both dimensions beneath the parent.
- Any valid human-selected nested path remains authoritative and is only verified, never re-detected merely because the new default is prettier.
- A mature Game with an established Reports coordinate and no SOP coordinate keeps Reports and remains `sop.state = not-set`; the amendment does not add `Plumbing SLC/SOP` beside an unrelated established Reports root.
- A mature Game with an established SOP coordinate and no Reports coordinate keeps SOP. It is not “normalized” into the new workspace. A report destination remains unset until existing evidence, a human choice, or an explicitly eligible bootstrap decision supplies it.

The default is selected only before an established layout exists, or to finish an unambiguous partial reserved workspace. Presence of unrelated project files does not make Sideline guess a different topology.

# 6. REPORTS-SLC LEGACY RULE

`Reports-SLC/` is a permanent fully recognized valid legacy layout. Keep it in `RECOGNIZED_REPORT_ROOT_NAMES` and in additive legacy report globs with no deprecation clock.

# 7. SOP BOOTSTRAP DECISION

Choose **Option B** and create `Plumbing SLC/SOP` in the clean initial workspace.

This is justified because SOP/onboarding is already a first-class durable S6 coordinate and a live S10 Game Setup control. Creating its approved home at the same moment as Reports gives a new Game one coherent Sideline utility room and prevents a later Sideline-owned SOP folder from becoming new root-level furniture. It is not a speculative Diagnostics-style placeholder.

The SOP folder is a coordinate only. This amendment does not create SOP content, copy onboarding material, select a source document, or replace project-native documentation. An existing SOP candidate is adopted instead. Multiple candidates require human choice. `FolderProvenance` already includes `created`, and the S10 projection already renders that as `Created by Sideline`; implementation need only make the SOP decision logic preserve and verify created provenance just as it does other authoritative SOP coordinates.

# 19. RISKS / OPEN QUESTIONS

1. **Meaning of NEW:** this amendment recommends “filesystem-unconfigured for Sideline,” which is evidence the current architecture can prove. If product intent instead means chronological repository creation, a separate authoritative lifecycle signal or explicit consent is required; file count, Git age, or folder appearance must not be guessed.
2. **Logical atomicity:** safe non-destructive creation cannot promise rollback atomicity. Preflight minimizes partial results; idempotent completion and truthful state are the correct guarantees.
3. **Empty directories and Git:** Git does not preserve empty folders. This amendment deliberately adds no placeholder file. A cloned Game may need Sideline to re-ensure the approved empty structure when its exact Game contract/bootstrap state permits it. Portable seeded content would require a separate product decision.
4. **Casing:** the reserved parent/children need case-insensitive recognition with on-disk casing preservation and multiple-variant attention, especially on case-sensitive hosts.
5. **Legacy pending intent:** an old persisted `create-reports-slc` action must be re-evaluated against fresh evidence before new code mutates. It must not silently become permission for a different tree.
6. **No current SOP content writer:** the folder is justified as an existing product coordinate and human destination, not as a promise that Sideline will generate SOP content in this play.

None of these requires replacing the Control Plane contract owner, migrating mature Games, or introducing a new authority model.
