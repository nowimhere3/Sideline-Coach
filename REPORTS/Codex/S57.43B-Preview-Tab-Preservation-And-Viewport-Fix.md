## Root cause: Sideline was replaced

S57.43A reserved a blank tab and later navigated that tab directly to `endpoint.clientUrl`, while the original click path simultaneously opened the embedded Preview modal in Tab 1. The result inverted the intended ownership: Tab 1 was consumed by Preview controls and Tab 2 became the raw Game.

## Exact navigation correction

The Preview button now synchronously opens a same-Sideline URL carrying the exact `previewWork` Game identifier. The original tab performs no modal, endpoint, iframe, or location mutation. In the new Sideline viewer tab, normal status convergence opens the existing Preview sheet and resolves the existing `PreviewEndpoint` into its iframe. The raw endpoint is never opened automatically; only the existing explicit `Open in new tab` anchor targets the raw Game. Closing the Preview viewer attempts to close that script-opened tab.

No tab registry, cross-tab synchronization, history system, remote Preview, or alternate endpoint architecture was added.

## Root cause: embedded viewport was tiny

The prior delta gave the outer sheet a viewport-relative height but left the actual stage/device/iframe height transfer dependent on an implicit grid and runtime inline sizing. Live field proof showed that the definite outer height was not reaching the rendered Game surface reliably, leaving the stage as a shallow strip.

## Exact viewport correction

The sheet is now an explicit column flex container. Header, notice, and footer retain intrinsic height; `.preview-stage` owns all remaining space with `flex: 1 1 0`, `height: 0`, and `min-height: 0`. The iframe now has explicit `width: 100%` and `height: 100%`. Desktop fill occupies the full stage, while Tablet and Phone retain their simulated widths and continue scaling against both the now-substantial stage width and height. Rotate behavior is unchanged.
