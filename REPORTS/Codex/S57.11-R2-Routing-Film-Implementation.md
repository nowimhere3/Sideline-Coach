# Event Contract Implemented

## Decision

One decision event is attempted at the existing real `play-dispatched` seam and only there. Preview calls never reach that seam and write nothing.

The event records:

- schema version, numeric event time, `clientRef`, and Game identity
- `baseline` as the existing route actually selected
- `chosen` as the exact dispatched seat/target
- existing authority as `auto-baseline`, `coach-manual`, or `coach-envelope`
- dispatch versus handoff action
- transport, concrete Player instance, Player type, selected model/effort where applicable
- R1 seat-derived open resource-pool identity
- chosen-pool-only `receiptBefore`

R2 writes no `recommendation` field. The optional schema seam remains available for R6 without rewriting R2 history.

## Outcome

The outcome attaches after the Work Ledger processes terminal `turn.changed` truth. Delivery rejection also records the existing `not-sent` outcome. Each joins its decision through the same `clientRef` and is restart-deduped.

The event records only facts available at that seam:

- canonical `LedgerOutcome`
- dispatch/start/finish timing and duration
- retry count (`0`; the current dispatch path has no same-`clientRef` resend behavior)
- report-produced state known at the outcome capture instant
- chosen-pool-only `receiptAfter`
- concurrency digest
- play-level isolation summary plus per-window burn observations where evidence permits

No failure class or substitution target is fabricated when the existing source has no canonical structured fact.

# Open Receipt Identity And R1 Compliance

Durable receipts use open data:

- `pool: string`
- `window: string`
- `windowLengthMin: number`
- optional `remainingPercent`, `resetsAt`, and `observedAt`
- `stale: boolean`

The receipt wrapper carries `evidence: known | unknown` and capture time. Unknown/unsupported pools have UNKNOWN evidence and an empty window list; R2 does not invent a sentinel percentage, reset, or window.

Receipt capture calls `RoutingEconomicsReader.read()` and selects only the pool consumed by the chosen seat. It never polls a provider, scrapes UI, caches current resource truth, or reads Film back into economics.

# Concurrency And Isolation

Concurrency is reconstructed from existing Work Ledger current/recent Play intervals across Games. Film adds no independent active-work authority.

Each overlapping digest contains only:

- overlapping `clientRef`
- concrete Player instance and optional Player type
- seat-derived resource pool
- start/end when known
- overlap duration

Same known pool overlap is burn contamination. Different known pools are operational context only. Unknown pool overlap remains explicitly separate and is never treated as proven same-pool contamination.

Per-window isolation behavior:

- HIGH — same reset cycle, valid fresh brackets within 15 minutes, no same-pool overlap
- MEDIUM — same evidence with brackets within 45 minutes
- LOW — valid same-cycle receipts with same-pool overlap; no pro-rata ownership is invented
- NONE — stale/unproven/missing receipt, reset-cycle change, impossible negative delta, invalid bracket, or bracket beyond 45 minutes

A zero percentage-point delta is marked as censored at at most 1%, not treated as exact zero burn. A play-level NONE summary remains present even when UNKNOWN evidence yields no window observation.

# Tolerant Reader

The reader processes all retained generations oldest-first. A malformed JSON line, torn trailing line, unsupported schema, invalid event, or safely ignorable future event kind is diagnosed and skipped independently. One damaged line never hides earlier or later valid events and never crashes normal Sideline operation.
