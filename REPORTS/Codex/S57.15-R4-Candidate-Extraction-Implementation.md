# Previous Eligibility Seam

Eligibility was distributed inside `src/routing-policy.ts`:

- `computeAutoRoute(...)` directly excluded Terminal/direct-shell and `autoEligible === false` entries.
- A second filter selected `ready` or `busy` candidates.
- `computeContextAwareRoute(...)` separately excluded Terminal/direct-shell.
- `constrainedCandidates(...)` separately applied exact Player, instance, model, effort, and model-exclusion constraints.

The specialized Scout Formation and direct Terminal routes already had distinct, intentional authority gates. R4 preserved those special route kinds rather than flattening them into ordinary reasoning candidates.

# New Extracted Seam

`eligibleSeats(candidates, options)` is exported from `src/routing-policy.ts`.

Its pure options preserve the two existing authorities:

- `authority: 'auto'` enforces the existing `autoEligible !== false` rule.
- `authority: 'context'` preserves explicit-human and proven-context-owner behavior, including existing manual-only seats.
- `availability: 'all'` preserves truthful diagnostics for unavailable roster entries.
- `availability: 'taking-plays'` preserves the existing `ready | busy` admission rule.
- Existing `RouteConstraints` narrow exact Player/instance and the live model/effort catalog exactly as before.

Both `computeAutoRoute(...)` and `computeContextAwareRoute(...)` now call this seam. The former `constrainedCandidates(...)` path was removed. A source-contract test proves the ordinary Terminal/direct-shell admission predicate exists exactly once and the router calls `eligibleSeats(...)`.

# RouteSeat and Resource Pool

`src/routing-candidates.ts` defines the open `RouteSeat` projection and its small `routeSeat(...)` mapper.

Every extracted seat carries:

- the full existing `PlayerRoutingCapability`;
- `resourcePool`, projected by the existing R1 `resourcePoolForSeat(...)` authority.

No model name or lineage participates in resource identity. Direct Claude maps to `claude`, direct Codex maps to `codex`, and AntiGravity/future unmetered seats remain `unknown`. UNKNOWN resource truth does not exclude an otherwise eligible seat.

The router imports only the candidate projection seam; it does not consume `RoutingEconomicsSnapshot`, `RoutingEconomicsReader`, price, scarcity, burn, or policy data.
