## Root cause confirmed

`ScoutPlayerAdapter.capability(gameRoot)` fell back to `<active Game>/REPORTS/Scout Only`. `src/extension.ts` did not supply an override, so external Games with no duplicated Scout scorecards produced zero eligible receivers and no Scout capability.

That missing capability removed Scout from all existing downstream surfaces at once:

- `capability.snapshot`;
- the synthetic TEAM card;
- the MANUAL Player dropdown;
- the specialized reconnaissance-first AUTO route.

Field evidence confirmed the distinction: each named external Game lacks a local Scout evidence tree, while canonical Sideline infrastructure contains READY AntiGravity and OpenRouter evidence.

## Chosen canonical-root ownership

Extension activation now derives the Scout durable report root from its own runtime root:

`context.asAbsolutePath(path.join('REPORTS', 'Scout Only'))`

It injects that stable root into `ScoutPlayerAdapter` through `durableReportRoot`. The active Game root continues to be supplied independently to `capability()` and `execute()` and remains the reconnaissance target.

The separation is therefore:

```text
Scout qualification / depth chart / Formation evidence
  -> <Sideline extension root>/REPORTS/Scout Only

Scout reconnaissance target and temporary workspace
  -> <active Game root>
```

No user-specific absolute path was hardcoded. No evidence was copied into external Games.
