# Q2.10C.1 — Full Autonomy Permission Policy and Resource Routing

**Timestamp:** 2026-09-12 23:45:13 -06:00 (America/Edmonton)  
**Verdict:** **Q2.10C.1 READY FOR HUMAN PROOF — COACH-MANAGED CONTROLLED PLAYERS NOW DEFAULT TO FULL AUTONOMY**

## Human authority change

The Q2.10C `accept-edits` default was a valid conservative proof, but it was not sufficient for this user's headless workflow. It caused normal shell/tool work to finish as `Completed · 1 action needed approval and was skipped` because no interactive user could answer the provider prompt.

This profile now makes **Full Autonomy** the explicit default for Coach-managed Controlled Codex, Claude, and AntiGravity Players. The policy boundary is ownership, not provider name:

- `coach-managed` Controlled Players receive Coach's selected permission policy.
- `adopted`, `external`, and human-launched sessions do not enter this launch path and retain their existing authority.
- Bench keeps the exact process/session and does not change authority.
- Sibling instances receive the policy independently on every provider invocation.

## Provider flags verified

The installed binaries were queried before implementation:

- Codex retains its certified `approvalPolicy: never` and `sandbox: danger-full-access` contract.
- Claude Code `2.1.270` advertises `--dangerously-skip-permissions` as bypassing all permission checks. Controlled Claude now passes that exact flag.
- AntiGravity CLI `1.2.2` advertises `--dangerously-skip-permissions` as auto-approving all tool permission requests without prompting. Controlled AntiGravity now passes that exact flag.

The adapters still verify `--help` before opening or restoring a Player. If the selected flag is absent, Coach fails closed with a selected-permission message and does not silently fall back to `accept-edits`.

## Full Autonomy behavior

`player-authority.ts` is the single human-intent policy. Its durable vocabulary is ready for:

- **Full Autonomy** — selected for this profile.
- **Ask for risky actions** — maps the prior `accept-edits` value to Dadified language.
- **Ask every time** — represented as a future choice and truthfully unsupported by a headless adapter until a provider mechanism exists.

This shape belongs under **Settings → Players & Providers → Player Permissions**. It is not exposed in the normal Dispatcher. The current Play establishes the schema, migration/default behavior, runtime selection, fail-closed adapter contract, and controlled-status projection; it does not widen into preference-file storage or a full Settings UI.

The first broken boundary was launch authority: Coach was correctly managing the session but launching it with a mode that could only ask an absent human. The repair keeps the same exact-instance/session architecture and changes only the explicit Coach-managed authority.

AUTO / CONSERVE should eventually combine:

- exact Player instance and execution provider;
- live model catalog and reasoning controls;
- context affinity and current work state;

For example, native Claude quota exhaustion plus available AntiGravity capacity and a live Claude Sonnet model may justify recommending AntiGravity / Claude Sonnet. Coach must explain that recommendation and allow override. It must never hardcode AntiGravity as cheaper, unlimited, or always preferred.
