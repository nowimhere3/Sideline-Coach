# Executive Result

Q2.10F.2 Slice A2 is complete and ready for the next implementation slice.

A freshly replaced Control Plane can now recover an exact active Controlled turn from the Stadium's exact-instance routing capability, adopt that evidence into the Slice A Instance Work Ledger, and continue through the normal completion/history/report path. A recovered `started` turn retains the Stadium's original semantic start timestamp. A recovered `accepted` turn remains Starting and receives no fabricated execution clock.

This is additive server-side recovery plumbing. It makes no browser change, changes no routing decision, and claims no human field proof.

# Slice A Baseline Preserved

Slice A remains the foundation:

- the Instance Work Ledger is the sole canonical execution authority;
- `startedAt` remains Coach dispatch/attribution time during normal operation;
- `executionStartedAt` remains the genuine execution-clock origin;
- epoch and monotonic revision still order `ExecutionView` truth;
- terminal outcomes remain final for an exact turn;
- `status.execution`, execution SSE, acknowledgement, queue projection, and dispatch result identity are unchanged;
- browser code still ignores the new recovery field until a later slice.

Slice A2 adds evidence and reconciliation only. It does not introduce a second lifecycle owner.

# activeTurn Capability Contract

`PlayerRoutingCapability` now has an optional exact-instance field:

```ts
activeTurn?: {
  turnRef: string;
  state: 'accepted' | 'started';
  startedAt: number;
}
```

The field is omitted entirely when no exact active turn is known. It is never emitted as enumerable `undefined`, never inferred from generic `busy`, and never contains terminal turns.

This contract is recovery evidence for a replaced Control Plane. It is not presentation authority and is not a routing preference.

# Stadium Projection

`PlayerRoster.getRoutingCapabilities()` now reads its existing exact-instance `turnStateByInstance` record.

- `accepted` with a real `turnRef` emits exact accepted evidence and its stored Stadium event timestamp.
- `started` with a real `turnRef` emits exact started evidence and its stored Stadium event timestamp.
- `completed`, `failed`, `interrupted`, `unknown`, idle, and missing-turn identity omit `activeTurn`.
- Terminal and non-Controlled capability shapes are otherwise unchanged.

The timestamp remains stable across later capability snapshots because it comes from the original Stadium-local semantic turn event rather than snapshot time.

# Ledger Re-Learning

`InstanceWorkLedger.observeRoster()` now validates `activeTurn` conservatively and adopts it only when:

- the capability belongs to the current Game's exact instance;
- transport is Controlled;
- the capability says the instance is busy;
- exact `turnRef`, supported active state, and finite timestamp are present;
- no current canonical Play exists;
- no genuine terminal record already exists for that `turnRef`.

For a Ledger with no durable dispatch record, the recovered Play uses the exact `turnRef` as its fallback `clientRef` and the Stadium event timestamp as the only truthful recovery attribution time.

When the durable Ledger contains the Play that was active during replacement, recovery preserves its original `clientRef`, prompt summary, model, effort, and Coach dispatch time. This keeps later explicit report provenance aligned with the original Play rather than replacing it with a guessed identity.

# Accepted vs Started Recovery

Recovered accepted evidence creates a current exact Play and projects Starting:

- `turnRef` is recovered;
- `startedAt` uses known durable dispatch time when available, otherwise the Stadium event time;
- `executionStartedAt` is absent.

Recovered started evidence creates a current exact Play and projects Working:

- `turnRef` is recovered;
- durable dispatch identity is preserved when available;
- `executionStartedAt` is the Stadium's original semantic started timestamp.

Generic `busy` without `activeTurn` preserves Slice A's safe degradation: Working with no invented Play identity and no clock origin.

# Recovery Clock Semantics

Normal execution remains unchanged: the live Control Plane stamps its own `now()` on the first genuine `started` event.

Replacement recovery is the narrow exception. Because the new process was not alive at the true start, it adopts the Stadium's already-recorded semantic started timestamp. It never uses daemon reconnect time, capability observation time, browser time, or current wall time as a substitute.

# Terminal Monotonicity

Genuine completed, failed, interrupted, and unknown history for an exact `turnRef` rejects stale `activeTurn` evidence. The Play is not resurrected.

Slice A's durable serializer previously converted an in-flight Play into Unknown during process replacement. Slice A2 now marks only that process-loss placeholder as a `recoveryCandidate`. Exact matching active-turn evidence may reclaim that one record; ordinary terminal Unknown remains final.

This distinction also handles the narrow race where completion reaches the replacement daemon before its first capability snapshot: completion replaces the process-loss placeholder with the real terminal outcome instead of being discarded.

# Completion After Recovery

Recovered current Plays use the normal `recordTurn()` terminal path.

On matching completion:

- `currentPlay` clears;
- bounded recent history receives the original Play identity;
- recovered `executionStartedAt` is preserved;
- duration derives from genuine execution start to Control Plane-observed finish;
- revision advances monotonically;
- `ExecutionView` becomes Finished through the existing projection.

No provider-specific completion path was added.

# Report Attribution After Recovery

The existing Q2.10E provenance parser and report-linking implementation were not changed.

When durable replacement data exists, recovery restores the original `clientRef`. A later explicitly stamped report therefore links to the recovered completed Play through the existing exact Game + instance + clientRef contract and appears in the normal Finished projection.

If only Stadium `turnRef` evidence survives and original `clientRef` is genuinely unavailable, Sideline does not invent it. Exact instance ownership can still be proven by valid provenance, but Play-level matching remains limited to identifiers that actually survived.

# Game / Exact-Instance Isolation

Recovery is performed inside one `observeRoster(gameId, ...)` call and one exact capability `instanceId`. Tests use two Games and sibling instances to prove:

- similarly shaped instances in another Game are untouched;
- one instance's active turn does not mutate its sibling;
- malformed timestamps do not create canonical Play identity;
- opaque instance and exact turn identity, never friendly labels, control adoption.

# Compatibility Notes

- `activeTurn` is optional and absent fields are omitted from object shape.
- Existing capabilities, status responses, raw turn events, routing inputs, and browser behavior remain compatible.
- Ledger persistence stays version 1 and gains only an optional marker on an in-flight process-loss record.
- Existing version-1 files remain readable.
- A version-1 in-flight placeholder written by pre-A2 code lacks the new recovery marker and therefore is not reclaimed as though it were proven safe. That one deployment-boundary case degrades to Unknown rather than risking resurrection of a genuine terminal turn.
- No architecture breadcrumb changed because implementation confirmed the frozen Opus contract. The recovery-candidate marker is the persistence detail required to reconcile that contract with Slice A terminal monotonicity.

# Remaining Limitations

- Slice A2 does not make the browser consume epoch/revision views; that is Slice B.
- It does not render TEAM activity, clocks, Outgoing acknowledgement, Player strips, Report Ready, or View Player controls.
- A generic busy capability without exact active-turn evidence cannot recover a Play identity or clock.
- A recovery with no surviving original `clientRef` cannot fabricate Play-level provenance alignment.
- No human field proof is claimed or required for this additive server-side slice.

# What Slice B May Now Assume

Slice B may assume that:

- `status.execution` and execution SSE remain the canonical revisioned projections from Slice A;
- after a normal replacement cycle, a still-active Controlled turn can be re-adopted by exact Game + instance + `turnRef`;
- recovered started turns carry a truthful execution clock origin;
- recovered accepted turns remain Starting without a fake clock;
- terminal truth cannot be resurrected by stale active-turn evidence;
- completion and report linking continue through the ordinary Ledger path.

# WAS / IS / WILL BE

## WAS

## IS

The Stadium exposes optional exact active-turn evidence. A replacement Control Plane validates and adopts it into the canonical Ledger, preserves durable Play identity when available, distinguishes accepted from started, recovers the semantic clock only when proven, and later completes the Play normally.

## WILL BE

Slice B will implement the browser epoch/revision store and dispatcher repair against this canonical server truth. Later slices add TEAM presentation, Player-attached strips, Outgoing handoff, report-ready acknowledgement, and hardened end-to-end proof.
