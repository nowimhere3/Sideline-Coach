# Normalization Approach

`src/control-plane/route-constraints.ts` remains the only Play-wording recognizer. No second routing contract or routing engine was created.

The recognizer now:

1. removes fenced Markdown examples before considering intent;
2. examines the existing bounded opening window for natural directives;
3. recognizes only the enumerated structured field labels elsewhere in the Play;
4. resolves Player fields against current-Game candidate types, Ledger-known types, and friendly exact-instance names;
5. narrows model matching to the selected Player/exact instance when one was recognized;
6. accepts only exact normalized model ids or display names present in the live catalog;
7. accepts effort only when the applicable live model catalog supports it;
8. returns the same Q2.10E-B `RouteConstraints` fields and recognized-dimension list.

For example, these inputs normalize equivalently:

```text
AGENT: Codex
MODEL: GPT-5.6 Sol
THINKING / EFFORT: Medium
```

```text
Use Codex on GPT-5.6 Sol, Medium.
```

Both become Player `codex`, model `gpt-5.6-sol`, and effort `medium`. AUTO continues filling only dimensions the human omitted.

# Source / Context Versus Executor

Source attribution and execution authority remain separate.

- `Created by Claude`, `Previous work by Claude`, and `Architecture produced by Claude` do not match an executor directive and create no `RouteConstraints`.
- `Created by Claude. Then send to Codex.` recognizes Codex only as the requested executor.
- When a selected report and its explicit Q2.10E-A provenance prove Claude owns the context, Q2.10D retains Claude as context owner and supplies its report through the existing handoff preamble to Codex.
- Source prose alone is not treated as authoritative context provenance; ownership still comes from the selected/named report and Ledger evidence.

This preserves the authority split:

`provenance/context = who knows or produced this`

`RouteConstraints = whom the Head Coach explicitly chose to execute next`

# Advisory Report Recommendation Boundary

`Suggested next move: Codex` and `Recommended next Player: Claude` are intentionally absent from the accepted Player-field dialects. They remain Player-authored advice. Selecting a report that contains such advice can supply authoritative provenance/context through Q2.10D, but the advice itself cannot become a hard executor constraint.

If the Head Coach copies or restates that advice as `Use Codex`, `AGENT: Codex`, or another accepted outgoing directive, it then becomes human routing intent.

Fenced routing examples are also ignored. This prevents documentation quoted in a Play from becoming an accidental command.

# Remaining Limitations

- Recognition is intentionally not general NLP and does not approximate misspelled or unavailable Player/model names.
- Natural directives remain bounded to the opening portion of the Play or unmistakable sentence clauses. Structured labels are recognized because their exact field names are explicit.
- Source phrases do not independently establish context ownership; selected/named reports and explicit same-Game provenance remain authoritative.
- Report recommendations remain advisory until the human restates them as a supported outgoing directive.
- No dedicated AUTO Customize UI, Usage Sentinel, CONSERVE, or cost interpretation was added.
- `Same Player, cheaper model` remains deferred until Coach has a truthful model-cost abstraction.
