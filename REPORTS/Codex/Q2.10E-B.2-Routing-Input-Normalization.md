# Root Cause of the Live Field Failure

Q2.10E-B.1's structured fields were recognized by literal regular expressions anchored at the beginning of each line. Plain `AGENT: Codex` matched, but in `**AGENT:** Codex` the Markdown emphasis markers were treated as part of the field label. The parser therefore found no explicit Player, model, or effort constraint, and normal Q2.10D context affinity was allowed to select the Claude report owner.

The policy and context detection were behaving as implemented. The missing seam was deterministic presentation normalization before structured-label recognition.

# Normalization Approach

`src/control-plane/route-constraints.ts` remains the single recognizer and continues returning the same `RouteConstraints` type.

For each candidate structured line, it now:

1. removes a Markdown heading prefix;
2. removes a bullet or numbered-list prefix;
3. separates the label from the value at the first colon;
4. normalizes case, whitespace, emphasis markers, and minor punctuation on the label;
5. resolves that label against the closed routing-field vocabulary;
6. resolves the value independently and strictly against current Game Player identity, the applicable live model catalog, or supported effort values.

This makes the following equivalent at the label layer:

```text
AGENT: Codex
**AGENT:** Codex
Agent: Codex
### AGENT: Codex
- AGENT: Codex
* Agent : Codex
** Agent ** : Codex
```

Presentation normalization does not alter routing precedence. It only lets an obvious structured instruction reach the already-approved B/B.1 constraint path.

# Opening-Window Behavior

The recognizer now considers the first 15 meaningful, non-empty, unfenced, non-blockquoted lines. This permits a report title, stage title, assignment heading, blank lines, Markdown decoration, or a short introduction before the routing block.

The bounded window is also a safety boundary: an `AGENT:` example after 15 meaningful implementation lines is not promoted to Head Coach authority. The Play is not scanned end-to-end for routing-looking technical prose.

Existing B.1 natural directives remain within the same opening window, including `Use`, `Give this to`, `Send this to`, `Route this to`, `Then send`, and the field-proven `For Stage 1.2, use ...` form.

# Typo-Tolerance Decision

A small deterministic label-only tolerance was implemented because it fits cleanly without introducing fuzzy NLP.

The recognizer accepts one unambiguous edit in the closed field-label vocabulary: one insertion, deletion, substitution, or adjacent transposition. This covers the requested examples:

- `AGNET` → `AGENT`
- `RESONING` → `REASONING`
- `THNIKING` → `THINKING`

A fuzzy label is accepted only when it maps to exactly one known normalized alias. The mechanism is never run over prose, Player names, exact instance names, model values, or effort values.

# Strict-Value-Resolution Behavior

Forgiving label syntax does not relax identity resolution.

- Player values must exactly match a current-Game known Player type/display name or a known friendly numbered instance after the existing punctuation/case normalization.
- Model values must exactly match a real model id or display name in the applicable live catalog.
- Effort values must exactly match a supported effort for the applicable candidate/model.
- Model resolution remains narrowed by a recognized Player or exact instance.

Consequently:

- `AGENT: Cdoex` does not become Codex.
- `MODEL: GPT-5.6 Soil` does not become GPT-5.6 Sol.
- `EFFORT: Middium` does not become Medium.
- A valid `AGENT: Codex` paired with an unavailable model retains only the truthful Codex constraint and lets AUTO fill the unresolved dimension; no model is fabricated.

# Context / Advice Versus Execution-Authority Boundary

The B.1 authority boundary remains intact.

The following are not executor fields and create no hard constraint:

- `Created by: Claude`
- `Previous Agent: Claude`
- `Report Author: Claude`
- `Suggested Agent: Codex`
- `Recommended Model: Opus`

Selected-report provenance continues to establish evidence-backed context ownership. Report recommendations remain Player-authored advice. Only a supported next-execution directive such as `AGENT: Codex`, `SEND TO: Codex`, or an existing natural imperative becomes human routing authority.

Fenced Markdown, Markdown blockquotes, and standalone quoted/inline-code examples are ignored. Documentation showing `AGENT: Claude` cannot silently become a command.

# Remaining Limitations

- Recognition remains deliberately deterministic and is not general NLP.
- Structured authority is limited to the first 15 meaningful lines. Later text is intentionally not scanned, even if it resembles a field.
- Only the documented, closed label vocabulary receives typo tolerance.
- Player/model/effort values receive no spelling approximation.
- Quoted or fenced routing text is treated as documentation. A human who intends it as authority should state it directly.
- No AUTO Customize, Usage Sentinel, CONSERVE/YOLO, scheduled routing, or report-recommendation authority was added.
