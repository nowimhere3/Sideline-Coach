PASS — a Scout Formation with a BLOCKED or UNKNOWN terminal execution view and an unacknowledged parent report can now retain `Report ready` and `View Scout Report`. Ordinary non-Scout blocked/unknown Player cards remain quiet.

## Exact root cause

The server was already correct. A BLOCKED Scout execution projected as `couldnt-finish` and carried the exact registered Formation report object.

The browser helper incorrectly defined report readiness as:

```js
view?.state === 'finished' && Boolean(view.report) && view.report.acknowledged !== true
```

The Scout-specific `couldnt-finish` / `unknown` rendering branch called that helper, making its Report-ready path unreachable by definition. The browser discarded valid report truth and the synthetic card fell back to `Scout · Ready`.

## Repair

`isReportReady(view)` now means only:

```js
Boolean(view?.report) && view.report.acknowledged !== true
```

Terminal-state rendering remains responsible for deciding how to present the report:

- finished Scout remains Report ready;
- PARTIAL remains truthful through the finished projection;
- BLOCKED/UNKNOWN Scout can show Report ready through the existing `scout &&` branch;
- ordinary non-Scout `couldnt-finish` / `unknown` still returns `null`;
- acknowledgement remains exact-path and human-initiated.
