## Previous and new behavior

Previously, Preview initialized as Desktop, with no target selection before launch. Remote endpoint rendering forced Desktop again and hid Tablet/Phone controls. The chosen viewport could therefore be replaced by transport presentation rules.

The cockpit now displays a **Preview target** selector beside Preview. Phone is preselected at widths up to 619px, Tablet at 620–1023px, and Desktop at 1024px and above. The phone cutoff reuses Sideline's existing responsive breakpoint; the intermediate range supplies the Tablet class. This is responsive classification, not user-agent emulation: resizing or orientation can affect classification on initial page load. An unavailable browser signal falls back to Desktop.

Dad may explicitly select Phone, Tablet or Desktop before clicking Preview. Status updates and Game selection do not reset that selection. No host name, Stadium platform, physical Game computer, endpoint resolution or remote transport determines the default.

## Tab launch and viewport handoff

The existing synchronous new-tab flow is preserved. Its URL now includes `previewTarget=phone|tablet|desktop` alongside `previewWork=<gameId>`. Existing query parameters are retained and the bootstrap fragment is removed as before. The receiving viewer accepts only existing preset keys; invalid values fall back to its viewer default. A target query without a Preview Work Game does not override a normal cockpit's device default.

Preview Work initializes its preset from this validated query before resolution. The iframe dimensions are applied before assigning its Game URL. The selected target wins even if the receiving tab's responsive width differs from the original cockpit's width. No session registry or persistence subsystem was added.

Tab 1 remains the cockpit. Tab 2 is the separate Sideline Preview Work viewer, with its opener cleared. The raw Game opens in Tab 3 only through the existing explicit **Open in new tab** link; its target, rel attributes and endpoint URL remain unchanged. No automatic Game tab or cockpit navigation was introduced.

## Desktop and phone compatibility

Local Preview retains loopback URL mapping, endpoint/page selection, existing preset dimensions, iframe sandbox and explicit raw-Game link. Desktop retains its fill preset; Tablet remains 768×1024 and Phone remains 390×844, with the existing scaling and rotation behavior.

Remote Preview still uses its projected `remote.frameUrl` and `remote.openUrl`, the same mutation-protected API calls, grant recovery and page-selection behavior. It now respects the selected existing preset and exposes all preset controls. Viewport state stays in the Sideline viewer URL and is never added to the remote POST body or any authorization contract.
