## Final schema

The additive `remotePreview` block has exactly:

```ts
{
  advertised: boolean,
  grants: Array<{
    gameId: string,
    deviceTag: string, // first six hex characters of SHA-256(deviceId)
    ageS: number,
    idleS: number,
    stadiumMatch: boolean,
    staticMatch: boolean | 'unknown'
  }>,
  counters: {
    entered: number,
    served: number,
    bytes: number,
    denied: Partial<Record<PreviewDenialCode, number>>
  },
  lastDenial?: { code: PreviewDenialCode, at: number }
}
```

`advertised` comes from an open, non-dead tunnel whose hello included the compiled-in Preview capability; an open socket before hello is false. Grant summaries are capped at the existing 32-grant boundary. Ages are whole seconds from recorded creation/use times. `stadiumMatch` compares the current authoritative connected session; `staticMatch` compares the last cached target identity and remains `unknown` when no target observation is retained. A true static match is last-observed evidence, not a new live RPC or a guarantee that the listener remains reachable.

Counters measure successful ticket entry, completed forwarded responses (including HEAD), and asset bytes handed to the downstream sink. Byte counts can include partial responses; `served` increments only on clean completion. Denials record actual owner events, with the last observed reason/time. Counters survive grant revocation within the same process. Snapshots return detached copies.
