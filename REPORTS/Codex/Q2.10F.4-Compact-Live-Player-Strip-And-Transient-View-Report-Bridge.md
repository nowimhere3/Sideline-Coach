# Executive Result

Q2.10F.4 is implemented and automation-green. The exact Player's execution strip is now one compact horizontal mini update center:

`state | useful task reminder | elapsed time or action`

Working owns the one prominent canonical elapsed timer. A report-linked completion may briefly replace that right-hand timer with View Report. The bridge expires from canonical `finishedAt`; Incoming remains the durable report home.

Q2.10F.3's field-proven quiet-history policy remains intact. Old completed/report-linked evidence cannot resurrect a strip, TEAM never gains Report Ready, and historical Unknown/failure remains hidden from ordinary Dad mode.

# Compact Live Strip

The normal Working strip is a single three-column CSS grid row:

- state is fixed and human-readable;
- the task reminder is the only flexible column and ellipsizes before other content shrinks;
- the right slot is fixed, right-aligned, and protected.

Starting, Queued, waiting, current Needs You, and direct-shell states use the same compact spatial model where their canonical truth supports it. No new lifecycle phase was invented.

# Task Reminder Extraction

The browser uses the existing projected Play summary as its input. A deterministic presentation filter finds its first genuinely useful line and skips Sideline routing/front matter, including Agent, Player, Worker, Model, Effort, Thinking/Reasoning, Role, Task Difficulty, Thread, Repository, Branch, Environment, assignment/routing headings, and common Play/Task container headings.

Markdown heading, bullet, emphasis, and fence decoration are handled locally. No model call, network summarizer, routing parser, or second summary store was added. A useful one-line semantic summary passes through unchanged. If no useful content exists, the middle slot remains empty.

# Timer Hierarchy and Mobile Layout

The elapsed value uses the same `1rem` scale as Player-name typography, weight 750, tabular numerals, right alignment, and a non-shrinking right-side slot. Its origin remains canonical `executionStartedAt`, corrected through the existing server clock offset.

There is still exactly one production one-second interval, and only rendered Working elapsed nodes tick. TEAM, Outgoing, Incoming, Starting, Finished, and View Report do not tick.

At narrow widths the summary collapses and ellipsizes first. The strip clips its own overflow, the grid keeps the timer/action readable, and mobile receives additional right padding and a compact gap without increasing strip height materially.

# Transient Completion Bridge

The existing 10-second rich-completion window is reused. Its age is computed from canonical `finishedAt`, not page render or arrival time:

- Finished before report linkage shows a short truthful Finished / Report on its way row with no View Report claim and no timer.
- If an exact report links inside the window, the same row becomes `Finished · filename | View Report`.
- If the report links after the window, no old Player strip is resurrected.
- Reload/reconnect shows only the canonical time genuinely remaining.
- Canonical acknowledged truth retires the bridge naturally.

The one-shot decay redraw is separate from the one-second elapsed ticker.

# View Report and Acknowledgement

View Report reuses the existing exact report path, Incoming reader, and `POST /api/work/acknowledge` path. Its acknowledgement includes the current Game, exact instance, Play ref, and report path.

Execution linkage and the browser's report-list update can cross in flight. If the linked report is not yet in the local Incoming list, View Report now refreshes that existing list once and retries the exact path. It never creates a second reader and never acknowledges a report the human could not open.

The strip is not optimistically hidden. It changes only when a newer canonical ExecutionView arrives or its canonical completion window expires.

# Identity and North-Star Preservation

All presentation remains keyed by exact `playerInstanceId`. The current shared friendly-label resolver is unchanged. Route selection, AUTO/MANUAL behavior, queue semantics, Ledger history, report attribution, epoch/revision merging, and acknowledgement endpoint semantics were not modified.

TEAM continues to summarize only current live/actionable work. Incoming continues to own returned work durably. The temporary bridge is orientation and handoff, not a persistent badge or historical scar.

# WAS / IS / WILL BE

## WAS

Working used a state/timer header plus a separate multi-line task block. The timer was visually secondary, routing headings could become the visible task context, and Q2.10F.3 had intentionally removed every completion bridge to eliminate persistent report scars.

## IS

The exact Player owns one compact state/task/right-slot row. Working gives the right slot to the prominent canonical elapsed time. Recent report-linked completion briefly gives it to exact View Report, then becomes completely quiet while Incoming retains the report. Old evidence never resurrects the bridge.

## WILL BE

Real-phone observation may tune density within this same contract. It must not reopen canonical execution ownership, create a second report reader, add TEAM Report Ready, expose routing plumbing, or turn completion into persistent Player history.
