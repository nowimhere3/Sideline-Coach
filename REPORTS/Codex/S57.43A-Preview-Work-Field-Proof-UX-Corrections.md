## Behavior implemented

- A valid Preview Work click synchronously opens one temporary `about:blank` tab inside the browser user gesture.
- Existing asynchronous `PreviewEndpoint` resolution then navigates only that reserved tab with `tab.location.replace(endpoint.clientUrl)`.
- The reserved tab has its opener cleared immediately. Sideline never assigns or replaces its own location.
- Failed, stale, mismatched, and chooser-required resolutions close the temporary blank tab. Retry and chooser buttons reserve a fresh tab from their own user gestures.
- The existing embedded Preview sheet still resolves and renders the same endpoint, retains page selection and `Open in new tab`, and preserves Desktop / Tablet / Phone / Rotate behavior.

## Embedded Preview height correction

The existing four-row Preview grid now has an explicit dynamic-viewport block size: desktop uses `calc(100dvh - 28px)` with a `100vh` fallback, while the no-padding narrow-screen layout uses `100dvh`. The `minmax(0, 1fr)` stage row therefore receives the remaining height beneath controls and above the footer. Desktop fill mode continues to occupy the full stage; Tablet and Phone continue scaling against both stage width and stage height, so presets do not collapse the workspace into a shallow strip.
