## Implemented contract

The existing configured-domain escaping is reused for `p-([a-z2-7]{20})-([a-z2-7]{10})`; optional HTTP ports retain the existing hostname convention. Malformed IDs/tags and wrong domains do not route. Tags are parsed, never generated.

Signed hello capabilities are optional, validated, stored per verified socket, and removed on disconnect/close. Preview requires that the current connected socket advertises `preview.v1`, otherwise 404. The gate is checked again immediately before forwarding to protect against host replacement during request collection. Production RelayClient does not advertise Preview support: S5 owns that activation.

Preview forwards only GET/HEAD; unsupported methods receive 405 with `Allow: GET, HEAD` and are never forwarded. Requests carry `surface: preview` and the exact `previewTag`; app requests carry additive `surface: app`. Legacy frames without fields remain accepted. Invalid surfaces, missing/malformed Preview tags, and tags on non-Preview frames are refused.

Per S57.45 D1, the exact Preview header allowlist is `accept`, `cookie`, `user-agent`, `service-worker`. Cookie is explicitly included by the authoritative architecture for later grant authentication; this slice neither authenticates nor issues Preview cookies. Authorization, Host, Origin, action/content/SSE headers, conditional/range headers, and proxy/forwarding headers are not passed. App allowlisting is unchanged.

Preview uses the separate `preview` client-identity rate bucket: 600 requests per 60-second window in production. App retains its existing `http` 120/minute and pairing limits. Injected-clock proof exercises all 600 Preview requests followed by all 120 app requests, then proves separate refusals and window recovery.

The existing browser-response queue seam now selects an 8 MiB cap for Preview, retaining 1 MiB for app. At the boundary the response remains open; exceeding it cancels/destroys only that response. S1 binary framing, producer backpressure, and tunnel queue limits are untouched.

Completed, cancelled, offline/capability-denied, and method-denied Preview request logs use literal `/<preview>` and Preview surface metadata. The production serializer preserves that metadata. No raw asset paths, query strings, cookies, or secrets are logged. App log schema/path behavior remains unchanged. Preview `/health` is forwarded as Game content rather than bypassing the Preview contract through relay health handling.
