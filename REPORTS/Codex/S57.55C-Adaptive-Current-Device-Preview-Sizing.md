## Viewport measurement and sizing

Current-device Preview is adaptive; cross-device Preview is deterministic emulation.

Launch rechecks the unchanged S57.55A responsive classification: Phone ≤619px, Tablet 620–1023px, Desktop ≥1024px. When the selected Phone/Tablet target matches that current class, it measures `window.visualViewport.width/height` first, then falls back to `document.documentElement.clientWidth/clientHeight`. Measurements are CSS pixels, preserving fractional values. Both dimensions must be numeric, finite, and within 1–16384px. Unavailable or invalid data retains the existing canonical preset.

Examples proved in tests: a 390×780 phone uses 390×780, a 412×915 phone uses 412×915, and an 820×1180 tablet uses 820×1180. Desktop retains existing available/fill behavior. Cross-device selections retain Phone 390×844, Tablet 768×1024, and Desktop fill.

The existing frame-sizing engine still scales the chosen logical iframe dimensions to fit the Preview stage. Preview chrome can therefore make the displayed frame smaller while the Game's layout viewport retains the requested CSS dimensions. No second viewport engine or device-model database was added.

## Launch handoff and orientation

The existing `previewTarget=phone|tablet|desktop` handoff remains. One additional presentation parameter, `previewViewport=<width>x<height>`, marks a measured same-device Phone/Tablet selection; `previewViewport=fill` marks same-device Desktop. Cross-device selections omit it. Each launch clears any stale value before calculating new presentation state.

Preview Work accepts this value only alongside a valid selected target and Preview Work Game. It validates the dimensions and initializes adaptive state before resolution. The existing preset setter applies dimensions before iframe navigation. Receiving-tab dimensions never reinterpret a cross-device launch as adaptive. Missing or malformed state falls safely back to canonical presets, even when the receiving viewer happens to match the target class.

Measurement occurs immediately before opening the tab, so changes since page initialization are captured without a permanent orientation observer. A landscape viewer uses its current dimensions and the same responsive width contract. For example, a 915×412 viewport is Tablet under that contract; selecting Tablet adapts to 915×412, while retaining Phone is cross-device emulation. Orientation after launch remains under existing resize/scaling and Rotate behavior; adaptive dimensions are a launch snapshot. Switching presets in Preview Work uses canonical dimensions for other targets and restores the adaptive dimensions when returning to the original adaptive target.
