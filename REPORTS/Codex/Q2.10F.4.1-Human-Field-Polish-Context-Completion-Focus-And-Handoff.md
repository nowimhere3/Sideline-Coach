**Q2.10F.4.1 READY FOR MINIMAL HUMAN PROOF — THE LIVE PLAYER STRIP NOW RETAINS USEFUL CONTEXT, EDITED REPORTS CAN RETURN THROUGH THE TRANSIENT HANDOFF, AND THE NEXT ACTION IS EASIER TO REACH.**

The Q2.10F.4 execution architecture was preserved. This pass changes only the summary captured at dispatch, the existing-report provenance instruction, the bounded Dad-mode presentation window, and focused layout/focus styling.

# Human Field Findings Repaired

1. The blank middle slot came from the Control Plane reducing every Play to its literal first line before the browser could filter routing front matter. A Play beginning with `# AGENT ASSIGNMENT` therefore became only that heading; the browser correctly hid it and had nothing useful left.
2. Editing an existing report could leave the report's old provenance marker in place. The file changed in Incoming, but its explicit `clientRef` still described the older Play, so the current exact Play had no trustworthy report link and correctly withheld `View Report`.
3. The canonical completion bridge lasted only 10 seconds.
4. programmatic strip focus used the same aggressive blue treatment as intentional navigation emphasis.
5. Outgoing's exact-Player View action was a small left-aligned target.

# Context Selection

A new pure deterministic helper, `summarizePlayContext`, now creates the Ledger reminder before dispatch:

1. an exact known Incoming/report path supplies its filename;
2. otherwise the first useful semantic task line is selected;
3. routing, model, effort, role, repository, thread and related Sideline front matter is skipped;
4. fenced examples are ignored;
5. blank remains truthful only when no useful content exists.

The selected report path travels through both immediate and queued dispatch. The browser retains its defensive presentation filter, but it no longer receives an already-destroyed first-line summary.

No AI summarizer, terminal parsing, progress guessing, or new lifecycle state was introduced.

# Existing-Report Completion Bridge

Controlled Players were already told to stamp reports they create **or update**. That instruction now explicitly requires replacement of an existing `sideline-provenance` comment with the exact current marker and forbids keeping a second marker.

The existing Ledger behavior then does the rest: an updated path with current explicit provenance is removed from any obsolete same-Game owner and linked to the current exact `playerInstanceId` + `clientRef`. The existing `ExecutionView` and Incoming reader project that legitimate link. Unknown or unrelated artifacts remain fail-closed and receive no View action.

This is not a second report database and does not infer arbitrary modified files.

# Thirty-Second Canonical Window

The transient Finished/View Report bridge is now 30 seconds. Its age is still calculated from canonical `finishedAt` corrected by `serverNow`.

- Reload and reconnect show only time genuinely remaining.
- The browser never restarts the window.
- An expired historical completion cannot resurrect.
- Acknowledgement remains server-backed.
- Incoming remains durable.
- TEAM still has no Report Ready segment.

# Focus and Handoff Geometry

Keyboard focus on the Player strip remains visible through a restrained one-pixel focus-visible outline and soft halo. The existing short-lived `player-reveal` navigation highlight remains stronger, preserving the distinction between accessibility focus and the human's explicit View navigation.

Outgoing acknowledgement copy remains left aligned. Its `View {exact Player}` action now stretches between the card's existing left and right insets, keeps a 40-pixel minimum target height, and remains width-safe on mobile. Exact navigation continues to use `playerInstanceId`; the wider button does not change routing or identity.
