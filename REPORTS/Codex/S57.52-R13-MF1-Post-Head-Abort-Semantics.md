## Defect and correction

The adapter previously represented synthetic response destruction as a clean relay `end`. The Gateway sometimes terminated an incomplete body with `end`, and other abort paths destroyed only the upstream, leaving the downstream open. Both paths could conceal asset truncation or leave requests hanging.

Before changing the adapter, targeted binary-safe search (`rg -a`) confirmed daemon destroy calls were socket/request destroys, with no app response `res.destroy()` dependency. A broader targeted source search found response destruction in the local HTTP probe and StaticPreviewServer, neither of which uses this synthetic app response. The relay's existing post-head `error` branch was confirmed to destroy the browser response. No protocol change was needed.

The adapter change is restricted to Preview responses with a sent head. Pre-head destruction and app/SSE cancel behavior retain their previous semantics. The Gateway settles once before destroying upstream request/response and downstream, so the downstream `close` event cannot recursively abort or produce a second terminal frame.

Post-head timeout, upstream request/error events, response errors, incomplete close, revokeAll, and byte-counter overflow now use the same downstream abort path. Only complete upstream `end`, with matching declared length when supplied, ends a body response normally. HEAD retains normal body-free completion. Existing pre-head denial responses retain their statuses and content.

## Timeout and backpressure

When downstream `write()` returns false, the Gateway calls upstream `setTimeout(0)` and pauses the upstream response. On downstream `drain`, it re-arms the inactivity timeout (production remains 15 seconds) and resumes reading. A timeout callback already queued while paused is ignored. Settlement prevents late drain callbacks from resuming cancelled work. A stalled producer outside a downstream pause remains subject to timeout protection.
