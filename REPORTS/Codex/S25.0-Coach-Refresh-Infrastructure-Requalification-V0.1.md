# Previous behavior

`runCoachRefresh()` reused Combine's `refresh-due` policy and hard caps, but due truth was primarily driven by first discovery, catalog return, invalid/missing timestamps, or the seven-day staleness window. A recent callback/provider/unknown result stayed NOT DUE even when a later infrastructure repair invalidated the environment under which it had been observed.

That retry protection was correct for ordinary evidence but could strand a capable receiver after a shared execution repair.

# Evidence-validity design

The scorecard now has optional `qualificationEvidence` containing only:

- provider/harness scope;
- execution-contract revision;
- observation timestamp.

The current repaired contract is scoped to `openrouter/opencode` and revision `authenticated-isolated-opencode-v1`. It becomes active only when the shared credential-resolution seam reports credential presence. It does not represent credential validity, provider health, model quality, or readiness.

A legacy card is early-DUE only when all of these are true:

1. the current authenticated OpenRouter/OpenCode contract is active;
2. the card belongs to that provider/harness scope;
3. the card has not already been tried under the current revision;
4. its status is an infrastructure-compatible callback state rather than READY, LIMITED, RATE LIMITED, or UNAVAILABLE;
5. its own preserved note matches the proven pre-repair missing-credential/provider-registration/opaque `Error: {` boundary;
6. it is not protected by explicit `FIELD_BLOCKED` evidence.

The due reason is emitted in canonical Combine output as an explicit infrastructure-requalification reason. Selection does not alter the card. If the bounded tryout runs, normal Combine classification updates status and counters once, and the current qualification revision is recorded even when the new outcome is a truthful provider failure. That stamp prevents an immediate retry loop.

# Why this is the smaller design

- Removing or shortening the seven-day guard would create retry pressure for unrelated ordinary failures.
- Invalidating every OpenRouter card would conflate provider identity with evidence and would retry legitimate quality, rate-limit, or hosted-tier results.
- Rewriting or migrating historical statuses/counters would destroy truthful game film.
- A global infrastructure epoch would invalidate unrelated harnesses and providers.
- A general dependency/version graph would exceed the proven need.

The optional provider/harness-scoped revision adds one durable seam, works with existing scorecards, and requires no history rewrite or second runner.

# Game-film invariants

- Infrastructure repair means “eligible for a new bounded snap,” never READY.
- Existing notes, evidence paths, statuses, and counters remain historical observations.
- Requalification selection itself performs no scorecard write.
- A real retry uses ordinary Combine status derivation and increments ordinary attempt counters exactly once.
- Provider/auth/harness failures remain infrastructure evidence, not negative Player-quality film.
- UNKNOWN remains unchanged unless the card contains the specific proven invalidated-boundary evidence.
