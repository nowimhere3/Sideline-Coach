# CORE OWNERSHIP RULE

A Game-visible folder belongs beneath `Plumbing SLC/` by default only when it exists primarily to operate Sideline Coach for that Game, has an approved Game-scoped lifecycle, and is owned by an existing or deliberately approved Sideline contract. Sideline must first consider existing Game material and human choice.

Sideline-created report plumbing, the approved new-Game SOP workspace, future explicitly approved diagnostics, and intentionally Game-visible Sideline operational artifacts qualify.

Project code, `src/`, project-native `docs/`, README files, assets, project-native reports, existing onboarding material, and existing SOP folders do not become Sideline-owned. Sideline may adopt their coordinates when evidence or the human selects them, but must not relocate, rename, merge, or claim them.

# RISKS / OPEN QUESTIONS

1. **Meaning of NEW:** S11 recommends filesystem-unconfigured for Sideline, which current exact-Game evidence can prove. If product later requires chronological repository creation, it needs an explicit lifecycle signal; Git age and file count are not authority.
2. **Atomicity:** non-destructive ensure cannot promise rollback atomicity. Preflight, truthful partial state, and idempotent completion are the safe guarantees.

6. **SOP content:** S11 approves a folder coordinate, not automatic SOP generation or ownership of project documentation.
