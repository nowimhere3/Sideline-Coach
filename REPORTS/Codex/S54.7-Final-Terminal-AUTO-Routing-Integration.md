Routing order is now:

1. Explicit MANUAL/human target path bypasses AUTO classification.
2. Within AUTO, recognized Player/model/effort constraints and an explicitly selected route alternative outrank Terminal intent.
3. An exact shell verdict may choose one uniquely eligible Terminal.
4. If Terminal intent is absent or Terminal eligibility is not uniquely proven, existing Scout/context/provider/model/effort reasoning policy runs unchanged.

The context-aware route decides Terminal eligibility once. Its normal fallback passes reasoning candidates only, preventing a lower policy layer from reopening the shell route after an explicit choice suppressed it.

## Terminal eligibility policy

AUTO Terminal eligibility requires all of these facts on the authoritative selected Game's capability projection:

- `playerType === "terminal"`
- `executionType === "direct-shell"`
- exact instance identity
- `transport === "legacy"` (the existing Terminal transport)
- `ownership === "coach-managed"`
- `state === "ready"`
- `autoEligible !== false`
- exactly one eligible candidate

The routing capability contract now carries explicit ownership. `PlayerRoster.getRoutingCapabilities` projects the actual instance ownership; it is never inferred from display name or transport.

Existing stronger source rules remain in force:

- Capabilities are requested from the authoritative Stadium session for the exact `gameId`.
- The roster emits no capability for a benched Player.
- Closed, removed, retired, or missing Terminals are omitted.
- A Terminal with an active command projects `busy`.
- Stadium ingress resolves the exact instance and `runTerminalCommand` rechecks live/on-field/not-retired/not-busy state before execution.
- Cross-Stadium and wrong-Game dispatches remain blocked.
