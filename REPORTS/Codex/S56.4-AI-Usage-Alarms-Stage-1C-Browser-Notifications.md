## Settings And Permission Behavior

The existing Routing & Alarms disclosure now includes Browser Notifications beside the established delivery controls. Its restrained status text reports one of:

- On
- Off
- Permission required
- Permission denied
- Unavailable in this browser

Permission handling follows the browser-owned contract:

- Page load, Settings disclosure, status hydration, and alarm arrival never call `Notification.requestPermission()`.
- Permission is requested only inside the explicit Browser Notifications toggle-on action when the current permission is `default`.
- Existing `granted` permission enables the channel immediately without another prompt.
- A granted request persists canonical `channels.browser: true` through the existing `/api/preferences` path.
- A denied request or pre-existing `denied` state leaves the canonical channel off for that enable attempt, displays Permission denied, disables the switch, and does not re-prompt.
- An unsupported Notification API leaves the switch off and disabled, displays Unavailable in this browser, and does not pretend to save a working channel.
- Turning the channel off persists canonical `channels.browser: false`.
- If a stored preference and browser capability disagree, capability/permission truth gates runtime delivery and the UI does not claim that notifications are active.

The browser permission itself remains browser-owned. No local storage, IndexedDB, cookie, new JSON file, or new endpoint was introduced for alarm preferences or permission state.

## Browser Delivery Mechanism

The browser adapter is a small consumer in the existing `ai-alarm` SSE handler:

1. Parse the existing structured `AiAlarmEvent`.
2. Reject malformed or already-rendered event IDs.
3. Preserve the existing temporary in-app toast using `AiAlarmEvent.message`.
4. Check the canonical master switch, event-specific threshold/reset policy, browser-channel preference, Notification API support, and `permission === "granted"`.
5. Construct one notification with title `Sideline Coach · AI Usage` and the canonical event message as its body.

The adapter does not inspect Scoreboard text, evaluate telemetry, calculate thresholds, or create alternate alarm wording.

## Event Deduplication
