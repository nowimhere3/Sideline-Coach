## Legacy migration

Activation resolves the legacy source only for bounded migration:

```text
<extension source/install>/REPORTS/Scout Only
```

Migration behavior:

1. The destination must be absent or empty.
2. Only the S31-approved durable lanes are copied:
   - `Combine/Scorecards`;
   - `Player Verification`;
   - `Formations`.
3. `Combine/Runs`, Game-local `Scouts/`, and unrelated repository geology are not migrated.
4. Files are copied into a sibling staging directory with timestamps preserved, then the completed staging tree is renamed into place.
5. A non-empty destination wins and migration is a no-op; competing truth is never merged.
6. The legacy source is never moved, edited, or deleted.
7. A concurrent host that finds the destination published by another host treats it as the canonical non-empty destination.

## Packaging repair

### Strategy selected

`.vscodeignore` was removed. `package.json files[]` is now the one supported inclusion strategy:

```text
out/**/*.js
src/public/index.html
node_modules/ws/**
README.md
LICENSE
```

Why this strategy:

- it is a positive product allowlist rather than an attempt to enumerate every form of developer debris;
- compiled source maps are unnecessary and excluded;
- the webview is a required runtime asset;
- `ws` is the sole production dependency and must be present for the extension and Control Plane to start;
- VSCE adds its manifest/container metadata normally.

The first successful narrow package inspection caught that the previous `files[]` omitted `ws`. The allowlist was corrected before declaring PASS.
