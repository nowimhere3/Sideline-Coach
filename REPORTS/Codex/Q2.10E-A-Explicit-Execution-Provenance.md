# Q2.10E-A — Explicit Execution Provenance

## Verdict

**Q2.10E-A READY FOR HUMAN PROOF — CONTROLLED REPORT PLAYS NOW CARRY SIDELINE-SUPPLIED EXECUTION PROVENANCE**

Automated validation is complete. No real provider Play was dispatched during implementation, so this report does not claim field proof.

## Existing seam discovered

Q2.10D had already established one provenance contract in `src/report-provenance.ts`:

`<!-- sideline-provenance: {...} -->`

The Stadium already parsed that invisible Markdown comment while scanning reports. `CoachReport.provenance` already flowed to the Control Plane, and context routing already preferred an explicit same-Game `playerInstanceId` over timing attribution. The missing seam was source-side production: Controlled Players were never reliably given the exact marker to write.

The authoritative dispatch path is `ControlPlaneRouter.dispatch()`. Before a Controlled prompt crosses to the Stadium, it already knows the selected Game, minted clientRef, exact canonical Player candidate, execution provider, resolved model/effort selection, and dispatch time. That is the smallest provider-neutral source of truth; no adapter-specific routing or second provenance store was needed.

## Implementation

For each Controlled reasoning Play, the Control Plane now:

1. mints the Play `clientRef` and captures one dispatch timestamp;
2. constructs a typed `ControlledExecutionProvenance` payload from routing facts;
3. formats the existing invisible `sideline-provenance` marker;
4. appends a short report-only instruction to the delivered prompt containing that exact marker;
5. tells the Player to copy the marker unchanged near the top of every Markdown report created or updated for that Play.

The model is not asked to infer or compose any machine field. The complete marker is supplied by Sideline. The human Play remains the text recorded in the Work Ledger; handoff preambles continue to precede it, and the machine report instruction follows it. Dad Mode does not display the plumbing.

Terminal and legacy/adopted paths are untouched. Terminal still receives the exact command with no suffix, model, effort, or report-provenance instruction.

## Source of truth for every field

- `gameId`: the Control Plane's selected/target Game after authoritative Stadium validation.
- `clientRef`: minted once by the Control Plane for the actual dispatch.
- `playerInstanceId`: the exact canonical routing capability selected for the Play.
- `playerType`: that same exact capability's Player type.
- `provider`: the capability snapshot's execution provider, falling back only to the known Player type if the snapshot has no provider string.
- `model`: the explicit resolved provider-native route/manual model id. If none is selected, `provider-default` is recorded.
- `effort`: the explicit resolved effort only. It is omitted when default, unsupported, inapplicable, or otherwise unknown.
- `at`: the Control Plane dispatch/execution-start timestamp serialized as ISO-8601.

Player instance, execution provider, underlying model, and reasoning effort remain separate dimensions.

## Provider Default behavior

`default`, `auto` that did not resolve, an empty value, and an absent model never become a guessed catalog entry. They stamp:

`model: provider-default`

An absent/default effort is omitted, which is the existing contract's truthful Unknown state. Sideline does not infer either value from the provider name, previous Play, UI labels, catalog order, or likely behavior.

## AntiGravity provider/model separation

An AntiGravity execution selecting a discovered Claude-family model now stamps values equivalent to:

- Player instance: `antigravity-<opaque id>`
- Player type: `antigravity`
- execution provider: `antigravity`
- model: `claude-opus-4.6-thinking` (when explicitly resolved)
- effort: `high` (when explicitly resolved)

AntiGravity does not become Claude merely because the underlying model is Claude-family. Conversely, prior model/effort are retained as context evidence but do not force the next route; current routing policy remains authoritative.

## Ledger attribution repair

The Work Ledger now stores the full parsed provenance object on an explicit report link, so provider/model/effort evidence survives its durable serialization with report ownership.

Explicit provenance now also outranks timing attribution operationally. If a report was first scanned before its final marker and conservatively linked by timing, a later scan with valid same-Game provenance removes all older projections of that report path in that Game and attaches it to the declared exact instance. A foreign-Game marker never owns local context.

## Known constraints

- Sideline supplies the exact marker through the prompt because current report paths are Player-chosen. A provider that ignores the instruction may still produce an unstamped report; the existing conservative timing attribution then applies, and ambiguity remains Unknown rather than guessed.
- The timestamp records dispatch/execution start, not report completion.
- Explicit model provenance records the provider-native resolved selection Sideline passed. If Provider Default hides the actual underlying model, `provider-default` remains intentionally truthful.
- This Play does not create or migrate `Reports-SC`, change report globs, or implement the future human-readable Sideline Report Contract.
- The detached Control Plane was not restarted and no paid/live provider Play was sent during automated implementation. Because router code changed, current Game hosts must load the newly compiled extension so the Freshness Guard can replace the old daemon and reconnect Stadiums before field proof.
