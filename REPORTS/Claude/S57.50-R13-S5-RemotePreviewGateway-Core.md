## Implementation summary

- **Tag and origin.** `derivePreviewTag` is base32(sha256) per D2. The origin is `https://p-<host>-<tag>.<domain>`.
- **Mint (`POST /api/games/preview/remote`).**
  - The daemon re-resolves through the Stadium and requires the primary endpoint to be `source: 'static'`.
  - Only then does it call the read-only `game.preview.remoteTarget` (S4). Nothing is started.
  - It mints an in-memory grant bound to device, Game, previewTag, Stadium session id and static instance id.
  - It also mints a 60 s single-use ticket bound to the page path.
  - A new mint revokes the prior grant for the same device and Game.
  - Global cap is 32, evicting the least recently used.
- **Enter** (`/__sideline/preview/enter?t=`).
  - The ticket is deleted on first use, whether or not it is valid.
  - It is checked for expiry, grant liveness, tag and device liveness.
  - A random secret is generated then. Only its hash is stored, and it is delivered only as `__Host-sl_pv=…; HttpOnly; Secure; SameSite=Lax; Path=/` with a 303.
- **Per-request order (F2).**
  - Method and service-worker header.
  - Reserved and bad paths.
  - Grant by secret hash, idle (30 min) and absolute (8 h) lifetime.
  - Tag match.
  - Device liveness.
  - `remoteMeter.admission()`, then `touch()`.
  - Game known.
  - Stadium session connected, `instanceId` unchanged, feature advertised.
  - Target from a 5 s cache or the RPC, with `instanceId` equal to the grant's.
  - Loopback GET or HEAD.
  - Echoed `X-Sideline-Preview-Instance` verified before any byte is forwarded.
  - `Content-Length` ≤ 8 MiB.
  - Backpressured stream.
- **Status codes.**

  | Status | Meaning |
  |---|---|
  | 401 | No, unknown, expired or wrong-tag grant; revoked device |
  | 410 | Game gone, Stadium session changed, static instance changed |
  | 403 | Allowance refused |
  | 503 | Stadium offline |
  | 502 | Upstream failure, instance mismatch, or any upstream status outside 200, 400, 403, 404 |
  | 413 | Over 8 MiB |
  | 405 | Bad method (`Allow: GET, HEAD`) |
  | 404 | Reserved, bad or over-long path |

- **Headers.** Responses carry the fixed E3 set. Only a sanitized `content-type` and a numeric `content-length` come from upstream. The upstream request carries only `Host`, `Accept: */*` and the instance header. The cookie and grant secret never go upstream.
- **Streaming.** Buffers go straight to the adapter sink (S1 turns them into `chunkB64`). `write() === false` pauses the upstream until `drain`. A downstream `close`, `revokeAll()` or an oversize stream destroys the upstream request.

## Security-boundary behavior (proved)

- **No generic proxy.** Host and port come only from the Stadium RPC. The upstream is always `127.0.0.1:<port>` and the path is a pathname only (query dropped). The URL is parsed by hand, so `//host/x`, `http://host/x` and `\` tricks cannot change the target. Non-ASCII, NUL, dot-segment and over-2048-character paths are refused.
- **Nothing is started remotely.** After the server is disposed, the gateway returns 410 and `activePort` stays undefined.
- **Stale authority fails closed.** A restart, a session change or an instance mismatch gives 410 or 502, drops the grant, and is never silently rebound. A cached port that now belongs to an impostor is stopped by the echo check: the impostor's body is never forwarded.
- **No credential bleed.** The preview surface never reads device cookies. A `sl_dev` or `__Host-sl_dev` cookie is not a preview credential. The `__Host-sl_pv` cookie is HttpOnly and host-only. A grant is not valid on another Game's origin.
- **Projection is leak-free.** The remote `POST` response contains no `localUrl`, `clientUrl`, port, loopback flag, Stadium id, instance id or filesystem path. `previewId` is replaced by an opaque hash (see the choices below).
- **Local callers** get 409 `local-viewer`, and the Stadium is not contacted. The route is `remote-mutate`, so the action header and Origin checks from S2 apply (tested).

## Implementation choices where S57.45 is silent (no contract change)

1. `previewId` in the remote projection is `remote:<16 hex of sha256(stadium previewId)>`, because the Stadium's previewId embeds the Stadium id and port (invariant 10).
2. The grant secret is generated at enter time rather than at mint. The raw secret therefore exists only in the response.
3. The upstream request is stricter than the spec requires: no `User-Agent`, `Cookie` or forwarded headers, and `Accept` is fixed to `*/*`.
4. Only upstream statuses 200, 400, 403 and 404 pass through. Anything else, including any 3xx, 409 or 5xx, becomes 502.
5. A 200 response without a `Content-Length` is refused (502) so the 8 MiB cap can be enforced before bytes move. A streamed response that exceeds 8 MiB anyway is aborted.
6. `remotePreview` on the existing `GET` is true only when the tunnel is connected, the Stadium session is connected, and it advertises `game.preview.remote.v1`.
7. The hello `caps` are sent unconditionally because the gateway now always exists in the daemon. The old relay ignores unknown hello fields (checked against `HEAD` `reference-relay.ts`), so an upgraded host behind an old relay is safe.

## Unresolved risks (for the Opus security review)

- **Path semantics.** The gateway forwards the raw percent-encoded pathname and relies on `StaticPreviewServer` for decoding and containment, as architected. The pre-filter catches dot segments, NUL and `__sideline`, but `StaticPreviewServer` remains the authoritative check for everything else.
- **Denial counters** are in-memory only, with no diagnostics surface (RM-1 is out of scope).
- **In-flight streams** hold the grant lookup only at request start. A later revocation aborts them only through `revokeAll()`, a tunnel stop, or the downstream closing. Per-device revocation takes effect on the next request rather than mid-stream.
- **`DeviceRegistry.isLive`** reflects the 30-day idle window. Preview traffic does not slide it, because Preview does not authenticate with the device token. This is intentional, but confirm that is what the review wants.
- **Not exercised:** the real `Stadium`-to-daemon RPC wiring (covered by S4 plus a fake socket here), the phone UI (S6), and field proof on real Dad hardware (S8).
- **Deployment:** the S3 relay is still undeployed. Until it is, the production relay will not route `p-` origins, so nothing is reachable end to end. That is the safe state.
