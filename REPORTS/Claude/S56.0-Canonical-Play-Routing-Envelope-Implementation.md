## Root cause

`recognizeRouteConstraints` detected `MODEL: Claude Sonnet 5` as a structured MODEL field, but `exactAlias` only compared it to the catalog aliases (`opus`, `sonnet`, display names). No exact match → `model: undefined`, which `routing-policy.ts` could not distinguish from an omitted model. Architecture classification then ran `ClaudeRoutingPolicy`, which prefers Opus. An explicit value was silently replaced by inference. The same collapse applied to an unknown structured Player and to an unsupported/unknown REASONING value.

## Contract implemented

Per dimension (Player / model / effort):

1. **Absent** (no structured field in the bounded opening region) → AUTO may fill.
2. **Explicit + resolved** → wins absolutely.
3. **Explicit + unresolved** → preserved as `RouteConstraints.unresolved`; AUTO returns a needs-attention error and never reaches provider/model fallback inference.

Only **structured** fields (`AGENT:`, `MODEL:`, `REASONING:` and existing aliases) can be unresolved. Natural-language `Use X on Y` is unchanged (catalog-validated advice; `Use Codex on Imaginary 9` still yields Codex only).

## Model normalization rules (deterministic, no fuzzy matching)

Applied only to an explicit structured MODEL value, against the catalog of the resolved Player (or all on-field Players if none):

1. Exact catalog id / display name (case, punctuation, whitespace-insensitive).
2. Same, after dropping a redundant Player/provider prefix (`Claude Sonnet` → `Sonnet`).
3. Trailing version tokens dropped **only if** the remainder is a digit-free catalog alias (`Claude Sonnet 5`, `Sonnet 5`, `Claude Sonnet 4.5` → `sonnet`).
4. A form matching more than one distinct model id is ambiguous → unresolved.

`GPT-5.6 Soil` and `GPT-5.6 Sol 2` stay unresolved (no typo correction; digit-bearing remainders are never trimmed).

## Unresolved-routing behavior

Error (existing `{ error }` result convention), e.g.:
`Unrecognized model 'Imaginary 9' requested for Claude. Coach did not choose another model because this Play explicitly constrained the model.`
Analogous text for `Player` and `reasoning level`. Nothing is dispatched or queued. If the resolved Player is not on field at all, no catalog exists to judge model/effort, so the existing "currently unavailable" error is kept.

Effort is unresolved when it is not `low|medium|high|xhigh|max` or is not offered by the resolved Player/model catalog (previously silently dropped).
