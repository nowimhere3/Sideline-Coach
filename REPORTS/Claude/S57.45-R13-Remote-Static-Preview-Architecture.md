## A. Executive Verdict

**R13 serves the running Game from a dedicated, per-Game Preview origin on the existing relay:**

```text
https://p-<hostPublicId>-<gameTag>.<RELAY_DOMAIN>/
```

The relay labels that origin as the **preview surface**. The host's `InProcessRemoteAdapter` sends preview-surface frames to a new daemon-owned **RemotePreviewGateway** and never to the daemon router. The gateway authorizes each request with an ephemeral, host-minted **RemotePreviewGrant**, bound to one viewer device, one Game, one Stadium session, and one `StaticPreviewServer` instance. It then forwards `GET`/`HEAD` over loopback HTTP to that Stadium-owned server, whose containment stays authoritative. It streams the response back binary-safe, with backpressure.

Why:

- **Origin.** The Game runs as a Game. `/` is the Game root, so root-relative assets work without rewriting or `<base>` injection.
- **Isolation by construction.** The Game runs on an origin that holds no Sideline credential (`__Host-sl_dev` is host-only on `h-`). Sandboxing is not what provides the isolation, so ordinary JS (localStorage, fetch, modules) still works.
- **Reuse.** The relay, pairing, device registry, commercial gate, tunnel, and static server are all reused. The additions are one relay label, one host gateway, one Stadium RPC, and one frame field.
- **The daemon never learns a port from the phone.** The only forwarding target is `127.0.0.1:<port>`, where the port came from the connected Stadium session for the grant's Game. Every response must prove it came from the expected server instance.

Rejected:

- **Path-scoped Preview on the `h-` origin.** It breaks root-relative assets. It puts Game JS on the origin that holds `sl_dev`. Making that safe would need a sandbox without `allow-same-origin`, which breaks localStorage and cookies, so ordinary static games would fail.
- **HTTP over the Stadium WebSocket.** It re-frames bytes over a JSON-RPC channel for no gain. The daemon and a co-located Stadium share loopback.
- **A separate registrable domain.** An iframe from a different site gets third-party-cookie partitioning or blocking on Safari and iOS, so the grant cookie fails. The protection it offers over F2 is fully covered by `__Host-` cookies.

## B. Canonical End-to-End Flow

### B1. Opening Preview on the phone (app origin `h-…`)

```text
Phone (Preview viewer tab, h-<host>.<domain>/?previewWork=GS3)
  │ GET /api/games/preview?gameId=GS3                (existing route)
  ▼
Daemon (remote-device) → { available:false, reason:'remote-viewer', remotePreview:true }
  │   remotePreview is true only when: relay connected with hello cap 'preview.v1'
  │   AND the Game's Stadium session is connected AND it advertises 'game.preview.remote.v1'
  ▼
Phone │ POST /api/games/preview/remote {gameId, staticEntrypoint?}
      │   (remote-mutate: X-Sideline-Action:1 + Origin == h-origin, as today)
  ▼
Daemon
  1. proxyExactGameRpc-equivalent → Stadium 'game.preview.resolve' (starts static server if needed; existing)
  2. require available && primary endpoint source === 'static'   (else reason 'remote-viewer')
  3. Stadium 'game.preview.remoteTarget' {gameId} → {port, instanceId}  (read-only; never starts anything)
  4. mint RemotePreviewGrant(device, game, stadiumSession.instanceId, static instanceId)
     + single-use 60 s entry ticket bound to the grant and the chosen page path
  5. return the remote projection (§D4): frameUrl = https://p-<host>-<tag>.<domain>/__sideline/preview/enter?t=<ticket>
  ▼
Phone sets <iframe src=frameUrl>
```

### B2. Entering and loading the Game (Preview origin `p-…`)

```text
Phone iframe GET https://p-<host>-<tag>.<domain>/__sideline/preview/enter?t=…
  ▼
Relay: Host matches ^p-([a-z2-7]{20})-([a-z2-7]{10})\.<domain>$ → hostPublicId, previewTag
       host advertised 'preview.v1'? else 404
       frame = { t:'req', surface:'preview', previewTag, method, path, headers(preview allowlist) }
       rate scope 'preview'; per-response queue cap 8 MiB; log path redacted to "/<preview>"
  ▼ tunnel/v1
RelayClient.parseReq (passes surface/previewTag) → InProcessRemoteAdapter
       surface==='preview' → NEVER reads __Host-sl_dev/sl_dev, NEVER calls dispatchRemoteRequest
       → daemon.dispatchRemotePreview(req, res, { previewTag, grantSecret: cookie __Host-sl_pv })
  ▼
RemotePreviewGateway
  /__sideline/preview/enter: consume ticket → Set-Cookie __Host-sl_pv → 303 Location: /<page path>
  ▼
Phone iframe GET https://p-…/index.html   (then /style.css, /app.js, /img/logo.png …)
  ▼
Relay → Adapter (preview surface) → Gateway per-request checks (§F2)
  ▼
Gateway → http.request 127.0.0.1:<target.port> GET|HEAD <pathname>
           request header  X-Sideline-Preview-Instance: <grant.staticInstanceId>
  ▼
StaticPreviewServer (Stadium): 409 if the instance header mismatches; then existing containment
           response header X-Sideline-Preview-Instance: <its instanceId>
  ▼
Gateway: verify echoed instance == grant.staticInstanceId BEFORE any byte is forwarded;
         Content-Length ≤ 8 MiB; replace headers with the fixed preview set (§E3);
         pipeline(upstream → adapter res) with backpressure; Buffers → chunkB64
  ▼
Relay decodes chunkB64 → phone renders GS3
```

**Local desktop Preview is unchanged.** `local-admin` still receives the `clientUrl` projection and loads the loopback server directly, with no proxy.

## D. Contracts

### D1. Relay ↔ host frames (`src/control-plane/relay-frames.ts`)

```ts
export interface RelayReqFrame {
  t: 'req'; id: string; method: string; path: string;
  headers: Record<string, string>;
  body?: string; bodyB64?: string;
  /** Set by the relay from the Host label only. Absent === 'app' (backward compatible). */
  surface?: 'app' | 'preview';
  /** Present iff surface === 'preview': the 10-char [a-z2-7] label suffix. Opaque to the relay. */
  previewTag?: string;
}

export interface HostHelloFrame {
  /* …existing… */
  /** Additive host capabilities. The relay routes p- origins only to hosts that sent 'preview.v1'. */
  caps?: string[];
}
```

**Relay rules:**

- App pattern, unchanged: `^h-([a-z2-7]{20})\.<domain>(?::\d+)?$`
- Preview pattern: `^p-([a-z2-7]{20})-([a-z2-7]{10})\.<domain>(?::\d+)?$`
- A `p-` request to a host without `caps ⊇ ['preview.v1']` → 404 `Not found`. This makes relay and host deploy order irrelevant: an old host never receives preview frames.
- Preview request header allowlist: `accept`, `cookie`, `user-agent`, `service-worker`. No `origin`, `x-sideline-action`, `content-type`, or `last-event-id`. `range`, `if-none-match`, and `if-modified-since` are **not** forwarded in R13.
- Preview surface: only `GET`/`HEAD` are forwarded. Anything else gets 405 at the relay, and the host enforces the same independently.
- Rate-limit scope `preview`: 600 req/min per client, separate from `http` (120).
- Preview per-response queue cap: 8 MiB (app surface stays at 1 MiB).
- Log entry `path` for the preview surface is the literal `"/<preview>"`. Game file names never reach Fly logs.

`RelayClient.parseReq` accepts and passes `surface ∈ {'app','preview'}` and `previewTag` matching `^[a-z2-7]{10}$`. Any other value → `error bad_frame`. The client sends `caps: ['preview.v1']` in hello once the gateway exists.

### D2. `gameTag` (host-owned)

```ts
gameTag(hostPublicId, gameId) =
  base32lower(sha256(`sideline.preview.origin.v1\0${hostPublicId}\0${gameId}`)).slice(0, 10)
```

The tag is an address, not a secret. It gives each Game its own origin, so localStorage, IndexedDB, and cache are never shared across Games. The gateway compares it with `grant.previewTag` and never reverse-maps a tag to a Game.

### D3. Stadium RPC and static server identity

```ts
// feature 'game.preview.remote.v1': advertised ONLY when vscode.env.remoteName === undefined
// method 'game.preview.remoteTarget'   (withExactGame; read-only; never calls prepare/urlFor)
params: { gameId: string }
result:
  | { success: true; gameId: string; available: true;  port: number; instanceId: string }
  | { success: true; gameId: string; available: false; reason: 'not-running' | 'not-colocated' }
```

`StaticPreviewServer`:

- `instanceId`: 128-bit random, base64url, minted in `start()`. It is cleared in `dispose()` and exposed as `activeInstanceId`. It is 1:1 with one listener, which is bound to one Game.
- Every response, including rejections, carries `X-Sideline-Preview-Instance: <instanceId>`.
- A request that carries `X-Sideline-Preview-Instance` with a different value → 409 and no filesystem access. Requests without the header behave exactly as today, so desktop Preview is unchanged.

### D4. Daemon routes (browser, `h-` origin)

`GET /api/games/preview` for `remote-device` (existing route, still `remote-read`):

```ts
{ success: true, gameId, available: false, endpoints: [], reason: 'remote-viewer', remotePreview: boolean }
```

Old clients ignore `remotePreview` and keep today's message.

**New:** `POST /api/games/preview/remote`. This is `remote-mutate`: add it to `DAEMON_ROUTE_POLICIES` in the same change. It requires `X-Sideline-Action: 1` and a matching Origin, as today. `local-admin` → 409 `{ reason: 'local-viewer' }`.

```ts
request:  { gameId: string; staticEntrypoint?: string }   // same validation as the GET route
response (eligible):
{
  success: true, gameId, available: true,
  endpoints: [{
    previewId, gameId, source: 'static', ownership, primary: true, label?, observedAt,
    // NO localUrl, clientUrl, port, loopbackIpv4, stadiumId
    remote: {
      frameUrl: 'https://p-<host>-<tag>.<domain>/__sideline/preview/enter?t=<ticket>',
      openUrl:  'https://p-<host>-<tag>.<domain>/<primary page path>',
      expiresAt: number            // ticket expiry; the grant outlives it
    },
    pages?: [{ path, label, primary, remoteUrl: 'https://p-…/<path>' }]
  }]
}
response (not eligible): { success: true, gameId, available: false, endpoints: [], reason, staticPages? }
  reason ∈ existing PreviewUnavailableReason ∪ 'remote-viewer'
  (non-static endpoint, not co-located, or feature missing → 'remote-viewer')
```

Each POST revokes the prior grant for the same `(deviceId, gameId)` and mints a new one. There is never more than one grant per device per Game.

### D5. Preview-surface routes (`p-` origin, gateway-owned, fixed set)

| Request | Behavior |
|---|---|
| `GET /__sideline/preview/enter?t=<ticket>` | Consume the single-use ticket (hash lookup, unexpired, grant live). Respond `303 Location: /<ticket.path>` with `Set-Cookie: __Host-sl_pv=<grantSecret>; HttpOnly; Secure; SameSite=Lax; Path=/` (a session cookie; expiry is server-side). Invalid → 401 ended page. |
| `GET`/`HEAD /__sideline/*` (anything else) | 404. The prefix is reserved; a Game folder named `__sideline` is not servable remotely. |
| `GET`/`HEAD` with `service-worker: script` | 403. Service-worker registration fails. |
| `GET`/`HEAD <any other path>` | Authorize (§F2) → forward `pathname` only (query dropped) → stream. |
| Any other method | 405 `Allow: GET, HEAD`. |

Ended page: static HTML, no script, `Cache-Control: no-store`. It says: "This preview has ended. Go back to Sideline and tap Preview Work again." Statuses: 401 no or unknown grant, 410 grant stale, 403 remote allowance, 503 Stadium offline, 502 upstream failure or instance mismatch, 413 asset over 8 MiB.

### D6. Gateway state (memory only; never persisted; never in DeviceRegistry)

```ts
interface RemotePreviewGrant {
  grantId: string;              // random, internal
  secretHash: string;           // sha256 of the __Host-sl_pv value; the raw secret is never stored
  deviceId: string;
  gameId: string;
  previewTag: string;
  stadiumInstanceId: string;    // StadiumSession.instanceId at mint
  staticInstanceId: string;     // StaticPreviewServer instanceId at mint
  createdAt: number;
  lastUsedAt: number;           // idle TTL 30 min, absolute TTL 8 h
}
interface RemotePreviewTicket { ticketHash: string; grantId: string; path: string; expiresAt: number } // 60 s, single use
```

- Global cap: 32 grants (LRU eviction).
- Target cache: `stadiumInstanceId → { port, staticInstanceId, fetchedAt }`, TTL 5 s. It is refreshed by `game.preview.remoteTarget` and dropped on any mismatch, upstream connect error, or session change.

### D7. Adapter response sink (`remote-dispatch.ts` / `relay-client.ts`)

- `write(chunk)`/`end(chunk)`: a `Buffer` or `Uint8Array` is **always** sent as `chunkB64`, and a `string` as `chunk`. There is no UTF-8 round-trip guessing. This also fixes the latent bug where a multibyte UTF-8 character split across two 64 KiB chunks was corrupted on the app surface.
- `write()` returns `false` when the tunnel's queued bytes are at or above 2 MiB. The sink emits `'drain'` when the RelayClient flushes back to 1 MiB or less, so the global 8 MiB tunnel-kill threshold is never reached by a well-behaved producer.
- The sink emits `'close'` (and `req` emits `'close'`) on relay `cancel` or tunnel loss. The gateway then destroys the upstream loopback request.

### D8. Device cookie migration (`__Host-sl_dev`)

- Pairing exchange and refresh set `__Host-sl_dev=<token>; HttpOnly; Secure; SameSite=Lax; Path=/` (no Domain).
- The adapter authenticates with `__Host-sl_dev` whenever it is present, and **ignores `sl_dev` entirely** in that case.
- If `__Host-sl_dev` is absent, a legacy `sl_dev` is accepted once. The response re-issues `__Host-sl_dev` and expires the legacy one (`sl_dev=; Max-Age=0; Path=/`), so Dad never has to re-pair.
- App-surface requests that carry an `Origin` header not equal to `expectedOrigin` → 403. This covers cross-origin CORS-mode fetches, including GET.

## E. Security Model

### E1. Threat → blocking layer

| Threat | Blocked by |
|---|---|
| Remote user reaches arbitrary localhost or port | **Gateway**: there is no URL, host, or port input from the phone. The target comes only from `remoteTarget` for the grant's Game, on `127.0.0.1` only. **Stadium**: the feature is advertised only when co-located. |
| Stale ephemeral port reused by another process or by a new Game's listener | **Static server** 409s on an instance mismatch. **Gateway** verifies the echoed instance before forwarding any byte, and checks the grant's `staticInstanceId` against a fresh target. |
| Path traversal, symlink escape, dotfiles, secrets | **StaticPreviewServer** (authoritative, unchanged). **Gateway** pre-filters: pathname only, ≤ 2048 chars, no NUL/`%00`, `/__sideline/` reserved. |
| Non-static dev servers (Vite etc.) exposed | **Daemon** mints only when the primary endpoint is `source: 'static'`. **Gateway** only ever targets the StaticPreviewServer instance. |
| Game JS reads or uses Sideline credentials | **Origin**: Game runs on `p-…`; `__Host-sl_dev` is host-only on `h-…` and HttpOnly. **Adapter**: preview surface never reads device cookies. |
| Game JS makes ambient calls to the Sideline API | **Adapter**: a foreign `Origin` → 403 (D8). **Daemon** (existing): mutations need `X-Sideline-Action` + Origin, which forces a preflight the daemon never approves. There is no ACAO, so no-cors GETs return opaque responses. |
| Game JS tosses cookies onto the parent domain | **`__Host-sl_dev`** (D8): a Domain-scoped cookie cannot have that name, and the legacy name is ignored once `__Host-` is present. |
| Game JS steals the preview grant | `__Host-sl_pv` is HttpOnly. The grant only authorizes this Game's static content, which the device already has. |
| Game navigates or drives the Sideline viewer | **Viewer iframe sandbox**: no `allow-top-navigation*`. **Sideline** has no postMessage listeners. |
| Preview framed by a hostile site (clickjacking) | **Gateway CSP** `frame-ancestors 'self' https://h-<host>.<domain>`. |
| Cross-Game state bleed (storage, cache) | **Per-Game origin** (`gameTag`). |
| A Game's service worker persisting past revocation or across sessions | **Gateway** 403s `Service-Worker: script`. **Relay** forwards that header on the preview surface only. |
| Ticket leakage via logs or Referer | The ticket is single-use with a 60 s TTL and lives only in the query. The relay logs pathname only and redacts preview paths. `Referrer-Policy: no-referrer`. The enter response is a redirect. |
| Revoked device keeps previewing | **Gateway** checks `DeviceRegistry` liveness on every request (D6/F2). |
| Compromised or buggy relay | The relay cannot mint grants. Mislabeling app → preview gives less authority. Mislabeling preview → app arrives with no device cookie → 401. |
| Old host behind a new relay | **Relay** routes `p-` only to hosts whose hello has `caps: ['preview.v1']`. |
| One large asset tears down the tunnel (F3) | **Adapter/RelayClient** backpressure (D7). **Gateway** caps assets at 8 MiB. The relay's preview queue cap is also 8 MiB. |
| A Game load trips the rate limit (F4) | **Relay** `preview` scope, 600/min. |
| Allowance exhausted or not entitled | **Gateway** applies `remoteMeter.admission()` and `touch()` per request, same as the app surface. |

### E2. Game execution isolation (decided)

- **Iframe:** keep the existing sandbox, `allow-scripts allow-same-origin allow-forms allow-popups allow-modals`, and `referrerpolicy="no-referrer"`.
- **`allow-same-origin` is permitted and required.** Without it, the Game gets an opaque origin, so localStorage and IndexedDB throw and the grant cookie is not sent on subresources. Isolation comes from the dedicated credential-free origin, not from an opaque sandbox.
- **Never add** `allow-top-navigation`, `allow-top-navigation-by-user-activation`, or `allow-popups-to-escape-sandbox`.
- **CSP owner:** the gateway. The policy is deliberately minimal (E3). It does **not** restrict `script-src`, `connect-src`, or `img-src`, because a static Game that loads a CDN library or font must behave as it does locally. Keeping the Game away from Sideline is the origin's job, not CSP's.

### E3. Fixed preview response headers (upstream headers are discarded except `content-type` and `content-length`)

```text
Content-Type:            <from static server>
Content-Length:          <from static server>
X-Content-Type-Options:  nosniff
Cache-Control:           no-store
Referrer-Policy:         no-referrer
Content-Security-Policy: frame-ancestors 'self' https://h-<hostPublicId>.<domain>
X-Robots-Tag:            noindex, nofollow
```

`Set-Cookie` appears only on the `enter` response.

## F. Lifecycle / Revocation (fail closed)

### F1. Revocation triggers

| Event | Effect | Mechanism |
|---|---|---|
| Ticket unused after 60 s, or used once | Ticket dead | Ticket store |
| Idle > 30 min, or age > 8 h | Grant dead → 401 ended page | Per-request check |
| New Preview Work on the same device and Game | Prior grant revoked | Mint |
| Device revoked, revoke-all, or idle-expired in DeviceRegistry | All that device's grants dead on the next request | Per-request `DeviceRegistry` liveness |
| Game's Stadium disconnects, or its session instance changes (reload, reconnect) | 503 while offline; 410 once a different session instance appears | Per request: `getAuthoritativeSessionForGame(gameId).session.instanceId === grant.stadiumInstanceId` |
| Static server disposed, or restarted on a new port or instance (Game switch in that window, reload) | 410 | Target refresh + instance compare + echo check |
| Game unknown, archived, or removed | 410 | `registry.getKnownGame` |
| Remote Access turned off / `RelayClient.stop()` | All grants cleared | `gateway.revokeAll()` from the stop path |
| Host identity rotated | All grants cleared (the origin changes anyway) | Same |
| Daemon restart | All grants gone (memory only) | Implicit |
| Allowance exhausted or not entitled | 403 page; grant kept | Per-request admission |
| Phone navigates away or cancels | Upstream loopback request destroyed | Sink `close` (D7) |

A transient tunnel reconnect does **not** revoke grants. It is transport, not authority.

Recovery is always the same Dad action: tap **Preview Work** (or the viewer's Retry), which mints a fresh grant. A stale grant is never silently rebound to a new server instance.

### F2. Per-request authorization order (the gateway, every preview request)

1. Method is `GET` or `HEAD`; no `service-worker: script` header.
2. `__Host-sl_pv` present → grant found by hash → not idle- or absolute-expired.
3. `frame.previewTag === grant.previewTag`.
4. `DeviceRegistry` says `grant.deviceId` is live.
5. `remoteMeter.admission()` allows; then `touch()`.
6. Game known; authoritative session connected; `session.instanceId === grant.stadiumInstanceId`; session advertises `game.preview.remote.v1`.
7. Target (cached ≤ 5 s, else RPC) is available, and `target.instanceId === grant.staticInstanceId`.
8. Loopback request carries the instance header. Response echo matches, else 502, drop the cache, and forward nothing.
9. `Content-Length` ≤ 8 MiB, else 413 and abort upstream.
10. Stream with backpressure; fixed headers; update `lastUsedAt`.

Any failure → the fixed status or ended page, and a denial counter (§I). Never partial content.

## G. Implementation Slices

These are small and reversible, and each is independently testable. Order: **S0 → (S1 ∥ S2 ∥ S3 ∥ S4) → S5 → S6 → S7 → S8.** No slice changes local desktop Preview behavior.

### S0 — Wildcard TLS/DNS proof for `p-` labels (human plus a cheap check)

remotePreview: {
  advertised: boolean,                 // hello caps included 'preview.v1' on the live tunnel
