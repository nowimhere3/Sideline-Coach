## 4. C5 — Game Admission Semantics (Q5)

| Event | Slot effect |
|---|---|
| Window opens / workspace discovered / auto-registered | **none** |
| Explicit Add Game completes | admits (`gate.charge('games.active', gameId)`), idempotent |
| First committed Play (queued **or** sent) | admits, idempotent. Refused → nothing is queued or sent, and the result is a capability-named 403 |
| Add then Play / Play then Add | one slot (proven) |
| Archive | releases (`gate.release`). History, reports, registry record and repository are all untouched |
| Restore / reconnecting window | **none** |
| Later Add or Play | re-admits if a slot is available |

**Admission set.** The existing C3 ceiling meter in `~/.sideline/entitlement` is the only Game-count authority. It is durable, idempotent, keyed by `gameId`, and independent of the in-memory Control Plane archive state.

**At the ceiling:**
- Add Game is refused **before the picker opens**, with the Q5 copy.
- New first Plays are refused.
- Already-admitted Games keep working.

**Grandfathering.** At the first start with C5, while the admission meter has no history, every Game with Play history in the Work Ledger is admitted, **even above a ceiling**. Nothing is evicted or locked. Only new admissions wait until the count falls below the limit. It runs once: a later archive is never undone by a restart. Open windows without Plays are not seeded.

**Unlimited** never blocks: 40+ admissions pass in the tests. Admissions are still recorded, as data for later packaging.

**Anti-rotation:** not implemented, per Q5.
> BREADCRUMB: anti-rotation restrictions should be considered later only if real usage demonstrates material abuse or commercial leakage.

## 8. Architecture Deviations and Clarifications

1. **Admission is taken at the commit point** (immediately before the Play is queued or sent), not at the top of dispatch. A Play refused for other reasons (offline, conflicted, duplicate, missing Terminal evidence) never consumes a slot. A committed Play that the Stadium later rejects has already admitted its Game; it was dispatched, which is the Q5 trigger.
2. **Pre-picker refusal at the ceiling** means that at the ceiling, Add Game cannot be used to *re-select* an already-admitted Game. Such a Game is selected from the Sideline instead. This follows Dad's stated preference.
3. **Grandfather criterion** = Games with Play history in the persisted Work Ledger (`currentPlay` or `recentPlays`). This is narrower than S57.2's "or currently known and not archived", because open windows must never consume slots (Q5).
4. **Opting out deletes pending telemetry.** This is a privacy-preserving reading of Q7 ("no telemetry written or sent while OFF").
5. **`surface` is `desktop` for Play/Game events even when the action came from a phone.** The router seam does not carry the principal. `remote.*` events use `remote`.
6. **Dev-operator Formation runs** (Dev Mode `/api/scout/formation-run`) bypass the router, so they emit `scout.play_finished` but not `scout.play_started`. Routed Scout Plays emit both.
7. **The consent preference is writable from a paired phone,** like every other preference on the existing `remote-mutate` route.
