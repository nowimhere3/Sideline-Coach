## THE DESIGN (per the amendment: no finite synonym list)

A structured field already tells Sideline what the value names, so the resolver **finds the one canonical roster/catalog identity contained in the value** instead of matching whole phrases:

```
raw structured value
→ presentation normalization        (case, punctuation, hyphens, emphasis)
→ canonical identity extraction     (longest non-overlapping spans of roster/catalog aliases)
→ ambiguity / contradiction checks
→ resolved (exactly one identity) | explicit-unresolved (none, several, negated, or near-miss of another identity)
```

The new pure module **`src/control-plane/route-normalization.ts`** is the single home for this (no roster, filesystem, VS Code or routing-policy knowledge). `route-constraints.ts` supplies roster/catalog-backed aliases; `routing-policy.ts` was **not** touched. Player is resolved first, then MODEL is resolved against that Player's own catalog.

## EXACT NORMALIZATION RULES

### Player (AGENT / PLAYER / WORKER / TARGET PLAYER / ASSIGNED AGENT / EXECUTOR …)

Aliases come from roster/provider truth, **not de-duplicated**: canonical `playerType`, the field/display label, the capability's provider identity, the logical `scout` target, ledger-known types, and exact numbered friendly names (`Claude 2`) for instances.

1. Normalize presentation. Tokenize.
2. **Blocked outright (`contradictory`):** any negation word (`not, no, never, without, except, excluding, instead, rather, avoid, neither, nor, don't, isn't, anything, anyone, other, else`), any choice/list word (`and, or, vs, versus, either, both, plus, then, also`), or a `& + | /` character.
3. Scan for alias spans, longest first, non-overlapping. Adjacent real words may join into one name (`Anti Gravity` = `AntiGravity`); every joined word must be ≥ 3 letters, so `Code X` never becomes `Codex`.
4. **No span → unresolved. Spans for more than one Player type → ambiguous → unresolved.** A name that belongs to two types is never guessed.
5. A number touching the identity (`Claude 3`) is an instance reference; it resolves only if an exact numbered alias exists, otherwise unresolved.
6. **Near-miss guard (block, never correct):** a leftover word of ≥ 4 letters that is one substitution or one adjacent swap from another known identity word blocks. `Claude Cdoex Agent` is unresolved instead of silently ignoring the typo. Insertions/deletions are not treated as near-misses, so `Claude Code` (`code` vs `codex`) is fine.
7. Otherwise exactly one identity resolves, and every remaining word is descriptive wrapping. An instance is chosen only by an exact numbered name (`Claude 2`, `Claude 2 Agent`); otherwise the Player type.

### Model (MODEL / TARGET MODEL / MODEL TO USE)

Same extraction against the **resolved Player's catalog** (model ids and display names), with two model-specific rules:

- Redundant Player/provider/product words are tolerated (`Claude Sonnet`, `Claude Code Sonnet 5`, `Sonnet Model`).
- Version decoration is tolerated **only around a digit-free family alias** (`Sonnet 5`, `Sonnet 4.5` → `sonnet`). A digit-bearing catalog id never accepts a stray number: `GPT-5.6 Sol` resolves, `GPT-5.6 Sol 2` does not (this preserves the S56.0 rule).
- No identity → unresolved. `GPT-5.6 Soil` never becomes Sol; `Sonet 5` and `Opuss` are unresolved; an alias shared by two model ids is ambiguous.

### Reasoning / effort

The supported vocabulary (`low medium high xhigh max`) is presentation-normalized and gets three harmless equivalents: filler words dropped (`High reasoning`, `Medium effort`), `Extra High` / `X-High` → `xhigh`, `Maximum` → `max`. Anything else, including a choice (`high or low`) or a typo (`Middium`), stays explicit-unresolved. Provider support is still enforced (e.g. Claude does not offer `xhigh`). Deliberately not over-engineered.

## COMPATIBILITY RISKS

- **Stricter on choice words in structured Player/model values.** A structured value containing `and`, `or`, `then`, `also`, `&`, `/` etc. is now unresolved even with one identity (`AGENT: Claude Code / CLI`, `AGENT: Claude then Codex`). This is deliberate (never guess between choices), but a Coach that writes `Claude / Sonnet` on one AGENT line would now stop visibly rather than sometimes matching. It stops loudly, never wrongly.
- **Near-miss block can catch a legitimate descriptor.** A descriptor that is exactly one substitution from an identity word blocks (`Claude Coder` vs `codex`). Rare; the failure is a visible stop.
- **`Claude Code 2` resolves to the Claude Player type** (the number is not adjacent to the name, so it is treated as decoration); only `Claude 2` / `Claude 2 Agent` select instance 2. Type-level routing is what `Use Claude` already does.
- **A provider name is now an alias for its Player type** (e.g. `OpenAI` is not, `codex`/`claude`/`antigravity` provider ids are). If a future provider id differs from its Player type, that id becomes a valid name for it.
- **Descriptive words are tolerated by design**, so a value like `Claude Development Stadium` resolves without Sideline knowing what "Development" means. The protection against misreading is the identity/ambiguity/negation/near-miss checks, not a vocabulary.
- **Unchanged:** Player selection when no structured field exists, natural-language `Use X` behavior, the header window, Scout directive routing, MANUAL mode, and the unresolved error wording.
