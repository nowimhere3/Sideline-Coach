# Result

**VERDICT: GREEN.**

The R6 recommendation digest now carries the predicted p50 burn that R6 already computed for each option. The R7 shadow report compares it, for the chosen route, with burn actually observed on high/medium-isolation Plays, and reports the median error. Routing, scoring and dispatch are untouched.

# Exact Additive Schema Change

One optional field on the existing digest option type `RoutingFilmRecommendationOption` (`routing-film.ts`):

```ts
readonly burn?: readonly { pool: string; window: string; p50: number }[];
```

- `p50` is a fraction of the window (0..1), taken from R6's own `scores.cost.windows[].burnP50`.
- The field is absent when burn was UNKNOWN. It is never a fabricated zero.
- It rides on every digested option (baseline, primary, next best) and adds no new event kind, store, or telemetry owner.
- `schemaVersion` stays 1 and the reader is unchanged. It is tolerant, so old lines read exactly as before.

# Where The Prediction Is Frozen

`recommendationDigest(rec)` (`recommend.ts`), through a new `burnReceipt(option)` helper. The digest is written into the decision event at the real dispatch, after the route is fixed, so the forecast is captured at recommendation time and stored as an immutable plain value. The helper only reads `option.scores.cost.windows`; it calls no estimator, no belief and no clock. `recommendRoute` itself was not modified.

# How R7 Joins Prediction To Observation

`buildShadowReport` (`dev-views.ts`) gains `burnPredictionReport`:

1. For each Play with a digest and outcome, find the digest option whose target equals the **chosen** target (primary, then baseline, then next best). An unchosen option's forecast is never used.
2. Take each observed burn on that Play with isolation `high` or `medium`, an uncensored Δ, and Δ > 0.
3. Pair by exact `pool` + `window` identity. Dimensionality is preserved and never collapsed.
4. `error = (predicted p50 × 100 − observed Δ) / observed Δ`.
5. Report `n`, the median signed error, the median absolute error, a per-window breakdown, and `sufficient` (n ≥ the existing burn minimum of 5).

The `graduation.burnErrorCriterion` field, previously always `not-evaluable`, now reports `within-50-percent` / `outside-50-percent` only when the sample is sufficient. It is otherwise `not-evaluable`. No other graduation semantics changed: status stays `shadow`, the invariant tests stay `not-evaluated-here`, and the calibrated percent stays `not-granted`.

The browser line changes from "unavailable" to the measurement (or "not evaluable"), plus the isolation limitation and a per-window table. Nothing else in the R7 panels changed.

# Historical Compatibility

- Old digests have no `burn`; they still read with zero diagnostics through the real `RoutingFilmStore` (tested).
- No backfill, no migration, no rewrite.
- An old Play with an isolated observation is counted as `withoutPrediction` and stays unpaired. A test shows that even with a rich burn history, from which a prediction could now be made, the report refuses to invent one.

# UNKNOWN / Not-Evaluable Behavior

`status: 'not-evaluable'` (with `n = 0`, null medians) whenever no frozen prediction meets an isolated observation. It always shows the isolated-observation count, the count without a frozen prediction, and this limitation: "only high/medium isolation Plays are compared; predictions are the ones frozen at recommendation time, never reconstructed." There are no counterfactual claims.
