## 2. Implementation decisions within S57.38

1. **Periodic acquisition needs Codex usage enabled explicitly.** Production sets `codexUsage.enabled` explicitly (`daemon.ts` `require.main` block), so this is always on in the real daemon. The older implicit enablement, inherited from `claudeUsage`, stays manual and activity-only. That way ordinary daemon tests never launch the real Codex CLI.
2. **A payload with no `freshness` block keeps the legacy rendering.** The daemon always sends one (empty `{}` when no provider exists), and within that block a missing provider shows UNKNOWN. A block-less payload only comes from before S57.39, which in practice means test fixtures. This avoided rewriting about 60 existing Scoreboard tests.
3. **Claude gets `verifiedAt` through `HealthAuthority`.** This is required because the freshness rule is shared. **Claude's reader and polling are not touched.** Coach should know one side effect: Claude's false `alarm:stale` after 30 idle minutes, the latent defect S57.38 found, is fixed by this. **The Scouts investigating Claude freshness should account for it.**
4. **Not done, as locked:** `pruneExpired()` is not scheduled or modified. `resolveCodexWindows`' `?? 0` is left in place because it isn't on any projection path; the UI checks expiry against the raw window, and test SB-S57.39-5 covers that. No commercial accounting change. No redesign of AI Usage Global.
5. **Verify-only publishing:** each successful unchanged read now saves `ai-health-state.json` and sends one SSE event, about once per cadence per provider. That's intended: freshness moved.
