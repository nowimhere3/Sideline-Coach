## 4. C4 — Remote Metering Behavior

### 4.1 Definition, as implemented

**A Remote Minute is minute index `floor(ms / 60 000)` with evidence** of either:
- a paired phone's `/api/events` stream open at some instant of that minute, or
- an authenticated non-public remote request handled in that minute.

Minutes live in the usage store's per-install **minute set**, so any number of phones, tabs or reconnects inside one minute costs one minute.

### 4.2 Hooks

All hooks are in the daemon and only observe.

| Event | Hook | Effect |
|---|---|---|
| Stream open (remote principal) | `handleSseConnection` | charge current minute; arm 60 s checkpoint |
| Stream close | `removeSseClient` | charge closing minute; disarm when last stream closes |
| Request (non-public, paired) | `dispatchRemoteRequest` | admission check, then charge current minute |
| Checkpoint | 60 s timer while ≥ 1 remote stream is open | charge minutes since the last mark; end grace on time |
| Local desktop | — | never counted (C4-13) |

### 4.3 Durability without over-counting

- **Every charge is journaled at once.** There is no "open interval" state to repair after a crash, so a crash loses at most the minutes since the last checkpoint. That bound is proven in C4-7 (actual presence 5 minutes, recorded 4).
- **Continuous presence between marks is filled only when the gap is ≤ 2 minutes.** After a suspended process or a sleeping laptop, only the minute evidenced *now* is charged, so a stale "open" stream can never manufacture minutes (C4-6).
- **A per-minute memo** makes request storms cost one store lookup per minute.

### 4.4 Exhaustion and grace

1. When a finite allowance reaches zero, a **grace episode** starts. Its length is `grant.graceMinutes` (data), defaulting to S57.2's **5 minutes**.
2. The episode is persisted to `entitlement/remote-meter.json`, so a restart never grants a fresh grace (C4-10).
3. **One concise notice** goes to connected phones as a new SSE event, `remote-allowance {state:'grace', message, graceUntil}`.
4. **During grace,** remote requests work normally and uncharged minutes are not billed.
5. **After grace:**
   - the notice `{state:'exhausted'}` is sent;
   - remote SSE streams are closed;
   - authenticated requests get **403 `{code:'remote-allowance-exhausted', capability:'remote.access', message}`**;
   - a paired phone opening `/` gets a small "Mobile Remote paused" HTML page instead of an app shell that would fail every call.
6. **Unaffected throughout:** the local desktop, already-dispatched Plays, and paired devices (C4-9).
7. **Resume** is automatic at the next period or with a new grant. The episode clears itself on the first allowed admission.
8. **Not entitled** (as opposed to exhausted) is still `403 capability-unavailable` and is never metered (C4-12).
9. **Unlimited** never exhausts and never starts grace. Its minutes are still recorded under the unlimited grant, as S57.2 intends: real usage is the input to later packaging (C4-8).

### 4.5 One Remote clarification (within S57.2)

In C2, `syncRelayClient` refused to open the tunnel when `remote.access` was not *allowed*. With metering live, "exhausted" would have torn down the tunnel. Access then could not resume by itself at reset, which contradicts S57.2 §7.4 ("works again at `resetsAt`").

The gate now keeps the tunnel for **exhausted** and refuses it only for **not entitled**. Refusal of exhausted traffic happens per request. Behavior under `unlimited` is unchanged.

## 5. C6 — Crypto Design

| Aspect | Design |
|---|---|
| Document | `{ v:1, licenseId, installId, profileLabel, grants[], issuedAt, refreshAfter, expiresAt, keyId, sig }`. Unknown top-level fields make it malformed. Every grant is validated (known capability, well-formed allowance/period, unique grantId). `issuedAt ≤ refreshAfter ≤ expiresAt`. Max 64 KB and 200 grants |
| Canonical bytes | Recursive key-sorted JSON of every field except `sig`, no whitespace, non-finite numbers rejected. Key order in the file is irrelevant (C6-5) |
| Signature | **Ed25519** (`crypto.verify(null, …)`), base64url |
| Keys | `keyId` → raw 32-byte public key (hex). `PINNED_ENTITLEMENT_KEYS` is **empty** in production (§8.1). A keyId never borrows another key; removing a key retires every license it signed |
| Verification order | structure → key → signature → install binding. Never throws. Deterministic |
| Binding | `installId` must equal the C0 identity. If the identity is absent → `install-unavailable` |
| States | `none` · `valid` · `refresh-needed` (grants still in force → snapshot `validity:'grace'`) · `expired` (→ built-in, `expired-fallback`) · `invalid` + reason `malformed / unknown-key / bad-signature / install-mismatch / install-unavailable / unreadable` (→ built-in, `invalid-fallback`) |
| Clock rollback | A high-water mark lives in `entitlement/clock.json`. It is written only while a license exists, and only when it advances ≥ 1 h. More than **1 day** behind the mark means rollback: expiry is judged against the mark (rollback never extends a license), and an unexpired license is at most `refresh-needed`. **There is no lockout.** Expired or invalid always falls back to the built-in default (C6-6) |
| Safety floor | A missing, bad or expired license can never reduce access below `DEFAULT_PROFILE` (`unlimited`) |
| Isolation | Only the composition root (`daemon.ts`) and the authority know licenses. `gate.ts`, `router.ts` and the meter import nothing from `license.ts` (C6-9). `/api/status` exposes only symbolic state: no licenseId, keyId, signature, installId or grantIds (C6-8) |
| Not built (by design) | network activation, refresh calls, DRM, hardware fingerprinting, obfuscation, kill switch |

## 6. C7 — Privacy Validation

**Schema.** Every field of `ProductEvent` is one of:
- a closed enum (`name` ×20, platform, surface, capability, entitlement, allowanceBand, outcome, and seven dimension vocabularies);
- a fixed-format identifier (UUID v4 `eventId`, 26-char base32 `installId`, numeric-only semver `appVersion`);
- a bucketed number (`at` minute-rounded; `durationSec` in multiples of 10, ≤ 7 days);
- a small integer count (four fixed keys, 0–10 000).

**There is no free-form string anywhere.** Unknown fields, unknown dimension or count keys, class instances, arrays-as-objects, and nested values are all rejected.

**Proven rejections (C7-2):**
- prompt text
- report path
- Windows path in a dimension
- `gameId` as a dimension
- repository URL
- shell command
- `hostPublicId` (20 chars) and `deviceId` (32 hex) posing as `installId`
- email as `appVersion`
- a branch-named prerelease tag
- a SHA-256 prompt hash posing as `eventId`
- a report filename posing as `capability`
- foreign, huge and fractional counts
- unrounded time and duration

**Outbox:**
- **Consent** is a supplied function. The default is `DEFAULT_TELEMETRY_CONSENT = 'off'`, and with it `emit()` writes nothing: no directory, no file (C7-3, C7-8). A throwing consent source counts as `off`.
- **`emit()` never throws.** This holds for hostile getters, circular objects, Proxy traps and disk failures (C7-4).
- **Bounds:** 5 000 events or 2 MB, dropping the oldest first. Events older than 7 days are dropped. Torn and invalid lines are skipped and the file is rewritten clean (C7-5, C7-6).
- **Transport:** `NOOP_TRANSPORT` (`kind:'none'`) never delivers. Events wait (bounded) with retry metadata, `attempts` plus exponential backoff from 1 min up to 6 h. `batchId` is a deterministic hash of the batch's event ids.
- **No network code:** a static scan of `src/telemetry` finds no `http/https/net/tls/dgram`, `fetch(` or `WebSocket` (C7-7).
- **Separate failure domains:** telemetry imports nothing from entitlement and vice versa. A daemon whose telemetry directory cannot be written still serves status and entitlement normally (C7-9).
- **Dev preview:** `GET /api/telemetry/preview` is local-only by route policy (a phone gets 403) and returns 404 unless Dev Mode is on. It reports consent, transport, pending count and the last 50 events. The visual surface belongs to C9.
- **No emitters were added** (that is C8), so nothing in the product produces events yet.

## 8. COACH REVIEW REQUIRED Boundaries

### 8.1 COACH REVIEW REQUIRED — Production license signing key

- **ISSUE:** C6 verifies licenses against pinned Ed25519 public keys. No vendor signing key exists.
- **WHY IT BLOCKS:** Creating a production keypair means deciding who holds the private key, where it lives, how it is backed up, and how it rotates. That is security-sensitive and hard to reverse, because every license ever issued depends on it. It is not mine to decide.
- **SOURCE TRUTH:** `PINNED_ENTITLEMENT_KEYS` in `src/commercial/license.ts` is deliberately `{}`. Test C6-7 proves that any license, even one correctly signed by a test key, is then `invalid: unknown-key`, and `unlimited` stays in force.
- **OPTIONS:**
  - (a) Dad generates an Ed25519 keypair offline and keeps the private half in a password manager or hardware token. Only the public hex plus a keyId (e.g. `k2026a`) is added to `PINNED_ENTITLEMENT_KEYS`.
  - (b) Defer until the C10 backend exists, and let the backend's signer own the key (for example in a cloud KMS).
  - (c) Pin two keys from day one (active + standby) for painless rotation.
- **RECOMMENDATION:** (b), with (c)'s two-key pinning when it happens. Nothing needs a real license before public packaging, and the backend is the natural key custodian.
- **IMPACT:** None today. All C6 behavior is built and proven with test keys, and production safely ignores every license.
- **CURRENT STATE:** Mechanism complete, trust set empty.
- **DECISION NEEDED:** key custody and timing.

## 9. Architecture Deviations and Clarifications

1. **Per-minute durable charging replaces S57.2 §7.3's "open interval + checkpoint close" bookkeeping.** It meets the same guarantees (≤ 1-checkpoint under-count, never over-count) with no crash-repair state. The ≤ 2-minute continuous-fill rule is the anti-suspension safeguard.
2. **Two small new state files:**
   - `entitlement/remote-meter.json` holds the grace episode, so a restart cannot re-grant grace.
   - `entitlement/clock.json` holds the license high-water mark (S57.2's `lastSeenAt`), written only while a license exists.
3. **`EntitlementValidity` adds `invalid-fallback`** beside S57.2's `valid | grace | expired-fallback`, so "untrusted license" is distinguishable from "no license".
4. **`syncRelayClient` keeps the tunnel on exhaustion** (§4.5). This is a refinement needed for S57.2's own resume rule.
5. **The grace and exhausted notices are a new SSE event type** (`remote-allowance`). The existing Mobile UI ignores unknown events safely. Rendering them is C9 (the Mobile UI was not modified).
6. **The telemetry preview is a read endpoint only.** The visual surface is deferred to C9, as the Play allows.
7. **Under `unlimited`, real phone use now writes `~/.sideline/entitlement/usage.json` and a rotated journal.** The Play authorizes recording, and there is no enforcement effect.
