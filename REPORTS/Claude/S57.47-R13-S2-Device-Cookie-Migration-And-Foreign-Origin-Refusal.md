## Behavior
- **Issuance:** pairing exchange and every authenticated refresh emit `__Host-sl_dev=<token>; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=2592000`. No `Domain`.
- **Precedence:** if `__Host-sl_dev` is present, only it authenticates. Legacy `sl_dev` is never consulted, regardless of cookie order. A bad canonical cookie is final: a valid legacy cookie does not rescue it (tested).
- **Legacy migration (no re-pair):** legacy-only request authenticates via `sl_dev` and the response sets `__Host-sl_dev`. The next request carries both; canonical authenticates and the response expires legacy (`sl_dev=; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=0`). After that the session is canonical-only and sliding refresh continues.
- **Origin protection:** in the adapter, any request whose `Origin` header is present and not equal to the expected Sideline app origin gets `403` (JSON, `no-store`, no Set-Cookie), for every method including GET, before auth. No Origin or the correct Origin is unchanged. The existing mutation checks (action header, trusted Origin) are untouched. The Preview `p-` surface is not implemented.

## Deviation (please note)
The frame wire format carries one string per header (`Record<string,string>`, enforced in `relay-frames.ts`, `RelayClient.parseReq` and `reference-relay.ts`), so one response cannot carry both "set canonical" and "expire legacy" `Set-Cookie`s. Joining them with `, ` would be wrong for cookies. Widening the wire format would touch the deployed relay, which is S3 scope and needs a human deploy. So migration converges over two authenticated responses instead of one (issue canonical, then expire legacy). Security is unaffected: canonical wins from the first response on. A junk or planted legacy `sl_dev` alongside a valid canonical is expired the same way. During the one response that carries the legacy expiry, the canonical 30-day refresh is skipped. The next request refreshes it, which is harmless against a 30-day window. If S3 later makes `set-cookie` multi-valued, this can collapse into a single response with no other change.
