# Stage Gate (representation and proof it is CLOSED)

`R8_ADVISORY_STAGE_GATE = Object.freeze({ open: false, ... })` is a **compile-time constant**. That is the cleanest available representation, so I added no persistence and no product state. `advisoryStageOpen()` fails closed: only a literal `open === true` opens it, and `undefined`, `{}`, `1` and `'true'` are all closed.

- **No product surface can open it.** There is no preference, no env var, no HTTP field and no Dad or Dev switch. A test scans `src/` and finds the constant referenced only by the gate module and the daemon default. The page contains no reference to it.
- **Test seam only:** the daemon constructor accepts `routingAdvisoryStage`, the same kind of seam as the existing `routingFilm` journal option. Production never passes it.
- **Opening it later:** a dedicated gate-opening Play changes the constant after proving all three criteria (≥ 50 shadow Plays, median absolute relative burn error ≤ 50%, invariant suite green). The R7 shadow report is the evidence surface. Nothing here infers "invariants passed", because no honest runtime source exists.

# `optionToDecision(rec, option, ctx)`

Pure and deterministic; never re-runs the recommendation; holds no eligibility logic.
- **send / queue / handoff:** builds the existing `RoutingDecision` from the option's own executable `route`. Player type, instance, model, effort and action are preserved exactly (`send` → `dispatch`). The label and `playLabel` come from the existing AUTO decision. A handoff reuses that decision's context preamble, or builds one through the existing `buildHandoffPreamble`.
- **Freshness guards** (not selection): the seat must still exist in the same readiness (ready for send/handoff, busy for queue), and the model and effort must still be in its catalog. Otherwise it is refused (`seat-unavailable` / `route-stale`) and never rerouted.
- **Refused outright:** `wait-for-reset` (R9 owns it), MANUAL, any explicit route lock, an option that is not the one the choice names, and a primary that agrees with the baseline.
- **Scout-first:** yields the existing Scout decision shape (Formation seat, `scoutNeed`, `scoutAvailable`). The unchanged router then dispatches the Formation and stages the one bounded post-Scout continuation. No new Scout mechanics.

# Route-Choice Integration

`[USE]` follows the same shape as the existing alternative button:

```
USE → routeChoice 'recommended-primary' + recommendationId
    → POST /api/route/preview (staged route shows exactly what will run)
    → Send → POST /api/dispatch (same fields)
    → daemon resolves the offer → optionToDecision
    → router.dispatch({ advised }) → normal dispatch
```

- The daemon accepts only a suggestion it actually offered: an in-memory map, capped at 20 entries with a 10-minute TTL, keyed by recommendation id and bound to the Game and a hash of the Play. A changed Play, an unknown or unshown id, a consumed offer, or MANUAL is refused with **409 and nothing sent**.
- There is no browser-to-Player path and no parallel endpoint.

# `decidedBy`

`coach-accepted-primary | coach-accepted-next-best | coach-accepted-scout` on the existing decision event. The shadow baseline remains the static AUTO decision, so Film can tell advice from baseline (tested). Historical lines are untouched. Dismiss records nothing: there is no dismiss endpoint or event.

# Dad Chip

One line, one subline, two buttons (`USE`, `Dismiss`).
- **Line:** `Suggest {name} · Strong pick|Good pick`, capped at 28 characters.
- **Subline:** fixed templates keyed by the headline reason code (`EXPIRING_5H`, `WEEKLY_SCARCE`, `FIVE_HOUR_SCARCE`, `SCOUT_SAVES_PREMIUM`, `NO_SCOUT_FIELD_POSSESSED` / `FIELD_POSSESSED`, `PRIOR_ONLY`), capped at 40. A code without a template gets no subline, so nothing is generated.
- **No numbers:** no percentages (R10 not graduated), no prices, evidence or Dev detail (asserted).
- **Shown only when** the stage is open, mode is AUTO, the recommendation disagrees with the baseline, the route is not locked, and the strength is not a toss-up.
- **Dismiss** is JS session state only: it hides the chip, sends nothing, records nothing and changes no route. A dismissed suggestion stays quiet for the session; a different one still shows.

The S57.1 §16 secondary action would be a third button, which the R8 brief forbids (two buttons maximum). `next-best` and `scout` acceptance are therefore implemented and tested at the route-choice level, but the chip offers only `USE` and `Dismiss`. SCHEDULE is absent everywhere.
