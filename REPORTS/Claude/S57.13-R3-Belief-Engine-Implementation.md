# Implementation Summary

**Contract.**

```
computeBelief(
  target:  { playerType, modelId?, effort?, resolvedModelId? },
  profile: { taskClass, difficulty, role?, gameId? },
  priorPack: PriorPackSource,
  filmIndex: FilmIndex,
  now: number,
  options: { baselinePreference, resourcePool? }
) → CapabilityBelief
```

`CapabilityBelief` carries:

- `firstPass {mean, lo, hi}` (Beta posterior mean and 20th/80th percentiles)
- `nPrior` (after inheritance and decay), `nLocalEff` (own node), `pooled`
- `source` (`researched | inherited | baseline-preference`), `priorNode`, `inheritedFrom`, `priorNote`
- `priorPackVersion`, `segmentVersion`, `evidence` (S57.1 §12.1 words), `drift?`
- `durationMin` and `burn` (UNKNOWN when unsupported)

Output numbers are rounded to 6 decimals, so replay is byte-stable.

**Prior (S57.1 §6.2 + S57.9):**

- α₀ = m₀·n₀_eff and β₀ = (1−m₀)·n₀_eff, where n₀_eff = n₀ · 0.5^(age/180 d).
- Inherited nodes use n₀ × 0.5.
- Baseline preference uses AUTO's own table: rank 1/2/3 → 0.70 / 0.62 / 0.55 at strength 2. A playerType absent from the table → **0.55 / 2**. Baseline priors are policy, not research, so they do not age.
- `*` never matches the pack's `wildcardExcludes` (`ultra`, `provider-managed`, `provider-default`), so those targets fall to baseline.

**Local evidence (S57.1 §5.2–§5.3):**

- Each observation's weight is w = sim(class) · sim(diff) · decay(age) · attribution · gameBonus.
- Own-node evidence adds w·y and w·(1−y).
- Siblings add λ · w: λ is 0.35 for the same model with another effort, 0.15 for another model in the same lineage, and 0.05 for another lineage of the same playerType.
- Pooled mass is scaled to at most **6** in total.
- No pooling crosses a playerType or a role. A provider-managed seat informs only its own node.

**R3/R5 boundary (as directed):**

- An R2 `completed` outcome is **not** a clean first pass.
- First-pass evidence exists only when a `FirstPassResolution` is supplied (R5 later; synthetic fixtures now).
  - `clean` requires `completed`.
  - `player-defect` requires `completed` or `failed / partial / blocked`.
  - `interrupted / unknown / not-sent` are never skill evidence.
  - Any inconsistent resolution is refused with a diagnostic.
- Attribution weights: outcome / Coach / envelope 1.0, rule-high 0.6, rule-low 0.3.
- R3 contains **no** R5 attribution rules.

**Drift (S57.1 §5.5):**

- Needs ≥ 5 recent resolved outcomes at the exact node for the same task class.
- The newest 5 are tested against the posterior built from everything before them. Drift is suspected when their success count falls in either 5% tail of the posterior-predictive Beta-Binomial(5).
- While suspected, the node's own Film decays on a **45-day** half-life instead of 90.
- It is recomputed from Film every time, so it clears once the newest five return inside the band. It never resets evidence.

**BurnEstimate (S57.1 §11.7):**

- Samples are per-window R2 burn observations with isolation **high or medium only**, in the **seat's own pool** (`options.resourcePool`), pooled with the same λ and cap.
- `low` / `none` isolation, other pools, and `not-sent` Plays are excluded.
- A zero delta is censored (≤ 1%): excluded from the estimate and reported as `censoredSmall`.
- Δ above 3 × the comparable p75 is dropped as possible external usage (only with ≥ 4 samples).
- μ = (n₀·log prior p50 + Σ w log Δ) / (n₀ + Σ w).
- Range: weighted empirical quantiles when Σ w ≥ 5; otherwise the prior (or thin empirical) range widened 1.5×, with a ×/÷1.5 floor so one sample is never an exact range.
- Confidence: high (Σ w ≥ 15 and ≥ 50% high-isolation), medium (Σ w ≥ 5), low, or unknown.
- Window ids are open strings from Film. There is no `fiveHour`/`weekly` enum.
- Burn does **not** need resolution. Unresolved production Film already carries it.

**Duration:** same estimator, over wall-clock minutes of **completed** comparable Plays.

# Interpretations And Deltas To Record

1. **R2 records no PlayProfile.** S57.1 §7 put `profile` on the decision event; R2 did not persist it.
   - R3 accepts profiles as an injected `clientRef` join.
   - Without one, an observation's class is treated as `default` (sim 0.3 to others) and its difficulty as adjacent (0.6). Production Film therefore counts at about 0.18 weight for implementation Plays.
   - **Action for R5/R6:** a profile source (task class, difficulty, role) must be written at dispatch, or joined from the ledger, before local film can dominate. This is a join, not a redesign of R2.
2. **Drift band.** S57.1 says "the posterior's 5th–95th percentile band". Applied to the *mean* of five binary outcomes, that band flags healthy nodes routinely: five straight successes on a ~0.77 node would read as drift. R3 uses the posterior *predictive* band for five outcomes: same intent, correct for binary data.
3. **Small constants S57.1 left open, all frozen and versioned:**
   - `quick↔default` uses the lower value, 0.1.
   - A *medium* rule confidence weighs as low (0.3); no S57.1 rule emits medium for player-defect.
   - The low-confidence range floor is ×/÷1.5.
   - Outlier removal needs ≥ 4 samples.
4. **Alias drift.** A Claude alias node is demoted to inherited (×0.5) only when a `resolvedModelId` is supplied and differs from the pack's `resolvesTo`. Film does not record resolved slugs yet (see S57.7 §14.4). Until something observes them, alias nodes stay researched.
5. **Variant ids.** An id like `family-medium` collapses to `family` only when that family is a researched modelId of the same playerType. This is generic; it does not special-case AntiGravity.
6. **Packaging note for R6.** `package.json` `files` and `tools/dev/audit-vsix.mjs` do not include `src/routing-intel/priors.json`. R3 has no runtime consumer, so packaging was not changed. The R6 Play must add the pack to `files` and to the audit's required list.
