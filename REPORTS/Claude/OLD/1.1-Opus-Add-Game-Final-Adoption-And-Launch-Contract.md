## 9. FINAL GAME ADOPTION CONTRACT (frozen)

Selecting a folder in Add Game is the human's authority to make it a Game. The Stadium that showed the picker runs `adoptGameFolder()` before resolving:

| Folder class | Result | Writes |
|---|---|---|
| Has valid `.sideline/game.json` | reuse marker identity | nothing |

| Local Git repo, no remote (Gallery-Media-Suite) | **adopt** | `.sideline/game.json` with `game_local_<16 hex>` |

| Marker cannot be written | refuse: "Coach couldn't save its Game file in that folder. Check that the folder isn't read-only…" | nothing left behind |

## 10. GIT/GITHUB VS GAME IDENTITY (frozen)

```
Game identity  ≠  Git repository identity  ≠  GitHub account authentication  ≠  Stadium identity
```

- A Game **need not have a remote** and **need not be Git**.
- A Git remote is a *strong existing identity* that Add Game reuses. It is not a prerequisite.
- GitHub authentication plays no part in Add Game. No Device Flow or sync was built.
- Git/GitHub metadata may **enrich** a Game later (e.g. the V0.1 repository-URL coordinate). It never replaces an established marker identity, because the marker outranks the remote.

---

## 11. `.sideline/game.json` OWNERSHIP

- **Owner:** the Game folder. It is project data, travelling with the folder, shared by every Stadium, profile, clone, and machine.
- **Writer:** only explicit Add Game adoption, and only when no strong identity exists. Content:

  ```json
  {"version":1,"gameId":"game_local_…","displayName":"<folder>","createdBy":"Sideline Coach (Add Game)","createdAt":"<ISO>"}
  ```

  Readers ignore extra fields.
- **Never:** overwritten, rewritten on rename, written into a remote-backed repo, written into another repository's subfolder, deleted by Exit/Archive.
- **Committable by design.** Committing it makes every clone the same Game, exactly like a shared remote. Whether Sideline later edits `.gitignore` is **not** decided here (Game Bootstrap).

## 12. MOVE/RENAME/STABILITY CONTRACT

| Event | Outcome |
|---|---|
| Folder moved or renamed | same `gameId` (marker travels); daemon records the new root on the next hello |
| Same folder added twice | `existing: marker` → same `gameId` → `decideAddGame` selects/opens the one Game |
| Two adoptions race | exclusive create (`wx`); the loser reads the winner's marker → `existing` |
| Local Game later gains a GitHub remote | same `gameId` (marker Tier 1 outranks remote Tier 2) |
| Remote-backed Game changes remote URL | unchanged from today: identity follows the remote (no marker written for it) |
| Folder copied (duplicate checkout) | both copies share the `gameId`; two open windows → `conflicted` (same rule as two clones) |
| Marker deleted by the human | folder falls back to remote/unknown; the next Add Game adopts a **new** `gameId` (explicit human act) |
| Folder read-only | refused truthfully; nothing written |

## 20. FROZEN DECISIONS

1. **Freshness first:** an Add Game failure is attributed only after proving the *loaded* code of the serving Stadium; disk source is not evidence.
2. **Serving Stadium:** a known-stale selected Stadium yields Add Game mechanics to a connected current Stadium; staleness never blocks when no current Stadium exists; unknown build never triggers a switch.
3. **A Game needs neither GitHub nor Git.** Explicit Add Game is sufficient authority to adopt a safe folder.
4. **Game identity must be derivable from the folder itself,** identically by every Stadium, profile and machine. Stadium-local (`globalState`) identity is never an Add Game identity.
5. **Ladder:** marker → Git remote → explicit adoption writes marker (`game_local_<16 hex>`). The root-commit tier is not the adoption mechanism.
6. **Marker ownership:** folder-owned, written only by explicit adoption when no strong identity exists, exclusive create, never overwritten, never in remote-backed repos or inside another repository.
7. **Stability:** marker outranks remote, so move, rename, and a later remote never fork a Game id.
8. **Refusals are plain language.** Dad Mode never mentions `.sideline`, `game.json`, or markers.
9. **Boundary:** marker creation belongs to identity/adoption; `Coach/`, `Reports-*`, SOP, `.gitignore` policy belong to Game Bootstrap.
10. **Game ≠ Git repository ≠ GitHub authentication ≠ Stadium** (reaffirmed). Git/GitHub may enrich, never replace, an established Game id.
