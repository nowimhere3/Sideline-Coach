# S7.1 — Legacy Report Discovery Compatibility Hardening

## WHAT WAS

Legacy report discovery (`CoachServer.getReportGlobs()` in `src/server.ts`) had two field-proven compatibility defects, diagnosed read-only by an Opus 5 field diagnostic (`REPORTS/Claude/Opus-Multi-Game-Report-Discovery-Regression-Root-Cause.md`):

1. **R2 defect — replacement, not extension.** `getReportGlobs()` returned the user/workspace `coach.reportGlobs` value **whenever it was non-empty**, discarding the recognized-root defaults entirely. A single user-scope setting (`"coach.reportGlobs": ["**/Reports/**/*.{md,txt}"]`) silently became the *only* discovery glob for **every Game on the machine**.
2. **R3 defect — case sensitivity.** VS Code's own glob include matching is case-sensitive even on Windows (independently reconfirmed in this Play with Node's `fs.globSync`, which showed identical behavior — see below). A recognized root on disk as `REPORTS/` was therefore invisible to a pattern spelled `Reports/`, even though the newer S7 canonical `RelativePattern` path already resolves on-disk casing correctly.

Field evidence from the diagnostic: Trend and Tap Assist (`Reports/`, 19 reports) worked only because its folder happens to be spelled exactly `Reports`. SidelineCoach-GameTest (`REPORTS/`, 36 reports) and gallerytest (`Reports and Docs/`, 29 reports) were both silently undiscoverable through the legacy path.

## WHAT CHANGED

New pure module **`src/report-glob-policy.ts`** (no `vscode` import, unit-testable without an Extension Host):

- `recognizedReportRootGlobPatterns(platform)` — one glob per name in `RECOGNIZED_REPORT_ROOT_NAMES` (`Reports-SLC`, `Reports`, `Docs REPORT`, **imported from `game-filesystem-contract.ts`, not re-declared**, per the Play's explicit instruction not to create a second vocabulary that can drift). On `win32`/`darwin` it emits the exact, upper-case, and lower-case spelling of each name; on other platforms, exact case only.
- `buildReportGlobs(configured, platform)` — the recognized-default patterns **UNION** any configured `coach.reportGlobs` entries, deduplicated, with deterministic order (defaults first in `RECOGNIZED_REPORT_ROOT_NAMES` order/case, then configured extras not already present).

`server.ts`'s `getReportGlobs()` is now a one-line adapter:

```ts
private getReportGlobs(): string[] {
  const configured = vscode.workspace.getConfiguration('coach').get<string[]>('reportGlobs', []);
  return buildReportGlobs(configured);
}
```

The old hard-coded runtime fallback array is gone — it is subsumed by `buildReportGlobs([])`, which always returns the recognized-root defaults regardless of what `configured` contains.

**Untouched, as instructed:** `reportPatterns()` (S7 anchored `RelativePattern` prepend, `server.ts:737–749`), `StadiumFilesystemContractCache`, `ReportPublisher`, `describeReport()`, the manifest `coach.reportGlobs` default, and every Game repository.

## WHY THIS IS THE SMALLEST FIX

- One new pure file, one changed method body (2 lines → 2 lines), one import line, no touched call sites (`getReportGlobs()`'s signature, callers, and every other method are unchanged).
- Reuses the existing authoritative vocabulary (`RECOGNIZED_REPORT_ROOT_NAMES`) instead of inventing a second list, exactly as instructed.
- Does not touch the S7 canonical path at all — that path is already case-correct (it anchors against the Stadium's own on-disk-cased evidence) and needed no repair.
- Case variants are generated only for the three recognized names, never for an arbitrary custom glob — `Reports and Docs` is not, and does not become, case-expanded or canonical.
- No Game filesystem was read, written, or reasoned about by product code in this Play; the fix is entirely in glob-string construction.
