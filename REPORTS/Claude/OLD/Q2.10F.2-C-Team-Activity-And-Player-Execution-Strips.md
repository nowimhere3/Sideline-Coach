# Slice B Contract Consumed

Verified in `src/public/index.html` before building:

- **Store:** `executionStore = { gameId, epoch, serverOffsetMs, views: Map<instanceId, ExecutionView> }`. It is filled only by `applyExecution` from `status.execution` snapshots and `execution` SSE events.
- **Clock:** `serverNow()` is skew-corrected. `formatPlayElapsed(startedAt, now)` is the existing formatter (`0:38`, `4m 18s`, `1h 03m`).
- **Hook:** `afterExecutionChange()` runs after every accepted store change. Slice C renders only from here. No parallel execution listener was added.
- **Stale daemon:** when `status.execution` is absent, the store stays empty.
- **`ExecutionView` fields** (from `src/control-plane/execution-projection.ts`): `state`, `revision`, `playRef`, `summary`, `executionStartedAt`, `finishedAt`, `durationMs`, `report{path,filename,acknowledged}`, `awaitingReport`, `queue{count,head{reasonKind,waitingOnName}}`, `detail`, `executionType`.

The store had every field each required V0 state needs, so no escalation was necessary.

# TEAM Header

`renderTeamHeader(views, names)` is a pure function that returns a string. `renderTeamHeaderInto()` writes it into `#rosterSummary` (the `<h2>`).

**Inputs it does not use:** the selected Player, the dispatch attempt, capability state, `turnState`, and the Incoming/report count.

**Connection truth still wins**, as the architecture requires:
- `TEAM · Offline` when the Game is not connected;
- `TEAM · Synchronizing…` when the Stadium is connected but the roster is not yet published.

**Layout:**
- The old `Players · N On Field · N On Bench` count has left the header. On Field stays on each card.
- The heading is always visible, expanded or collapsed.
- The card eyebrow now reads `Roster`, and it is still hidden when collapsed.

# Aggregate State Priority

| Count | States |
|---|---|
| ACTIVE | `starting`, `working`, `queued`, `waiting-capacity` (direct-shell running is `working` and counts) |
| NEEDS YOU | `needs-you`, `couldnt-finish`, `unknown` |
| REPORT READY | `finished` with `report` present and `report.acknowledged !== true` (never `awaitingReport`) |

**Rules:**
- Segments are ordered NEEDS YOU → ACTIVE → REPORT READY. Zero counts are dropped, and at most two segments show.
- ` · {Name}` is appended only when `1 ACTIVE` is the sole segment.
- There is no `0 ACTIVE`.
- The header never shows a timer.

# Player-Attached Play Strips

- **Record per row:** `renderStatus` still rebuilds rows. While building, it records `rosterRows: Map<instanceId, { row, name, typeName, strip, elapsedNode, key }>`.
- **`renderPlayerStrips()`**, called from `afterExecutionChange()`:
  - builds a change key for each row from the canonical view fields, name and disclosure state;
  - if the key is unchanged, the strip DOM is left untouched;
  - otherwise it removes the old strip and appends `renderPlayStrip(view, record)` as the row's last child (beneath actions and the existing queue lines).
- **Row rebuild:** `afterExecutionChange()` now runs after the rows are built, not before, so a full rebuild and an SSE-only change use the same path.
- **Player cards:** card line 2 remains `On Field · Controlled`. Eligibility and execution are visually separate.

# State-to-Strip Mapping

| state | Strip | Clock | Action |
|---|---|---|---|
| idle | none | — | — |
| starting | `◌ Starting…` · summary · (`N more queued`) | no | — |
| working | `◉ Working` · summary · (`N more queued`) | only when `executionStartedAt` is finite | — |
| queued | `◌ Queued` · `Waiting for an available turn`, or `Waiting for {waitingOnName} to finish another Play` only when `head.reasonKind === 'waiting-for-player'` and a name is present | no | — |
| waiting-capacity | `△ Waiting for capacity` · `{Type} can't start yet` | no | — |
| needs-you | `! Needs you` · `{Name} needs more direction` | no | `Review`: focuses the existing needs-attention queue line's `Try again`; shown only when that line exists |
| couldnt-finish | `✕ Couldn't finish` · `The Play stopped before a report arrived` | no | `See what happened` (disclosure) |
| unknown | `? Can't confirm status` · `Check the Game before sending it again` | no | `See what happened` (disclosure) |
| finished | `✓ Finished` · static duration from `durationMs` · `Report ready in Incoming` / `Report on its way` | static only | — |

**Why the disclosure is conservative:** `See what happened` toggles an inline line showing `view.detail`, or a human fallback. It performs no acknowledgement, calls no endpoint, and does not change truth. Slice E owns recovery and acknowledgement.

# Canonical Clock Rendering

- Working elapsed is `formatPlayElapsed(view.executionStartedAt, serverNow())`.
- The origin is written to `[data-elapsed-since]` on the clock node. The browser never writes or originates it.
- Working without an origin shows no clock node.
- Finished shows `formatPlayElapsed(0, durationMs)` as static text (`8m 19s`), with no `data-elapsed-since`, so it can never tick.

# One-Ticker Architecture

There is exactly one `setInterval(…, 1000)`. It calls:

1. **`tickElapsedClocks()`:** for each rendered row whose strip has an elapsed node, it rewrites `textContent` from the node's `data-elapsed-since` and `serverNow()`. It does not:
   - change the store or state;
   - render or remove strips;
   - write the TEAM header, Outgoing, Incoming or the announcer;
   - call the server.
2. **`renderTransitionalActiveStatus()`:** Slice B's transitional last-attempt line. It is folded into the same interval so a second interval does not exist. **Slice D removes it together with `#activePlayStatus`.**

Slice B's separate `setInterval(renderTransitionalActiveStatus, 1000)` was removed.

# Queue Rendering

- **Queued:** no clock. The named wait appears only from canonical `queue.head`; no reason is inferred.
- **Working or Starting with a queue:** the primary state stays, plus a `N more queued` line.
- **Existing per-item queue lines** (`Queued #1 · …` with Cancel / Try again) are unchanged and sit above the strip.
- **Focus keys added:** Try again is `queue-attention` (the target of Review); Cancel is `queue-cancel:{id}`.

# Roster Rerender / Focus Survival

**Before rebuild:**
- `captureRosterFocus()` records `{ instanceId, key }` when `document.activeElement` is inside a `.player[data-instance-id]` row and carries `data-focus-key`.
- Keys: `field`, `remove`, `upgrade`, `queue-attention`, `queue-cancel:{id}`, `strip`, `strip-review`, `strip-detail`.

**After rows and strips render:**
- `restoreRosterFocus()` finds the same key in the same exact instance's new row.
- It focuses through `focusElement`, which uses `{ preventScroll: true }`, so the viewport does not move.

**Strip-only replacement** (from an SSE event) restores focus to the same key inside the new strip, or to the strip itself.

**Roster order** is the status order (type / seat). No code path sorts by execution state.

**Highlight seam for Slice D:**
- `highlightUntilByInstance` (a Map) is re-applied as class `player-reveal` on rebuild while unexpired.
- CSS is provided, with no glow under reduced motion.
- There is no writer, no `revealPlayer`, and no `scrollIntoView`.

# Collapse Behavior

- Background execution changes never call `setRosterCollapsed`.
- When collapsed, the header text updates in place: `TEAM · 1 ACTIVE · Claude 1`.
- The only existing expansion paths are unchanged: the toggle, and the once-per-Game workflow default.

# Accessibility

**Announcer:**
- `#executionAnnouncer` is `class="visually-hidden" aria-live="polite"`.
- `announceExecutionTransitions()` speaks only per-instance state changes, for example "Claude 1 is working.", "Codex needs you.", "Claude 1 finished. Report ready in Incoming.", "Coach can't confirm Codex's status.".
- The first view of a Game or epoch is learned silently.
- Refreshes with no transitions say nothing, and the ticker never announces.

**Each strip:**
- `role="group"`, with `aria-label="{Name}: {state words}"` (no elapsed time);
- `tabindex="-1"` and `data-focus-key="strip"`, ready for Slice D;
- the elapsed node is `aria-hidden="true"`.

**Buttons and state:**
- Buttons have explicit names: "Review the Play for Claude 1", "See what happened with Codex". The disclosure uses `aria-expanded`.
- Every state shows a glyph plus words; colour only reinforces.

# Mobile Behavior

- The strip spans the card (`grid-column: 1 / -1`, `min-width: 0`) and stays in flow. There is no fixed, sticky or absolute positioning.
- The head row is flex. The state text ellipsizes; the clock is `flex: none` with tabular numerals.
- Summary lines use `overflow-wrap: anywhere` and clamp to two lines.
- Strip buttons are `min-height: 40px` and flex to full width at ≤460px.
- There is no floating timer, global live strip or automatic scrolling.
