==================================================
EXACT ROOT CAUSE
==================================================

`src/game-adoption.ts`, in `adoptGameFolder`, after the marker and Git-remote checks:

```ts
if (!fs.existsSync(path.join(root, '.git'))) {
  const enclosing = findEnclosingRepository(root);   // walks up parent folders looking for a .git
  if (enclosing) return refused('inside-repository', 'That folder is inside the … project. Choose the top folder of … instead.');
}
```

`GPT-Reader-FA` has no `.git` of its own, `findEnclosingRepository` found `TamperMonkey\.git` one level up, and
the folder was refused with a message telling Dad to pick the parent. That upward walk was **the only one in the
codebase**. `game-identity.ts` reads exactly `<root>/.sideline/game.json` and `<root>/.git` and never looks at a
parent (asserted by test).

That is why removing the refusal is safe for the identity requirement: nothing else can leak the parent's
identity into the nested Game.

==================================================
PARENT-REPOSITORY NON-MUTATION PROOF
==================================================

EFA-5 snapshots the entire parent tree, **including all of `.git`**, byte by byte (path plus SHA-1) *before*
adoption. It takes the snapshot before any `git` command because `git status` can itself refresh `.git/index`.
After adopting a folder nested inside `userscripts/`:

* The parent tree is byte-identical, excluding only the nested folder's own new marker directory.
* `.git/config` is byte-identical (no remote, config, or metadata change).
* There is no `.sideline` at the enclosing repository root, and none at the intermediate folder either.
* The only new thing anywhere is one file, `GPT-Reader-FA/.sideline/game.json`.
* Only afterwards, `git status --porcelain --untracked-files=all` in the parent reports exactly
  `?? userscripts/GPT-Reader-FA/.sideline/game.json`, and `HEAD` is intact.

EFA-11 repeats the byte-identical check across every failure path (unwritable, unreadable marker, missing folder,
file instead of folder), so a refused adoption also leaves the parent untouched.
