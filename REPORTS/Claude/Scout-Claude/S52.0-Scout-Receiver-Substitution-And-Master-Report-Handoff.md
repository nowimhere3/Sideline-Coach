- **Before this Play it had no failure classification at all:** non-zero exit = `FAILED`, full stop. No substitution, no bench, no depth chart.
- Report writing: JSON only (`completion.json`, `SCOUT-PLAY-COMPLETE.json`) plus per-lane `SCOUT-<lane>-Reconnaissance.md`. There was **no master report and no synthesis**; the terminal ended with a JSON dump containing four path fields.

## CURRENT PRODUCT FORMATION ARCHITECTURE FOUND

`src/scout-formation.ts` (`runScoutFormation`), reached by the browser through Stadium → `ScoutPlayerAdapter.execute`:

- One human objective; **every selected receiver gets the identical canonical Play** (same hash). Redundant independent looks, not distinct lanes.
- Candidate pool = built-in AntiGravity/Gemini Direct **plus every Combine scorecard on disk** (`combineDerivedFormationCandidates`), each with a `eligible()` that **re-reads its scorecard fresh** — READY or excluded. Formation size 1–3, default `min(2, eligible)`.

- Writes the canonical parent `Formations/<id>/FORMATION-RESULT.md` (+ `FORMATION-COMPLETE.json`), with mechanical synthesis (executive-answer excerpts, self-reported contradictions, failed scouts).
- Browser handoff (already solved, untouched): `formation.resultPath` → Stadium registers the exact parent (`scoutFormationReports`) → Incoming preview/copy/acknowledge; the Scout card shows Scouting · N Scouts running from `onSelected`.
- **Before this Play it had no substitution:** a `BLOCKED` receiver simply stayed blocked and the Formation went PARTIAL/BLOCKED, even with READY receivers sitting unused on the bench.

## CONVERGENCE DECISION

**WHAT IS SHARED (now):** the failure classification, the bounded selection rule, the substitution record, and the parent artifact name/header. **The depth chart is the Combine scorecards, in both.** Not a second roster.

**WHAT WAS DUPLICATED:** the infrastructure-failure regex (Combine executor only), and the "which receivers may take the field" notion (CLI: a hard-coded list; product: scorecards).

**WHAT CONVERGED:**
1. New `src/scout-substitution.ts` — classification, selection, `MAX_SUBSTITUTIONS_PER_LANE = 2`. The Combine executor's inline regex was **moved verbatim** here (verified character-for-character by the patch) and `scout-combine.ts` now imports it, so the two engines cannot drift.
2. Eligibility for the CLI's bench = the **same Combine scorecards** the product reads (`combineReadinessForModel`, fresh each call) **plus** the fail-closed read-only agent contract. No scorecard = UNKNOWN = not eligible.
3. Master report = `FORMATION-RESULT.md`, same first-line title and counter header as the product parent.

**WHAT REMAINS SEPARATE (deliberately):**
- **Lane semantics.** CLI lanes have distinct objectives; product receivers are identical redundant looks. Merging them would erase a real difference. Substitution means "next receiver for *this lane*" in both.
- **The two engines and their renderers.** I did not route `scout:play` through `runScoutFormation`; that would silently change manifests from "distinct lanes" to "same Play N times." The CLI master report **embeds the surviving receiver reports** (Dad opens one file); the product parent keeps its existing mechanical excerpt format.
- **One small duplicated constant:** the `Combine/Scorecards` path. The CLI runner cannot import the Combine (it would create a `runner ↔ combine` import cycle — `scout-combine` already imports the runner), so `scout-substitution.ts` reads the scorecard JSON directly and says why in its comment.

## INJURED-SCOUT SUBSTITUTION IMPLEMENTED

Per lane, after a receiver's attempt ends:

1. **Classify.** Not COMPLETE and positively infrastructure → substitutable. Otherwise stop.
2. **Retire the receiver for this Play** (`injured` set) — out for the whole attempt, not just the lane.
3. **Select** from the bench in depth-chart order, skipping: receivers already used on this lane, receivers assigned to or fielded on **any other lane**, receivers injured earlier in this Play, and anyone whose **current** eligibility says no.
4. **Bound:** at most 2 replacements per lane; a receiver is never selected twice for a lane; no recursion; the loop is a `for(;;)` that can only advance through the finite bench.
5. **Record** every decision — including "lane needed a replacement and none was eligible", with the reason each candidate was passed over.
6. **Field it** in the same lane with the same objective. Surviving lanes are not restarted, cancelled, or re-queued (test asserts launch counts).

CLI specifics: attempt 1 keeps the original `stdout.log`/`stderr.log`; later attempts write `stdout.attempt-N.log`, so **failed film is never overwritten**. `ScoutResult` gains `originalAgent` and `attempts[]`; completion gains `substitutions`, `scoutsSubstituted`, `masterReportPath`. Manifest gains optional `"substitution": "off"` (default `auto`). After a **contention** failure the runner waits 1.5 s before fielding the replacement (configurable; tests use 0), because the lock is transient and an instant retry would just lose it again.

Product specifics: `runOne` became `runAttempt` (unchanged body) + `runLane` (the loop). `attempts` is still **one final attempt per lane**, so every existing consumer, outcome calculation and counter is unchanged. Replaced receivers are kept in `preservedAttempts`; decisions in `substitutions`. Both fields are **omitted entirely when no substitution occurred**, so ordinary Formations are byte-identical to before. `request.substitution: 'off'` is available.

Formation size invariant held: lane count comes from the Play (`scoutsRequested` is lanes, not receivers tried); the initial receiver's identity is not load-bearing.

## FAILURE CLASSIFICATION

| Class | Evidence | Substituted? |
|---|---|---|
| **availability** | executor state `BLOCKED`; process could not start; non-zero exit whose output matches the provider/auth/quota/route/model signature (`rate limit`, `429`, `quota`, `provider model not found`, `api key`, `unauthorized`, …) | **Yes** |
| **contention** | non-zero exit with `database is locked` / `SQLITE_BUSY` / `EBUSY` — the field failure | **Yes**, after a 1.5 s pause |
| **substantive** | receiver COMPLETE (a weak or unhelpful answer is still an answer, even one that *mentions* rate limits) | **Never** |
| **unknown** | any other non-zero exit; `INTERRUPTED` (human abort/timeout); `UNKNOWN` | **Never** |

Conservative by construction: only positive evidence substitutes. A human interrupt can never trigger a replacement. Classification is purely from process evidence — no LLM judgement of answer quality.

## DEPTH-CHART / ELIGIBILITY SOURCE

The **Combine scorecards** (`<Scout Intelligence>/Combine/Scorecards/*.json`), read fresh on every decision. Real data on this machine right now (`currentStatus`, from the files): `nemotron-3-super` READY, `nemotron-3-ultra` READY, `laguna-s-2.1` READY, **`north-mini-code` AUTH ISSUE** (last tryout 2026-09-19). So for the field manifest, `sideline-scout-balanced` and `sideline-scout-deep` are the live bench for Lane A.

- Yesterday's READY is not today's: SUB-3/SUB-8 flip a scorecard to RATE LIMITED and assert the receiver is passed over.
- **No scorecard = not eligible.** Readiness is never invented.
- The CLI runner **does not write scorecards** when a receiver fails. A `database is locked` must not teach the depth chart that a good model is bad. (The product path already suspends READY on `BLOCKED`, which is correct there because `BLOCKED` is a provider-side classification.)
- Ranking is still roster/scorecard-directory order, not quality. That is the seam future scorecards/capacity evidence plug into.

## REPORT HANDOFF REPAIR

`renderMasterReport` (`src/scout-master-report.ts`) writes **`FORMATION-RESULT.md`** to `<reports-root>/<playId>/` (and a copy in the working folder), for **every** terminal outcome — COMPLETE, PARTIAL, FAILED, INTERRUPTED. It contains:

- headline `FORMATION PARTIAL · 1 of 2 Scouts completed`, play id, Game, times, requested/completed/failed/blocked/interrupted/unknown/substitution counts, outcome;
- each lane: objective, final receiver + model, attempt count, report path;
- **Substitutions (injured list)**, including lanes that found no eligible substitute and why each candidate was skipped;
- **Failed / blocked attempts (preserved game film)** with class, reason, and stderr/stdout paths;
- **Combined findings** (honestly labelled a mechanical index, not a verdict; Scout evidence is reconnaissance, not authority), self-reported **contradictions** lifted from surviving reports, and an **Unfilled lanes (UNKNOWN territory)** section so a missing lane is never silently absent;
- the **full surviving receiver reports embedded** (60,000-char cap per report, with a truncation note and path);
- recommended next step; evidence and working folder paths.

Receiver reports stay as subordinate evidence and are referenced by path. A PARTIAL Formation with one useful receiver produces a complete, truthful parent (SUB-6 asserts the embedded report and the failed-film path).

The **final line is only the absolute path** ending `:1`. The launch SOP is unchanged (manifest → OPENCODE_DB → key → `npm run scout:play`); no new launcher, script, or setup step was added — the intelligence went *inside* the existing command. Exit codes unchanged (0 only for COMPLETE).

**Behaviour change to know about:** the raw completion JSON is no longer printed by default (it buried the path). It is still written to `SCOUT-PLAY-COMPLETE.json` and is available on stdout with the new `--json` flag.

## REMAINING UNKNOWNS

1. **Is the lock transient?** (above.) Unproven in the field.
2. **Root cause is concurrent starts on one `OPENCODE_DB`.** Substitution treats the symptom well and truthfully, but a launch stagger or a per-receiver DB would remove the cause. I did not touch the launcher, per the Play. This is the highest-value follow-up.
3. **CLI working state still defaults into the Game** (`<Game>/Scouts/<playId>`), contradicting the product's read-only-Scout rule since S36. Observed on disk for the field run; out of scope here.
4. **Bench quality is scorecard-order, not ranked.** A READY-but-unproven model can be fielded as a substitute. Ranking is the known future seam.
5. **Master-report synthesis is mechanical.** It indexes and embeds; it does not adjudicate. That is intentional, and stated inside the report.
6. **Dev Mode discovery of a CLI master report** in Incoming is not wired (different root).
7. **A CLI `COMPLETE` with empty stdout** is still reported COMPLETE (pre-existing; the product engine requires non-empty output).
8. The recurring `scout-continuation` intermittent above.
