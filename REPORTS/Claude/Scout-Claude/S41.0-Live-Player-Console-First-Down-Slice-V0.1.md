==================================================
PREFERENCE / STATE IMPLEMENTATION
==================================================

**Persistence — reused, not parallel.** The flag lives in the existing `preferences.json` beside `devMode`, via the
same `loadPreferences` / atomic `savePreferences` and the same `POST /api/preferences`. An older file with no key,
or a non-boolean value, loads as OFF. The status projection already returns the whole preferences object, so the
browser reads `status.preferences.livePlayerConsole` with no new endpoint.

**The AND-gate is browser-side.** `liveConsoleEnabled() = devMode && livePlayerConsole`, read from `lastStatus` at
render time. The server does NOT clear `livePlayerConsole` when Dev Mode goes OFF — the user's choice is preserved and
simply invisible, so re-enabling Dev Mode restores their prior console preference. Dev Mode remains purely a
visibility gate; it enables nothing by itself.

**Expansion state.** `consoleExpandedByInstance` is a `Set` of exact `instanceId`s (presentation-only, browser-local).
It is never keyed by a visible label such as "Claude 1". It survives roster rebuilds, and `stripKey` includes
`liveConsoleEnabled()` and the instance's expanded bit so the strip redraws only when one of those changes.

==================================================
UI BEHAVIOR IMPLEMENTED
==================================================

- **Settings:** a "Live Player Console" card directly under Dev Mode, `hidden` unless Dev Mode is ON. Copy is the
  specified one-liner. Checkbox reuses the Dev Mode checkbox styling and `data-live-action` guarding.
- **Player card:** when both gates are ON and the exact Player's strip is `working` or `starting`, an actions row under
  the timer row carries **Expand Console** / **Collapse Console** (`aria-expanded`, `aria-controls`). Idle, queued,
  finished, needs-you and failed states get no console.
- **Shell:** `role="region"` labelled per Player, containing a `role="log"` body and an actions row. The body shows
  "Waiting for live execution activity…" — no fabricated output.
- **Text size:** the body matches `#reportPreview` — 14.5px / 1.6 monospace, 16.5px / 1.65 under 620px. It is scrollable
  (`max-height: 42vh`) and grows the card vertically.
- **Copy controls:** **Copy All** and **Copy New** sit at the bottom of the shell, **disabled** with title "Nothing to
  copy yet". No copy handler and no cursor state exist, so nothing can be fabricated.
- **Collapse is presentation only.** Toggling touches no dispatch, routing, timer, provider session or Play; the test
  asserts zero server requests on expand/collapse and an unchanged canonical timer origin.

==================================================
UNKNOWNS
==================================================

- **Console visibility on Finished / Report ready.** I limited the console to `working` / `starting`, per "active
  timer/work strip". A user watching a Play end will see the console vanish when the strip becomes Finished. Whether
  the console should linger for the rich-Finished window is a product call for the transport slice.
- **Reconnect/refresh expansion.** Expanded state is in-memory only, so a page reload collapses every console.
  Judged acceptable for a dev shell; not persisted deliberately.
- **Real-device look.** See "Not verified".
