  the exact prior failure-boundary text ("Bounded Evidence Answer tryout did
  not complete successfully.") is preserved byte-for-byte via the caller now
  passing `"${route.name} tryout"`. This is the one seam-widening change the
  mission asked me to look for — genuinely required for reuse, not

No new OpenCode execution stack, no new report contract, no new read-only
agent, no new provider-failure parser, no new telemetry shape — all reused
directly from Scout Combine V0.3 and Scout Formation V0.2, exactly as
instructed.

FIELD PROOF
==================================================

**Regression found and fixed** (before the real Formation could even select
a candidate):

The very first attempt failed immediately with `No eligible Scout candidates
were discovered`. Root cause: the prior Play (S13.0, Scout Combine V0.3)
changed `run-scout-formation.mjs`'s default `durableReportRoot` to
`REPORTS/Scout Only/Formations` as a "safe, additive" filesystem-hygiene
change. It was not safe — `ANTIGRAVITY_CANDIDATE.eligible()` (and now the
new bridge) both read SIBLING evidence relative to `durableReportRoot`
(`Player Verification/<id>.json`, `Combine/Scorecards/*.json`). Pre-pending
`Formations` to the root the CALLER passes in silently moved those lookups
to a folder that doesn't exist, so AntiGravity — genuinely READY per its own
Player Verification file — reported ineligible, and every Combine scorecard
vanished from consideration too. The prior Play's own unit tests never
caught this because they always pass an explicit `durableReportRoot` AND an
explicit `candidates` array, never exercising the real CLI default against
a real Player Verification file — exactly the kind of gap only a real field
run exposes.

**Fix**: reverted `run-scout-formation.mjs`'s default back to the plain
`REPORTS/Scout Only` root (the same root Combine already uses correctly),
and moved the `Formations/<id>` bounded-namespace decision INSIDE
`runScoutFormation()` itself (`durablePath = path.join(durableReportRoot,
'Formations', formationId)`) — the identical pattern Combine already uses
for its own `Combine/Runs/<id>` and `Combine/Scorecards/` subpaths. Now the
one root serves both purposes correctly: sibling-evidence lookups stay
correct, and Formation's own evidence still lands in its bounded namespace.
Verified: `completion.durablePath` now equals
`<durableReportRoot>/Formations/<formationId>` (new assertion in the existing
persistence test), and the real field run below found both real receivers.

FAILURE SEMANTICS
==================================================

Unchanged from V0.2/V0.3: `ScoutAttemptTelemetry.completionState` (COMPLETE /
FAILED / BLOCKED / INTERRUPTED / UNKNOWN) stays the measured truth;
Formation-level `outcome` (COMPLETE/PARTIAL/BLOCKED/FAILED/UNKNOWN) is
derived mechanically from it, exactly as before. Nothing about the bridge
introduces a new failure category — a Combine-derived receiver fails exactly
the way `createCombineExecutor` already classifies failures (provider/auth/
quota -> BLOCKED, a genuine hard error -> FAILED, timeout/signal ->
INTERRUPTED), because it IS that same executor.
