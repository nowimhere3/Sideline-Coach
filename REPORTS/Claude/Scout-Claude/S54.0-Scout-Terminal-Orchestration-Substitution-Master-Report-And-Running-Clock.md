## Executive Result

**PASS** for the automated slice; **not field-proven** (needs one real two-lane run, below).

A receiver is a Player, not the Play. In `npm run scout:play` a lane whose Player cannot execute it now hands the **same lane and the byte-identical objective** to the next receiver that is eligible *right now*, with no human step. Every distinct eligible Player is tried at most once per lane, so the bound is the finite bench (plus a hard attempt ceiling), not a tuned cap. Every attempt is game film and says who actually played (agent, provider, exact model, reasoning effort or an honest UNKNOWN, timing, lineage). Every outcome compiles **one** `FORMATION-RESULT.md`. The terminal shows a running clock and lifecycle lines, then a compact summary whose final line is only the clickable path.

**The OpenCode DB question is resolved by evidence, not guessed:** the lock is a *cold-start migration race on a shared DB file*. Concurrent starts on one fresh shared DB failed **8 of 18**; one DB per start failed **0 of 18**. Each attempt now gets its own DB, so the stampede is **impossible by construction** rather than merely recoverable.

Invocation is unchanged: `npm run scout:play -- --manifest "<manifest>"`.

## Architecture Decision

Push the intelligence **down into the one existing runner**; add no launcher, roster, engine or step for Dad.

- `scout-substitution.ts` — the single classification + bounded-selection policy (shared by the CLI runner and the product Formation).
- `scout-receiver-identity.ts` (new) — Player provenance resolved at the moment an attempt takes the field.
- `scout-master-report.ts` — the one compiled parent; deterministic extraction, no LLM call.
- `scout-terminal.ts` (new) — running clock + event lines, driven by **structured runner events** (`onEvent`), never parsed text; every time source injected.
- `scout-play-runner.ts` — lane/attempt model, per-attempt DB isolation, continuation packet, events, clock-based elapsed.
- `run-scout-play.mjs` — wiring only.

The CLI and product Formation still differ deliberately (distinct lane objectives vs identical redundant looks) and still write to different roots.

## Failure Classification

| Class | Evidence | Substituted |
|---|---|---|
| availability | `BLOCKED`; could not start; rate limit / 429; quota; model/route unavailable; auth/entitlement; upstream 5xx (with HTTP/status context); transport (`ECONNRESET`, `ETIMEDOUT`, `fetch failed`…) | **Yes** — labelled `RATE LIMITED`, `QUOTA`, `MODEL UNAVAILABLE`, `AUTH ISSUE`, `PROVIDER UNAVAILABLE`, `TRANSPORT FAILURE`, `COULD NOT START` |
| contention | `database is locked`, `SQLITE_BUSY`, `EBUSY`, `Failed query` (migration race) | **Yes** (`LOCKED`) |
| execution | killed by a signal the human/runner did not request; Windows crash exit codes (≥ 0xC0000000); OOM/`FATAL ERROR`/panic text; **clean exit with no report** | **Yes** (`CRASHED`, `NO REPORT`) |
| substantive | valid completed report — even a weak one, even one that *mentions* rate limits | **Never** |
| human-abort | the human cancelled | **Never** |
| policy | content-policy / safety refusal | **Never** |
| unknown | anything else, incl. non-zero exit with unidentifiable output | **Never** — stays UNKNOWN |

UNKNOWN is improved mechanically only where evidence exists: an `UNKNOWN`-state exit carrying positive 429 evidence is now substitutable; with no evidence it stays UNKNOWN. Bare numbers (`line 500`) are deliberately **not** treated as HTTP statuses (tested). A clean exit with empty stdout is now `FAILED / NO REPORT`, closing S52's known hole. A signal not requested by the human is `FAILED` (abnormal), not `INTERRUPTED`; `INTERRUPTED` now means only "the human asked".

## Substitution Contract

Per lane, after an attempt that did not complete: classify → if substitutable, retire the receiver **for this whole Play** → select the next receiver, in depth-chart order, that is not already used on this lane, not fielded on any other lane, not injured earlier, and **eligible now** → run it in the **same lane** → repeat. Completed lanes are never restarted or cancelled. Every decision, including "no eligible substitute remained" and why each candidate was passed over, is recorded.

**The `2` cap:** removed. The rule is now *each distinct eligible Player at most once per lane*; the bound is the finite bench, `laneAttemptCeiling(bench) = bench + 1`. A hard **attempt** ceiling (`result.attempts.length >= ceiling`) backs it independently. No numeric cap remains because none is needed: a lane can never exceed one attempt per distinct receiver, and recursion does not exist.

*Defect found and fixed while proving this:* my first ceiling guard compared a `Set` of distinct receivers (max 4) to a ceiling of 5, so it could never fire. Mutation-testing the "never twice" rule made the loop spin forever. The guard now counts attempts, and the "never twice" rule is additionally enforced by the injured/claimed set (two independent guards).

## Depth Chart Contract

Unchanged in principle, strengthened in timing: the Combine scorecards are the only depth chart; eligibility is **asked again for every candidate at every substitution decision** (test: a receiver ready at decision 1 is unready at decision 2 and is passed over). No scorecard = readiness UNKNOWN = not eligible. The CLI runner does not write scorecards on failure (a database lock must not teach the chart that a good model is bad).

## OpenCode DB Contention Decision

**Decision: per-attempt DB isolation** (`OPENCODE_DB=<attempt folder>/opencode.db`, removed after the attempt). Status: **impossible by construction in the default mode; merely recoverable (substitution) with `--shared-db`.**

Evidence (installed OpenCode 1.18.31, run in this Play):
- `opencode db path` honours `OPENCODE_DB`.
- **Cold shared DB, 6 concurrent starts × 3 rounds:** 4, 3, 1 failed = **8/18**, all `Failed query: CREATE TABLE …` (concurrent first-time migration). **Isolated DBs, same shape: 0/18.**
- **Already-migrated shared DB** (WAL, `busy_timeout` = 5000 ms): 8 concurrent readers ×3 and 8 concurrent writers ×3 = **0 failures**, all 24 rows written. So the lock is a *startup migration* window, not steady-state contention — which explains why it hit exactly when two Scouts launched together, and why a substitute launched into an in-flight sibling was at risk.
- Cost: a cold isolated start ≈ 1.06–1.20 s vs 1.02 s warm (≈ +0.15 s).
- **Credentials:** `scout.db` has **0** `credential` rows and **0** `account` rows; runs authenticate from `OPENROUTER_API_KEY` (per the SOP). So an empty per-attempt DB loses nothing today.

Rejected: start-staggering (hides the race, adds latency, still a shared file) and lock coordination (reimplements SQLite). Tradeoffs to know: (1) if anyone ever logs a provider into the shared DB, isolation would drop it — a lost credential would surface as `AUTH ISSUE`, never silently, and `--shared-db` restores the old behaviour; (2) only the DB is isolated (the cache/data dirs are shared), because per-attempt cache would force provider-package reinstalls — I did not test concurrent first-time package installs.

**Limit of this evidence:** I could exercise OpenCode's DB layer (`session list`, `db`) but not a full `opencode run` (no provider key in this session; `run` fails identically everywhere without one). The reproduction is the same migration code path, not a live Scout run.

## Continuation / Same-Lane Contract

A substitute is the same lane, not a new Play: Play ID, lane ID, Game, report lineage and the objective are unchanged — the prompt contains `BOUNDED OBJECTIVE\n<objective>` byte-identically for every Player, `objectiveHash` is identical across attempts, and the saved `objective.txt` is never rewritten (all asserted). The substitute additionally receives a bounded, **factual** continuation packet: who went down, the failure label/reason, and — only when the failed receiver left ≥ 200 characters that are *not* an error message — that partial output, explicitly marked **UNVERIFIED**. No hidden reasoning is transferred; with no usable output it says so and starts from the objective. Scouts are read-only, so there are no partial file artifacts; stdout is the only artifact.

## Player Provenance Contract

Per attempt, resolved when it takes the field: agent alias, provider (from the model prefix), exact model, display name (the depth chart's when known), **reasoning effort**, role, lane, attempt number, objective hash, start/end/duration, result, failure class/label/reason, `substituteFor`/`replacedBy`, stdout/stderr/report paths, DB isolation mode. **Reasoning effort is read only from the agent definition if it declares one** (`reasoningEffort:` / `reasoning_effort:` / `effort:`); otherwise it renders `UNKNOWN - not exposed by provider (provider-managed)`. The four real agent definitions declare none, so today every real run will show that string — truthfully. The runner authors the identity (trusted); child reports stay byte-exact evidence. The prompt now *asks* receivers for the standard headings (RESULT, KEY DISCOVERIES, FACT, INFERENCE, UNKNOWN, CONTRADICTION, IMPORTANT FILES / PATHS) but the compiler tolerates their absence (missing = `UNKNOWN`).

## Master Report Contract

`FORMATION-RESULT.md` in `<reports-root>/<playId>/`, for COMPLETE, PARTIAL, FAILED and INTERRUPTED alike. Sections: **# FORMATION RESULT** (play, Game, started/finished, **TOTAL ELAPSED TIME**, requested/completed/failed lanes, total attempts, substitutions, outcome) · **PLAYERS WHO TOOK THE FIELD** (one table row per attempt with all provenance fields) · **SUBSTITUTION CHAIN** (`Lane A: North Mini → Nemotron Super → COMPLETE`, with the reason each was benched) · **DISCOVERIES BY PLAYER** (per surviving Player: lane, objective, key discoveries, FACT/INFERENCE/UNKNOWN/CONTRADICTION, important files, source path) · **COMBINED FORMATION FINDINGS** (attributed mechanical index, explicitly not a verdict) · **FAILED / BLOCKED ATTEMPTS** (film with paths) · **CONTRADICTIONS** (attributed, not adjudicated) · **UNKNOWN / UNFILLED TERRITORY** ("absence is not success") · **CHILD REPORTS** (paths + bounded 60,000-char embed). No LLM call; headings and bold-heading lines are recognised defensively and the full report is embedded when nothing structured is found.

## Running Clock UX

`[00:03:17] SCOUTING · 2 running · 1 complete of 3 · 1 substitution`. Starts at the runner's `formation-start` event (after validation and workspace creation), stops at the terminal outcome. **TTY:** redraws in place once a second; the line is erased before every event line and at stop, so it can never be glued to output. **Non-TTY:** no escape codes, no `\r`; one plain status line every 30 s (test: ten minutes → ≤ 25 whole-line writes). The view is **inert after `stop()`** (late timers/events are counted and dropped), the interval is cleared on every outcome, and `stop()` is idempotent and also runs in `finally`. Total elapsed and each attempt's elapsed come from the same injectable clock and are persisted in the report and `SCOUT-PLAY-COMPLETE.json` (`elapsedMs`). Tests use fake `now`/`setTimer`; nothing sleeps.

## Terminal Event UX

```
[00:00:00] [QUEUED] lane-a · Poolside: Laguna S 2.1 (free)
[00:00:00] [RUNNING] lane-a · Poolside: Laguna S 2.1 (free)
[00:01:42] [RATE LIMITED] lane-a · Poolside: Laguna S 2.1 (free) (elapsed 00:01:42)
[00:01:42] [SUBSTITUTE] lane-a · Poolside: Laguna S 2.1 (free) → NVIDIA: Nemotron 3 Super (free)
[00:01:42] [RUNNING] lane-a · NVIDIA: Nemotron 3 Super (free) (attempt 2)
```
Failure lines use the meaningful label (`RATE LIMITED`, `LOCKED`, `CRASHED`, …), not a generic `FAILED`. The live view writes to **stderr**; the handoff to **stdout**. Raw JSON appears only with `--json`.

## WAS / IS / WILL BE
