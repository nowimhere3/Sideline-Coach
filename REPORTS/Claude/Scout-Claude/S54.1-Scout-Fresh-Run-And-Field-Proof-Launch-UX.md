## RESULT

**PASS** (automated). S54 architecture untouched.

`npm run scout:play -- --manifest "<existing manifest>" --fresh` now reruns the same Play with no manifest editing, no timestamp invention, no workspace deletion and no BOM trouble. The runner derives a new unique playId, tells the human what it is, and runs the normal S54 path. Without `--fresh`, reusing an existing playId is still refused — now as a plain message rather than a stack trace.

## THE DEFECT

The S54 field-proof instruction told Dad to rerun the existing manifest; the runner correctly refused (`Play workspace already exists`) because that `playId` already owned evidence. Dad then hand-cloned JSON, and a PowerShell-written clone carried a UTF-8 BOM that `JSON.parse` rejected. My S54 report's field-proof section was wrong to assume the manifest was rerunnable as-is; that is the gap this fixes.

## IMPLEMENTATION

- **`--fresh`** → `runScoutPlay({ fresh: true })`. Derivation happens in the **runner**, so every future caller (CLI now; product later) gets the same semantics.
- **Identity:** `<base>-fresh-<Calgary yyyymmdd-hhmmss>`; `-2`, `-3`… if that exact id is taken; an earlier `-fresh-…` suffix is replaced rather than stacked; always a valid ≤ 80-char id. Uniqueness is checked against **both** the workspace and the durable evidence folder, so old game film can never be reused.
- **Announced:** `FRESH RUN: playId <derived> (a new run of <original>; earlier evidence is untouched)` on stderr before anything runs. `rerunOf` is recorded in `play.json`, `SCOUT-PLAY-COMPLETE.json` and the master report (`Rerun of: …`).
- **Everything else identical:** lanes, objectives (byte-exact), agents, Game and concurrency come from the manifest unchanged; per-attempt DB isolation, same-lane substitution, master `FORMATION-RESULT.md`, running clock and the final clickable path are the untouched S54 code.
- **The manifest is only ever read.** `parseScoutManifest` tolerates a UTF-8 BOM (defensive input handling, not the rerun mechanism) and names the file on a genuine JSON error.
- **Default stays safe:** no `--fresh` → refuse. The refusal now says `Nothing was overwritten. Add --fresh to run this Play again under a new id.`
- **CLI messages:** expected refusals (existing playId, unreadable manifest) print as one plain line; stacks only with `SCOUT_DEBUG=1`.
- No second launcher, roster, manifest format or setup step.
