# EXECUTIVE VERDICT

S57.56 is right about the main point. The downstream router honours `RouteConstraints`. Coach's intent is lost before those constraints are built. I checked the source directly and found the problem is structural, not four separate regex bugs:

> **Sideline has two competing recognisers with different rules. The one that runs depends on whether a field-shaped line happens to appear anywhere in the Play.**

- `resolveSmartRouteConstraints` (`smart-route-resolver.ts:502`) calls `hasStructuredFields`. That function scans **every line of the whole prompt**, fenced code included (`:134-148`). If it finds any `agent/model/effort/reasoning/thinking:` label, the Play goes to the strict `recognizeRouteConstraints`. Otherwise it goes to the lenient `trySmartNaturalRoute`.
- The two recognisers disagree on almost everything. They differ on typo tolerance, model-first shorthand, static versus live vocabulary, and on silently picking defaults for `Gemini`/`GPT`. Each one also loses intent in its own way. The strict path drops model and effort when a Player field exists (`route-constraints.ts:643`). The lenient path drops the whole route when a single carrier word is present (`smart-route-resolver.ts:355`).

The fix is **one recognition front door**. It works in three steps:

1. Collect every *route statement* in a bounded opening region: structured fields, the shorthand line, carrier sentences, the control title and the Scout directive.
2. Resolve each statement against the **live catalogue tuple space** (instance × model × effort).
3. **Intersect** all the statements. An empty intersection is a contradiction and stops. More than one surviving option on a dimension Coach named is an ambiguity, which stops with bounded choices. Exactly one survivor is truth. A dimension nobody named is absent, and only those are filled by AUTO.

The output keeps the existing `RouteConstraints` shape. `unresolved[]` gains two optional fields, `reason` and `options`. Everything downstream stays as it is: the `unresolvedRouteError` stop, `constrainedSeats` filtering, `classifyTask`, provider policies and the shared staged/dispatch `computeRoute`. There is one small exception, a defensive guard in `computeAutoRoute` and `constrainedSelection` (Slice 2).

The design deliberately revises a few existing tests. Those tests encoded "structured silently outranks natural" and "only line 1 counts", and the Head Coach's law now forbids both. They are listed in **REQUIRED REGRESSION MATRIX → Intentional contract revisions** so Codex does not "fix" them back.

# ARCHITECTURAL LAW

1. **Explicit resolved intent is final.** A dimension Coach named that resolves to exactly one live value cannot be changed by task classification, provider preference, context affinity or policy defaults.
2. **No source silently outranks another.** Structured fields, shorthand, carriers, titles and directives are all statements by the same Coach. They either agree, which merges them, or they disagree, which stops. *Agreement* is defined by live-catalogue compatibility, not by string equality.
3. **Unknown is acceptable; guessing is not.** If a named dimension has more than one live candidate, Sideline asks. If it has none, Sideline stops. Nothing is "picked as a favourite."
4. **Absent dimensions are AUTO's, and only those.** AUTO still fills them inside the space the explicit dimensions allow. For example, `Medium` alone restricts AUTO to models that support Medium.
5. **Lexical knowledge is durable; capability knowledge is live.** The parser may know words (`med`, `extra high`, `send this to`, `five point six`). It may never hold a model table. Which models, versions and efforts exist, and who owns them, always comes from `PlayerRoutingCapability[]`.
6. **One computation.** Recognition runs once inside `computeRoute`. Preview and dispatch keep sharing it, and nothing is recognised in the UI.

# CANONICAL RECOGNITION PIPELINE

```text
prompt
  │
  ├─ R0  REGION         structured envelope = first 15 unfenced lines (unchanged, S56.0)
  │                     natural window      = first 10 MEANINGFUL lines (new)
  │
  ├─ R1  LEXICAL        presentation strip · case fold · punctuation→space
  │      (durable)      effort lexicon · carrier vocabulary · spoken versions (catalogue-gated)
  │                     typo tolerance (natural line 1 only)
  │
  ├─ R2  CLASSIFY       each region line → structured-field | scout-directive | control-title
  │                     | carrier | shorthand | choice | mention | (ignored)
  │
  ├─ R3  RESOLVE        each route statement → admissible set A_s ⊆ T (live tuple space)
  │      (live)         plus the dimensions it NAMED
  │
  ├─ R4  MERGE          A = ∩ A_s
  │                     ∅ across statements   → contradictory   (stop, options = statements)
  │                     ∅ within a statement  → unknown / unsupported (stop)
  │                     named dim with >1 value → ambiguous      (stop, options ≤ 4)
  │                     named dim with 1 value  → resolved      (final)
  │                     unnamed dim             → absent         (AUTO fills inside A)
  │
  └─ R5  EMIT           RouteConstraints (existing shape; unresolved[] gains reason/options)
            │
            ▼  (unchanged)
         unresolvedRouteError stop → constrainedSeats → classifyTask → policy fills ABSENT dims
```

**The tuple space T** is built on every call from the live `PlayerRoutingCapability[]` passed to recognition. That is the same `everyCandidate` that `computeContextAwareRoute` already passes. Each row is `(playerType, instanceId, modelId, modelDisplayName, effort)` for every controlled reasoning seat × model × supported effort. A product-supported Player type with no live seat contributes a placeholder row `(playerType, *, ?, ?, ?)`. That makes `Codex Medium` with Codex off field resolve to Player = Codex, which then hits the existing truthful "Codex is currently unavailable … Coach did not choose another Player" stop. It does not fall back to AUTO. T is small (tens of rows), so set operations are trivial.

**Single front door:** `resolveSmartRouteConstraints` stays as the exported name, because `routing-policy.ts:21/488/726` imports it. Its body becomes a direct delegation to `recognizeRouteConstraints`. Several things are retired from authority: `hasStructuredFields`, `trySmartNaturalRoute`, `MODEL_FAMILY_REGISTRY` and `REASONING_ALIASES`. None is imported outside `smart-route-resolver.ts`; I checked with grep across `src/` and `test/`. `PLAYER_REGISTRY` survives only as the durable list of **product-supported Player types and their names**. That is adapter truth, not model truth. `editDistance` and `matchAliasWithTypo` survive as utilities.

# FIRST-10-LINES CONTRACT

**Decision: zone extraction across a 10-line window (S57.56 Option A), with position-graded eligibility.** I rejected Option B because `Sonnet Medium` on line 2 under a heading is the Head Coach's primary example. I rejected Option C (density scoring) because it is not deterministic enough to explain to Coach.

**Meaningful line.** A line counts only if, after trimming, it is non-empty and is none of the following:
- inside a ``` fence (fence lines themselves are not counted either);
- a block quote (`>`);
- a horizontal rule (`---`, `***`, `___`);
- an HTML comment;
- a Markdown table separator.

Up to 10 meaningful lines form the **natural window**. Line 11 and beyond is never read for natural routing.

**The structured envelope stays at 15 unfenced lines** (`routeLines`, `route-constraints.ts:155-162`). Labelled fields identify themselves, carry little hijack risk, and S56.2-1b depends on that depth. Only *natural* recognition is bounded at 10. The legacy natural `Use X` imperative scan is **narrowed from 15 to the same 10-line window**, so all natural recognition shares one boundary.

**Eligibility by position:**

| Form | Line 1 (first meaningful) | Lines 2–10 |
|---|---|---|
| Structured field (`AGENT:` …) | ✔ (15-line envelope) | ✔ (15-line envelope) |
| Scout directive | ✔ (unchanged S56.1) | ✘ |
| Control title (`ROUTE — Title`) | ✔ | ✘ (a title is by definition at the top) |
| Carrier sentence (`Send this to …`) | ✔ any dimension count | ✔ any dimension count, at a line start or a clause start after `. ! ?` |
| Bare shorthand, single dimension (`Opus`, `Medium`) | ✔ (today's behaviour) | ✘ (too easily a sub-heading) |
| Bare shorthand, ≥2 dimensions (`Sonnet Medium`, `Codex High`, `Claude Sonnet`) | ✔ | ✔ |
| Bare Player only (`Claude`) | ✘ (unchanged S56.3-10) | ✘ |
| Heading marker `#…` / emphasis `** __ * _` | presentation, stripped | presentation, stripped |
| List item (`- `, `1.`) | presentation, stripped (today's behaviour) | **✘ never a route**: lists below line 1 are examples |
| Whole line wrapped in backticks or quotes | stripped (today's behaviour) | **✘ never a route**: cited material |
| Table row (`| … |`) | ✘ | ✘ |

When there are several eligible natural statements in the window, all of them are collected. They merge (R4) instead of first-wins, so two agreeing statements are harmless and two disagreeing statements stop.

# ROUTING GRAMMAR

All matching happens on R1-normalised tokens: lower-case, with `normalizeRouteText` turning punctuation into spaces. That means `GPT-5.6 Sol` becomes `gpt 5 6 sol`, and so do `gpt 5.6 sol`, `GPT 5 6 SOL` and the spoken form.

```ebnf
route          = player_part [ link ] [ model_part ] [ link ] [ effort_part ]
               | model_part [ link ] [ effort_part ]
               | effort_part ;
player_part    = PLAYER_ALIAS [ INSTANCE_NUMBER ] ;        (* roster/provider/adapter identity *)
model_part     = MODEL_WORDS ;                             (* 1–5 tokens, resolved in R3 *)
effort_part    = EFFORT_WORDS [ EFFORT_FILLER ] ;
link           = "on" | "with" | "at" | "using" ;
EFFORT_FILLER  = "effort" | "reasoning" | "thinking" | "level" | "mode" ;
(* whole route ≤ 8 tokens, the existing MAX_ROUTE_CALL_TOKENS *)

shorthand_line = route ;                                    (* every token consumed *)

carrier_line   = [ courtesy_pre ] carrier_head route [ courtesy_post ] [ boundary clause_tail ] ;
courtesy_pre   = "please" | "kindly" | "can you" | "could you" | "then" | "for" <≤120 chars> "," ;
carrier_head   = ( "send" | "route" | "give" | "dispatch" | "assign" | "hand" | "pass" ) [ object ] [ "off" ] "to"
               | "run" [ object ] ( "on" | "with" | "using" | "through" | "at" )
               | "use"
               | ( "i would like" | "i'd like" | "id like" | "i want" ) object
                   ( "to go to" | "to run on" | "to be sent to" | "to be routed to" | "to be handled by" | "on" | "to" ) ;
object         = "this" | "it" | "this play" | "the play" | "this one" ;
courtesy_post  = "please" | "thanks" | "thank you" | "for this" | "for this play" | "for this one" ;
boundary       = "to" | "for" | "so" | "because" | "," | ":" | "—" | " - "
               | "and"   (* ONLY when the next token is NOT route vocabulary *) ;

choice_line    = [ courtesy_pre carrier_head ] route ( CHOICE route )+ ;  (* nothing else on the line *)
CHOICE         = "or" | "and" | "either" | "both" | "/" | "|" | "&" | "+" ;
COMPARISON     = "vs" | "versus" | "compare" | "compared" | "than" ;     (* → mention, never route *)
```

**Line classification (R2), first match wins:**

1. Fenced, quoted or not meaningful → ignored.
2. `label: value` whose label resolves through `resolveFieldLabel` → **structured field** (unchanged S56.0/S56.2 semantics). A colon line whose label is *not* a route label (`Priority: High`, `Example: Sonnet Medium`, `Date: …`) is a **foreign field** and is never a natural route.
3. Line 1 only: Scout directive (unchanged), then control title.
4. Any negation token inside the **route span** → never a positive route. The existing `don't|do not|never use X` exclusion scan (`route-constraints.ts:686-693`) stays as it is and moves to the 10-line window.
5. `choice_line` → **choice statement** (R4 turns it into a contradiction).
6. `carrier_line` → **carrier statement**.
7. `shorthand_line` (subject to the position rules) → **shorthand statement**.
8. Anything else → **mention**, which is ordinary Play content.

**Scoping rule for `isChoiceOrNegation`.** Today it runs over the *whole line*, and its `CONNECTIVE` set includes `then`/`also` (`route-normalization.ts:69`). A line such as `Send this to Sonnet Medium, no rush` or `… then report back` would therefore be killed by its tail. From now on, choice and negation checks apply to the **carrier head plus route span only**, never to the clause tail after a boundary. Structured values keep the whole-value check (unchanged S56.2).

**Legacy advisory imperative (kept).** If a carrier's remainder is *not* a complete route, recognition falls back to today's prefix-Player match (`aliasesAtStart`) plus the `on MODEL` / `, EFFORT` extraction (`route-constraints.ts:657-681`). An unresolvable name there stays advisory and is never a stop. This keeps S56.2-14 (`Use Claude Code on Sonnet for this.` → Claude) and `Use Claude to fix the bug` working.

# MODEL-FIRST SHORTHAND

`parseRouteCall` is generalised. A leading Player becomes **optional**. The route can now start with a Player, a model or an effort. `MODEL_WORDS` are resolved by a live-catalogue resolver that is scoped to the Player if one was named, and otherwise to every live reasoning seat:

1. **Exact alias.** Tokens equal a model's id or display-name tokens (`gpt 5 6 sol`, `sonnet`, `fable`).
2. **Family + version.** A digit-free family followed by a version number (existing `matchModelWords` rule, `route-constraints.ts:380-384`).
3. **Contiguous run.** The tokens occur as one contiguous run in a model's alias tokens (`sol`, `5 6 sol`, `6 1`, `flash`, `astra`). This is the existing rule, now applied across Players when no Player is named.
4. **Brand-token rule (new, dynamic).** Consider a *single* token that appears in **every** model of exactly one Player type that has two or more live models, and in no model of any other Player. It names **that Player only**; the model stays absent and AUTO fills it. Today that covers `gpt` (meaning Codex) and `gemini` (meaning AntiGravity). This keeps the accepted `Gemini` / `Gemini Medium` behaviour without a static table. If AntiGravity's catalogue ever lists a non-Gemini model, `gemini` stops being a brand and becomes a family, and Sideline starts asking instead of guessing. Rules 1–3 are tried first, so a single-model Player's only model still resolves as a model.
5. **Result set S** = the distinct `(playerType, modelId)` pairs that match:
   - If the statement also names an effort, narrow S to models that support it, as long as the narrowed set is non-empty. Narrowing by Coach's own words is not guessing: `Gemini 3.x Flash` × `Medium` leaves only the models that can do Medium.
   - |S| = 1 → model resolved. The Player is inferred if it was not named.
   - |S| > 1 → **ambiguous model**. If the pairs span more than one Player type, the Player is ambiguous too, for example if AntiGravity's catalogue ever offers a Sonnet.
   - |S| = 0 → see Unknown model below.

**Unknown model (Head Coach's `Luna Med` rule).** Only route-*shaped* lines are judged, so a typo'd prose word never becomes a stop:
- **Player + unknown + optional effort** anywhere in the window (`Codex Luna High`) → Player resolved, **unresolved model** `Luna`.
- **Known family token + unmatched version** (`5.9 Sol Medium`, `Sonnet 9`) → **unresolved model**.
- **Line 1 or carrier: `X EFFORT`**, where X is 1–2 tokens and no catalogue token (`Luna Med`, `Send this to Luna Medium`) → **unresolved model** `Luna`. Message: *"No Player on your team offers a model called 'Luna'."*
  - Guard: X must not be a durable *label noun* (`priority`, `severity`, `risk`, `impact`, `urgency`, `confidence`, `complexity`, `status`, `importance`, `level`). This is lexical, not capability knowledge, so a bug-report Play opening `Priority High` stays ordinary.

**Effort vocabulary.** Lexical aliases plus live ids:

| Coach writes (any case) | Lexical canonical |
|---|---|
| `low` | `low` |
| `med`, `medium` | `medium` |
| `high` | `high` |
| `xhigh`, `x-high`, `x high`, `extra high` | `xhigh` |
| `max`, `maximum` | `max` |
| `ultra` | `ultra` |
| *any exact effort id in the live catalogue* (e.g. a future `minimal`) | itself |

- **There is no `ultra ↔ max` cross-mapping.** They are different live ids. The routing film shows both.
- Validation is always *the resolved model's* `supportedEfforts`. If the effort is unsupported → **unresolved effort**, whose message lists what that model does support.
- No `hi`, which is too easily a greeting.

**Typo tolerance.** Damerau distance 1, unique match, **only on natural line 1**, which preserves today's production behaviour (`Sonnett med`, `Gemeni med`):
- tokens of length ≥ 5 only, matched against live alias tokens of length ≥ 5;
- never effort words, never digit tokens, never structured values (S56.2 unchanged), never lines 2–10.

Lines 2–10 are where example and prose text lives, so they get exact matching only.

# STRUCTURED + NATURAL MERGE CONTRACT

Every statement s (structured envelope, shorthand, carrier, control title, Scout directive, choice) produces an admissible set `A_s ⊆ T` and records the dimensions it **named**. The structured envelope is *one* statement built from its `AGENT`, `MODEL` and `REASONING` fields. Within it, the S56.2 rule still holds: MODEL is resolved inside AGENT's catalogue.

**Merge = intersection.** `A = ∩ A_s`. Then, per dimension:

| Statement X | Statement Y | Result |
|---|---|---|
| absent | absent | absent → AUTO fills |
| resolved v | absent | resolved v |
| resolved v | resolved v | resolved v |
| Player `codex` | instance `Codex 2` | instance Codex 2 (an instance refines its type) |
| model `sonnet` (Player inferred Claude) | `AGENT: Claude` | Claude · Sonnet ✔ |
| model `sonnet` (inferred Claude) | `AGENT: Codex` | A = ∅ → **contradictory** |
| model ambiguous {5.6 Sol, 6.1 Sol} | `MODEL: GPT-6.1 Sol` | resolved 6.1 Sol (another explicit statement settles it) |
| effort `medium` | `REASONING: High` | ∅ → **contradictory** |
| any | unresolved (unknown / unsupported) | **unresolved** stop (S56.0 unchanged) |

**Applied to the Head Coach's examples:**

| Play | Statements | A | Staged |
|---|---|---|---|
| `Codex 5.6 Sol Medium` … `AGENT: Codex` | shorthand {codex, 5.6 Sol, medium}; structured {codex} | one row | **Codex · GPT-5.6 Sol · Medium** |
| `Sonnet Medium` … `AGENT: Claude` | shorthand {sonnet→claude, medium}; structured {claude} | one row | **Claude · Sonnet · Medium** |
| `Sonnet Medium` … `AGENT: Codex` | {claude…} ∩ {codex…} | ∅ | **STOP: contradictory**. Options: ① Claude · Sonnet · Medium (route line) ② Codex (AGENT field) |

Precedence by source type is **abolished**. Structured fields were authoritative because they were *explicit*. A model-first shorthand line is equally explicit, so the two now have equal standing, and disagreement goes to Coach.

# AMBIGUITY CONTRACT

**Representation decision: extend the existing `unresolved[]` items, with no new top-level shape.** Every stop path already runs through `unresolvedRouteError` before inference (`routing-policy.ts:468-490`, `:726-731`). Reusing that seam means no new branch can leak into AUTO.

```ts
// capability-types.ts — RouteConstraints.unresolved item (additive, optional fields)
readonly unresolved?: readonly {
  readonly dimension: 'player' | 'model' | 'effort';
  readonly rawText: string;
  readonly reason?: 'unknown' | 'unsupported' | 'ambiguous' | 'contradictory';   // absent ≡ 'unknown' (today)
  readonly options?: readonly RouteOption[];                                      // only for ambiguous / contradictory
}[];

export interface RouteOption {
  readonly playerType: string;
  readonly playerInstanceId?: string;
  readonly model?: string;
  readonly modelDisplayName?: string;
  readonly effort?: string;
  readonly label: string;      // "Codex · GPT-5.6 Sol · Medium" — unspecified dims omitted, never invented
  readonly source?: string;    // contradiction only: "route line 1", "AGENT field"
}
```

**Rules:**
- **Options** are the distinct projections of A onto the ambiguous dimension, combined with the *other explicitly named* dimensions. Dimensions Coach never named are left out of the label, because AUTO fills them after the choice.
- They are ordered by live catalogue order. That is deterministic, not a preference.
- There are **at most 4 options**. With more than 4 there are no options, and the message asks Coach to name the version.
- **Message**, rendered by `unresolvedRouteError`:
  > Sideline is unsure what route you intended. Did you mean:
  > 1. Codex · GPT-5.6 Sol · Medium
  > 2. Codex · GPT-6.1 Sol · Medium
- **Coach chooses, and the Play continues: the clarification seam (Slice 6).** It follows the existing `routeChoice` plumbing exactly (UI → `/api/games/preview` → `/api/plays/dispatch` → `computeRoute(…, extra)`).
  - A new `extra.routeClarification = { fingerprint, option }` is passed alongside `routeChoice`.
  - Recognition runs again and recomputes the same question. If the fingerprint matches, the chosen option's tuple replaces the conflicting or ambiguous statements as one resolved statement. The fingerprint is a stable hash of the dimension, the raw text and the option tuples.
  - If it does not match, because the catalogue or the prompt changed in the meantime, the route stops with *"The route question changed — choose again."*
  - **The Play text is never rewritten.** Preview and dispatch receive identical inputs, so staged equals dispatch.
- Until Slice 6 lands, the stop message itself lists the options. That is already truthful, and Coach can edit the Play or use MANUAL.

# CONTRADICTION CONTRACT

Contradiction is **explicit intent that cannot be satisfied as written**. It is never treated as absence, so it never falls through to AUTO.

| Source | Example | Representation |
|---|---|---|

# SPEECH-TO-TEXT NORMALIZATION

**Key simplification found in source:** `normalizeRouteText` already splits `5.6` into the tokens `5 6` (`route-normalization.ts:55-57`). So the spoken forms `five point six`, `five dot six` and `five six` need only **word→digit conversion plus dropping `point`/`dot` between numbers**. After that they are token-identical to typed `5.6`, and no other component has to change.

**Rule (evaluated and tightened from the prompt's proposal):**

1. The rule applies only inside a line R2 is already parsing as a candidate route (line 1 / carrier / ≥2-dimension shorthand), and inside structured `MODEL:` values. It never applies to prose.
2. Number words `zero`…`twenty` become digits. A run of number or digit tokens, optionally joined by `point` or `dot`, becomes one digit run. Examples: `five point six` → `5 6`; `5 point 6` → `5 6`; `six one` → `6 1`; `three point eight` → `3 8`.
3. **Catalogue gate.** The conversion is kept only if the resulting run equals the **complete maximal digit run** of at least one live model alias. Today those runs are `5 6`, `6 1`, `6`, `3 8` and `3 1`. Otherwise the words stay as they were, and the line simply fails as prose.
   - A sub-run never qualifies. `one` alone does not become `1` just because `6 1` exists.
   - So `Codex one` is never turned into an instance or a version.
4. There is no general English number parser, no ordinals and no `oh` → 0.

This is the improvement on "convert only versions present in the catalogue": the gate is the **whole** version run, which blocks partial and instance-number collisions.

# FINAL VERDICT

The defect is a split front door. Two recognisers with different rules are selected by a whole-prompt heuristic, and a sequencing bug lets one statement erase another. The architecture replaces that with one deterministic pipeline:

- a bounded region with position-graded eligibility;
- a closed grammar for route, carrier and choice lines;
- resolution against live-catalogue tuples;
- intersection-based merging that turns disagreement into a stop and multiplicity into bounded choices.

It reuses `RouteConstraints`, `unresolved`, `constrainedSeats` and the shared `computeRoute`. It adds no LLM, no model table and no new routing mode. Every decision the Play reserved for the Architect is made, the source evidence is sufficient, and the slices are bounded and independently green.
