## What was built

### 1. Pure evaluator: `src/routing-intel/calibration.ts` (new)

`CALIBRATION_GATE` (frozen):

| Constant | Value |
|---|---|
| `minResolved` | 30 |
| `bins` | 3 |
| `supportedBinMin` | 5 (= R7's `SHADOW_MIN_N.calibrationBin`; a test pins this) |
| `tolerance` | 0.10 |
| `toleranceEpsilon` | 1e-9 |
| `brierEpsilon` | 1e-12 |
| `weekMs` | 7 days |
| weekly instant | Monday 00:00 UTC |

- **`calibrationSamples(events, pack, at)`**
  - Reads only Film events at or before the instant, and projects resolutions at that instant (R5 `buildAttributedFilmIndex`).
  - Keeps chosen-route Plays whose first pass resolved (`clean` → 1, `player-defect` → 0).
  - p_i comes from `frozenChosenFirstPass`: the value R6 froze in the digest for the chosen target. It is never recomputed.
  - Player role only.
  - A resolved Play with no frozen prediction is counted as `withoutPrediction` and excluded from N.
- **`evaluateTaskClass`**
  - G1: N ≥ 30.
  - G2: `BS_base − BS_model > 1e-12`, with base rate ȳ(1−ȳ) in-sample. An exact tie fails.
  - G3: `b = min(2, ⌊3p⌋)`. A bin with n ≥ 5 is supported and must satisfy `|ȳ_b − p̄_b| ≤ 0.10 + 1e-9`. A sparse bin gets `passes: null`.
  - There is **no** minimum count of supported bins and **no** sparse veto.
  - `supportedBins` is filled only when the class graduates. The sums use Film order over unrounded values.
- **`evaluateCalibration(events, pack, instant)`** evaluates all four task classes.
- **`buildCalibrationReport(events, pack, now)`** returns the current weekly instant plus the one before it, so each class gets a status:

| Status | Meaning |
|---|---|
| `graduated` | passes all gates at the current instant |
| `un-graduated` | passed last week, fails now |
| `insufficient-evidence` | N < 30 |
| `not-graduated` | N ≥ 30 but a gate fails |

- **`calibratedFirstPassFor` / `withCalibration`** (Model A): the primary's own `scores.firstPass.mean`, unrounded. It is present only when all of these hold:
  - the Play's task class is graduated at the current instant
  - role is Player
  - the kind is `send`/`queue`/`handoff`
  - the value's bin is supported

  Otherwise the recommendation object is returned unchanged.

### 2. Derived weekly snapshot: `daemon.ts`

- `calibrationEvaluation()` evaluates at `calibrationWeekStart(now)`. It is cached by week and Film length, and is re-derived whenever the week turns, the Film grows, or a Coach attribution correction clears it.
- The cache is never persisted or authoritative. The Film remains the only truth, and deleting the cache changes nothing.
- The shadow recommendation seam now ends with `withCalibration(recommendation, …)`. It runs after ranking and only ever adds a field.

### 3. Contract: `recommend.ts`

- `strength.calibratedFirstPass?: number` has been added to `RoutingRecommendation`, per S57.1 §13.
- `recommendationDigest` now lists `strength` fields explicitly (`recommendation`, `evidence`), so the Film digest stays byte-identical. The exposed percent is not a Film fact.
- Ranking, ordering, `ROUTING_WEIGHTS`, belief and the rec `id` are unchanged.

### 4. Dad presentation gate: `dad-advisory.ts`

- `dadPercent(x) = min(99, max(1, round(100x)))`. This is the only rounding, and it happens at presentation.
- `dadCalibratedPercent(rec)` returns a percent only when `calibratedFirstPass` is present **and** the primary's resource evidence is not UNKNOWN (no `RESOURCE_UNKNOWN` reason and no window with price `unknown`), per §18.2 and §21.
- The line reads `Suggest Codex · 91%`, otherwise `Suggest Codex · Strong pick`.
- This view is only reached while R8's stage is open, and R8 stays dormant, so Dad sees no change today.

### 5. Dev view: `dev-views.ts` and `index.html`

- `RoutingIntelligenceView.calibration` is a `CalibrationReport` placed beside, not replacing, R7's §19.4 `shadow.graduation` block. That block still reads `shadow` / 50 Plays / `not-granted`.
- R7's private `predictedFirstPass` was replaced by the shared `frozenChosenFirstPass`. Its behavior is identical, and the R7 tests pass unchanged.
- The Dev panel (Routing Intelligence, Dev Mode only) adds "Calibration graduation · per task class". For each class it shows:
  - status and failures
  - n / required and the count without a prediction
  - model Brier vs base-rate Brier
  - each bin's n, mean predicted → observed, and ✓ / ✗ / sparse
  - the ranges where a percent may be shown, or "words only"
- Numbers are formatted there only.

### 6. Reversible un-graduation

- Each weekly instant re-evaluates from the Film.
- If a class that passed last week fails now, it shows `un-graduated`, its `supportedBins` becomes `[]`, and `withCalibration` stops adding the field. Dad goes back to words.
- There is no hysteresis and no stored flag.

## Notes for Coach

1. **Graduation can lag by up to a week.** A class that reaches 30 on Tuesday is first evaluated the following Monday (00:00 UTC). This is S57.1's "recomputed weekly," and it keeps the verdict deterministic.
2. **The week boundary is Monday 00:00 UTC** (Sunday evening in Calgary). The Dev panel shows both the last and the next evaluation in local time.
3. **A Dad percent is not visible anywhere yet.** R10 sets the field and the presentation gate, but only the dormant R8 chip renders Dad advisories. This is intended.
4. **Carried from S57.27 (breadcrumb):** p_i carries engine, weights and prior-pack versions. V1 freezes them. If a version ever changes, decide then whether the gate pools across versions or restarts per version.
