## 4. Why new UI and old AUTO behaviour coexisted

Of the candidate causes in the brief:
- **A — stale detached daemon: proven.**
- **C — Extension Development Hosts restarted, daemon survived: proven.**
- **D — static UI from current disk, routes from a stale backend: proven.**
- **B / F — no.** `out/` was current; the process simply had not reloaded it.
- **E — no.** Multiple copies exist on disk (diagnostic A5), but the live daemon and both Stadiums load `C:\Users\dmcal\Documents\GitHub\SidelineCoach\out`.
- **G — no.** No live code path contains the old string.
- **H — no.** The browser renders `routing.autoError` fresh from `/api/status` on every refresh.
- **I — no.** The Q2.9B change had landed in source and in `out/`.

The mechanism:

```text
Dev: Launch BOTH Game Hosts
  → new extension hosts activate → startServer() → ensureControlPlaneRunning()
  → discovery record exists, pid 21272 alive, /api/health ok → REUSE
  → nothing ever compares the daemon's build with out/
daemon (11:09 code in memory)
  → GET /     → fs.readFileSync(src/public/index.html)   → Q2.9B page
  → /api/status → old computeAutoRoute                   → old warning
```

**This also explains Q2.9B's "Unknown instance".** The 11:09 daemon had no `verb === 'field'` route. `POST /api/players/instance/:id/field` fell through to the type-level `/api/players/:id/field` route, which treats `instance/<id>` as a Player type. The source repair was real, but that daemon could never run it.

## 7. AUTO single-Player contract (amendment, implemented)

> **AUTO chooses WHO. Transport decides HOW.**

Audit of `AUTO candidate === Controlled candidate` assumptions:

| Location | Assumption | Q2.9C outcome |

| `server.ts` (in-extension, compatibility) AUTO | resolves transport after the decision | no change needed; the legacy branch sends terminal text |

## 8. Manual terminal transport truth

MANUAL means *the human chooses the Player*. It does **not** mean *terminal Players live in MANUAL and Controlled Players in AUTO*. Both modes reach the same transport-aware delivery:

```text
browser → POST /api/dispatch { playerInstanceId, routingMode }
  → Control Plane router → dispatch.request
  → Stadium executeDispatch → PlayerRoster.resolve(instanceId)
       live · controlled → PlayerControlHost.deliver (semantic, model/effort honoured)
       live · legacy     → sendTerminalText(prompt) → dispatch.accepted
       pending           → "That Player is reconnecting — try again in a moment."
```

- Proven by Q2.9B-1 (Stadium transport resolution) and by new Q2.9C-7 (the live router emits a real `dispatch.request` for the only terminal Player, with no model or effort).
- Q2.9B-1 remains green.

Physical arrival in Claude's terminal is the one irreducible human check (§15).
