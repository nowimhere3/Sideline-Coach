## THE DEFECT

Three things made Terminal evidence vanish on the machine's schedule rather than Dad's:

1. **Fast success** was shown only for the 30 s rich `Finished` window. After that the server projected `idle` for a report-less Play (2 min grace), and the console pin only attached to a console Dad had already opened.
2. **Failure and unknown outcomes never rendered.** `stripCopy` returns `null` for non-Scout `couldnt-finish` and `unknown`. That is deliberate, because Terminal outcomes are not Player health. It also meant the evidence was invisible.
3. **Copy released the console.** A successful Copy after completion deleted the expand and pin state, so Copy doubled as dismissal.

## WHAT CHANGED

All in `src/public/index.html`. This follows the S53.0 "Terminal Retention Architecture" design.

**One bounded record per Terminal Player** (`terminalEvidence`). It holds `{ instanceId, gameId, playRef, outcome, finishedAt, durationMs, summary, detail, dismissed }`. It is created on first sighting of a `direct-shell` view that actually ran (`finished`, `couldnt-finish` or `unknown`, with finite `finishedAt` and `durationMs`). `not-sent` refusals have no duration, so they create nothing. Output stays in the existing bounded `consoleActivity` transcript. There is no second execution truth.

**Lifetime rules**

| Outcome | Card | Timer | Released by |
|---|---|---|---|
| completed | `Finished` · command · `Completed · exit code 0` | `finishedAt + 5 min` on the **server clock**. **Provisional, not human-approved** (`TERMINAL_EVIDENCE_DEFAULT_MS`, S53 decision D1). Suspended while Dad has it Expanded. | Dismiss, timer, next Play, gates off |
| failed | `Command failed` · command · `Failed · exit code N` | none | Dismiss, next Play, gates off |
| unknown | `Ended — result unknown` · command | none | Dismiss, next Play, gates off |

- **Independent of the server view.** Once a record exists, a decayed or absent `ExecutionView` no longer erases the card. The card renders from the record plus the current clock (a pure function, so rerender and SSE reconnect are idempotent). One wake-up timer is scheduled per (instance, playRef) from `finishedAt`, so reconnect never restarts it.
- **Copy All / Copy New** copy text, advance the cursor and flash "✓ Copied". They no longer dismiss Terminal evidence.
- **Expand is not dismissal.** Collapse returns to the compact strip. Failures stay as a strip. A success then follows its timer, which has usually elapsed, so it goes quiet.
- **New Dismiss control** on retained evidence, in both the compact row and the expanded console header. It is browser-only and hides the card. The daemon store and output are untouched, and it is not a report acknowledgement.
- **Console header** now carries the outcome (`Live Terminal · Name · Failed · exit code 128`). On a phone the expanded console covers the strip, so the exit code stays visible.
- **Honest empty transcript.** A retained card whose transcript is confirmed empty says `No output was kept for this command.` instead of "Waiting for live execution activity…".
- **`sessionStorage` mirror.** Key `sidelineCoach.terminalEvidence.v1`, tab-scoped, Game-scoped, wrapped in try/catch and validated on restore. Reload keeps evidence and dismissals. Blocked, corrupt or partial storage is ignored and the page works without it.
- **Gates.** Evidence exists only while Dev Mode **and** View Player Terminal are both on. Turning either off clears the records and the stored copy.
- **Scout and AI Players** are never Terminal evidence.

## DECISIONS AND DEVIATIONS (please read)

1. **Copy still releases a completed *AI* Player's console.** S53.0 proposed removing the post-completion release for all Player types and amending LPT-28. This Play's contract says non-Terminal behavior must not change unintentionally, so I limited the change to `direct-shell`. LPT-28 (AI Player) is untouched and still passes. Making Copy universal is a one-line change plus a deliberate LPT-28 amendment. Say the word and it becomes the next tiny Play.
2. **A `queued` next Play shows its own Queued strip in place of the card.** The record is not superseded until the next Play actually runs. If the queued Play is cancelled, the card returns (TER-10).
3. **One assertion amended in a substrate-adjacent test.** `live-player-terminal-v02-transport.test.mjs` (LPT-T1 #11) pins the exact text of `isTerminalEligible` ("eligibility is not accidentally narrowed"). This Play widens it with `Boolean(evidence) ||`, so I added that clause to the regex. The intent is unchanged. No substrate *source* file was touched.
4. **Retention needs both gates.** With View Player Terminal off, no evidence card appears at all. There would be nothing to inspect, and S53.0 says to clear on either gate.

## REMAINING PROBLEMS / UNKNOWNS

- **Not yet observed in a real VS Code host.** Every proof runs on the real `index.html` in a DOM stub with a simulated server clock.
- **A late or failed transcript backfill** leaves the empty-body placeholder as "Waiting for live execution activity…" instead of "No output was kept…", because the honest text is shown only once the backfill has completed.
- **Unknown-outcome reachability.** `execution-projection.ts` (protected) projects `unknown` only when the ledger `workState` is `unknown`/`disconnected`. A Play whose latest ledger outcome is `unknown` in another workState may project `idle`, so the browser would never see it. The browser side is proven (TER-3). Whether the substrate can produce that shape in the field is not verified here.
- **Evidence never sighted cannot be reconstructed.** If Dad had no page open while a command finished and its 2-minute server window passed, there is no record. Honest and bounded, as S53.0 states.
- **Success duration is 5 min and provisional.** It needs the Play 3 setting and human ratification (D1).
- **One transient failure, not reproduced.** The first paired run of the two console suites showed `fail 1`. It passed on the immediate rerun, and the full suite then passed twice (1319/1319). I did not capture that test's name. The only real failure I did diagnose was the LPT-T1 regex (decision 3). Treat the transient one as an unexplained flake to watch, likely a random-port collision in the daemon tests, though that is unconfirmed.
