## 4. C0 — Install Identity

**Contract.** `~/.sideline/install.json` holds `{ "v": 1, "installId": "<26-char base32 = 128 random bits>", "createdAt": <epoch ms> }`.

- **Create-once.** The identity is written to a unique temp file (`wx`, `0600`) and published with `linkSync`. On `EEXIST` it loads the winner. This reuses the `host-identity.ts` pattern and its `base32Lower`.
- **Deterministic malformed handling.** An unparseable, wrong-version, bad-id, empty, oversized, directory or symlink file is **never silently overwritten**:
  1. It is renamed aside to `install.json.malformed-<ts>-<rand>`, and only if its bytes are unchanged at that instant.
  2. A fresh identity is published through the same create-once path.
  3. The result reports status `recovered`.
- **Wiring.** The identity is created in `ControlPlaneDaemon.start()`, not the constructor, so constructing a daemon has no new side effects. A filesystem failure is logged and the daemon starts normally.
- **Independent of Remote.** No `hostPublicId` is involved and no relay is needed.
- **Never exposed.** It is not in `/api/health` or `/api/status`, and nothing reads it yet.

**Acceptance (tests C0-1 … C0-5/6):**

1. First run creates the identity, and no temp files remain.
2. Restart loads the exact identity; the bytes on disk are untouched.
3. Concurrent initialization is safe:
   - a deterministic EEXIST race (a competitor publishes mid-call) returns the competitor's identity;
   - **8 real simultaneous processes** converge on exactly one id with no leftover temp files.
4. Four malformed variants are each quarantined with the original bytes preserved, and the recovered identity is stable afterwards.
5. A daemon with Remote disabled gets the identity, and `host-key.json` is not created.
6. The id appears in neither `/api/health` nor `/api/status`.

## 7. C3 — Usage Store + Meters

**Design:** usage state is a **deterministic fold of `UsageReceipt`s**.

- **Receipt fields:** `seq`, `id` (idempotency key), `capability`, `meter`, `grantId`, `periodKey`, `units ±`, `at`, and `minutes` for minute ranges.
- **Commit order:** receipts are appended to the journal first, then the fast-path state is written atomically (temp + rename, `0600`, dir `0700`).
- **Load:** a valid `usage.json` is loaded, then any journal receipts with `seq` newer than the state's `seq` are replayed. A missing or corrupt state file is rebuilt from the journal. Torn or foreign journal lines are skipped, and duplicate `seq`s fold once.
- **Rotation:** at 1 MB, keeping 3 generations. History lost to rotation under-counts, never over-counts.
- **Failure handling:** if the journal cannot be written, the use is still allowed and simply not recorded (under-count), with a warning. The feature is never blocked.

**Meters:**
- **count:** idempotency key per use. Release refunds the exact allocations. A released key may be charged again. The last 500 keys are kept per capability.
- **minutes:** a merged set of minute-index intervals per capability. A minute is charged at most once, ever. Contiguous minutes on the same grant and period become one receipt.
- **ceiling:** a member set; used = set size. Admission is idempotent and release frees a slot.
- **flag:** entitlement only.

**Grants:**
- `unlimited` dominates, but its usage is still recorded for later packaging.
- Otherwise the grant with the soonest effective expiry is drained first (`min(validUntil, period end)`), with grantId as the tiebreak. Remaining is aggregated across valid grants. A multi-unit charge may span grants.

**Periods:** lifetime, daily (local midnight), monthly calendar (local month), monthly anchored (UTC billing cycle, day clamped to month length), and rolling N days (daily sub-buckets summed).

**Not wired, as instructed:** the daemon constructs the gate **without** a usage store, so no `~/.sideline/entitlement/` files are created (test C3-16). `gate.chargeMinutes()` exists as the C4 entry point but is not called anywhere.

## 10. Architecture Deviations and Clarifications

1. **Install identity is created in `start()`**, not construction. This keeps daemon construction side-effect-free. `createdAt` is epoch ms, matching `host-key.json`.
2. **Malformed identity policy.** S57.2 left this open. This batch quarantines the file and recreates it, never overwriting silently, and the rename happens only if the bytes are unchanged, which minimizes race risk.
3. **`routines` is a `flag` meter.** S57.2 said "count (if ever)". Flag is the honest current meaning (creation access). Changing it later touches only the catalogue.
4. **Commit protocol strengthens S57.2 §6.4.** Receipts carry `seq` and state records the last folded `seq`, which makes crash repair exact (replay) instead of approximate.
5. **`gate.chargeMinutes()` was added** as the C4 surface (S57.2 named it `minutes: DurationMeter`). It exists but is unwired.
6. **Scout directive under a restricted profile.** Because the enricher removes Scout from AUTO, a "Scout this play" prompt under a non-entitled profile gets the existing routing outcome rather than a capability-named sentence. Only a restricted profile can reach this, and none exists at runtime. The router's own Scout guard does give the capability-named 403 whenever a decision still resolves to Scout.
7. **Game check placement.** In `runAddGame` the check runs after the human picks, because C2 has no admission set and "already admitted" can only be answered for a known `gameId`. C5 should decide whether an up-front "no slots" check before opening the picker is also wanted (UX).
8. **The router Game gate runs before the offline and conflict checks**, per S57.2's "top of `router.dispatch`". It also applies to queue-released Plays, which C5 should account for.
