# CLARIFICATION DATA CONTRACT

- `RouteQuestion { fingerprint, dimension, reason: 'ambiguous'|'contradictory', options: RouteOption[] }` and `RouteClarification { fingerprint, option /* 1-based */ }` (`capability-types.ts`, additive).
- `routeQuestion(constraints)` (`routing-policy.ts`) derives the question purely from the existing `RouteConstraints.unresolved`; no new ambiguity model. A question exists only if there is exactly one unresolved item, reason ambiguous/contradictory, with 2..4 options. Unknown/unsupported stops, >4 options, single options and resolved routes yield no question.
- `computeAutoRoute(…, clarification?)` / `RouteContext.clarification` / `Router.computeRoute(…, extra.routeClarification)` / `DispatchOptions.routeClarification`. Stops now return `{ error, question? }`; dispatch refusals carry `question`.
- Daemon: `/api/route/preview` and `/api/dispatch` both read `body.routeClarification` through the same `parseRouteClarification` (fingerprint = 16 hex, option an integer 1..4; anything else is dropped). The preview error response and `buildRouting` carry `question`.

# FINGERPRINT / STALE-SELECTION SAFETY

Fingerprint = sha256 (first 16 hex) of: dimension, reason, raw text, each option's tuple + label, and every already-recognized dimension and excluded model. Recognition re-runs on every call (preview and dispatch); the answer applies only if the recomputed fingerprint matches, the option index exists, the option is not an excluded model, and the option re-resolves to exactly one live catalogue route (`resolveCatalogueRoute`). Otherwise the route stops with *"The route question changed — choose again."* plus the new question; nothing dispatches. An answer when no question exists any more is ignored (the Play resolves on current truth). Proven: changed effort, changed exclusion, changed option set, out-of-range option, malformed answers, and a model leaving the catalogue.
