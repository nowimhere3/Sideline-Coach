## 1. Verdict

- **AGY's architecture map is sound.** It correctly keeps the §19.4 R8 gate (≥50 dispatched, burn, invariants) separate from the §12.3 R10 gate (≥30 resolved outcomes **per task class**, reliability, Brier). It also correctly specifies binary outcomes, frozen predictions and an in-sample pooled base rate.
- **Two parts of AGY's bin policy are invented and should be dropped:**
  - the 25 pp sparse-bin veto
  - the "≥ 2 evaluable bins" requirement

  Neither makes the Dad-visible number safer. The first is a random veto driven by coarse small-n proportions. The second is an evidence cost that does not test calibration.
- **AGY's policy leaves one real false-confidence hole.** A graduated class would show a percent for a prediction in a range that has 0–4 observations. That contradicts §12.2's "a percent is never shown before calibration earns it." The fix costs no graduation evidence.

## 4. Recommended bin policy: Option D, "Supported bins gate, supported bins speak"

1. A bin is **supported** when `n_b ≥ 5`. Only supported bins are tested against ±10 pp. Sparse bins (1–4) and empty bins neither block nor authorize. They are shown in Dev with their n and marked insufficient.
2. There is **no minimum count of supported bins**, and no sparse-bin veto. With N ≥ 30 across 3 bins, at least one bin always has n ≥ 10, so "≥ 1 supported bin" is automatic.
3. **Display scope (the addition that closes the hole):** after graduation, a percent is exposed only when the primary's predicted value falls in a bin that was supported, and therefore passed, in that class's current evaluation. Otherwise Dad sees words, exactly as before graduation.

This is Option C with its "enough supported bins" set to its natural value (1). Option C alone still leaves the display hole, so point 3 is required.

### Plain English for Coach

Sideline sorts its past predictions into three buckets: low, middle and high chance. For each bucket it checks whether the predictions came true about as often as promised, within 10 points.

- **A bucket with only one to four Plays in it can't tell us anything.** One lucky or unlucky Play swings it by 25–100 points. So those buckets don't get a vote, either to pass or to fail. That is AGY's instinct, and it's right.
- **The 25-point tripwire is just another way of letting luck vote.** A perfectly honest middle bucket with one Play in it trips it every time.
- **Requiring two full buckets punishes a good router.** If the Players you pick are usually strong, nearly all predictions land in the high bucket. You'd wait indefinitely for a middle bucket to fill, and gain no safety from it.
- **The real risk is different.** It is showing Dad "Codex · 45%" when Sideline has never proven itself in the 33–67% range.
- **The fix is simple.** Sideline may only speak in numbers in a range where it has proven itself. Elsewhere it keeps using words. This costs no extra evidence to graduate.

## 5. Why: the numbers

The table shows the exact binomial chance that a bin passes the ±10 pp test. Each figure is averaged over the bin's range of predictions, which removes the step effect you get with small n (computed this session).

| High bin (p 0.70–0.95) | n=5 | n=10 | n=20 | n=30 |
|---|---|---|---|---|
| perfectly calibrated | 46% | 63% | 80% | 87% |
| 15 pp overconfident | 32% | 35% | 33% | 28% |
| 20 pp overconfident | 26% | 25% | 18% | 13% |

At fixed values, n = 1–4, a **perfectly calibrated** bin behaves like this:
- **±10 pp test (Option B):** it fails 100% of the time at n = 1 for any p between 0.1 and 0.9.
- **25 pp tripwire (Option A):** it fails 100% at n = 1 when p = 0.5, and 36% at n = 2 when p = 0.8.

What this shows:
- **Sparse bins (1–4) measure how coarse the counts are, not calibration.** Both Option B (every populated bin) and AGY's 25 pp veto hand that noise a veto. B is effectively "never graduate after one stray prediction." AGY's veto fires on honest predictions and is only weakly related to real miscalibration. Drop both.
- **Raising the floor from 5 to 10 buys almost no safety.** A 20 pp overconfident bin passes 26% vs 25%; the higher floor mainly reduces false *rejections*. Per-bin power only appears at n ≈ 20. So the floor stays at the existing constant 5, and the bin test is treated as one of three safeguards, not the main one.
- **The main safeguard is Brier against the in-sample base rate.** With the pooled in-sample rate, `BS_base = ȳ(1−ȳ) = UNC`. By the Murphy decomposition, `BS_model < BS_base ⇔ resolution > reliability error` (up to within-bin variance terms). This already demands real discrimination and penalizes miscalibration across **all** N, including the sparse bins' observations.
  - This is why "≥ 2 bins" is redundant. A predictor clustered in one band has little resolution, so it must be very well calibrated to beat the base rate.
  - Example: a model that says 0.9 for everything when the truth is 0.7 has Brier 0.25 vs a base of 0.21, and fails.
- **The third safeguard is weekly recomputation with un-graduation.** It corrects a lucky early pass as n grows.
- **What remains is the display hole, and it is the one that matters to Dad.** The bin test and Brier are class-wide. Under AGY's rule, a graduated class could print a percent for a prediction in a range with 0–4 observations. Scoping the display to supported bins removes that at zero evidence cost.
- **Known consequence (fail-closed, not a defect).** A class whose resolved outcomes are all successes or all failures has `BS_base = 0` and cannot graduate until the outcomes are mixed. That is correct: there is nothing yet to show that the predictions tell good Plays from bad ones.

## 6. Exact deterministic rule

Evaluated per task class `C` at the weekly instant `t`, from Film events at or before `t`:

```
Sample S_C  = chosen-route Plays with
              decision.profile.taskClass === C
              first-pass resolution resolved at t (not pending, not excluded)
              p_i = FROZEN digest firstPass of the chosen route (existing predictedFirstPass;
                    scout-first / wait-for-reset options never supply p_i)
              y_i ∈ {0,1}  (binary; attribution weights are NOT used)
              → a Play with an outcome but no frozen p_i is reported as withoutPrediction and not counted
              → p_i is NEVER recomputed from today's belief (that would leak the outcome into its own prediction)
N_C = |S_C|

G1  N_C ≥ 30
G2  ȳ = Σy/N ;  BS_model = Σ(p−y)²/N ;  BS_base = ȳ(1−ȳ)
    pass iff BS_base − BS_model > 1e-12            (float ties fail)
G3  b(p) = min(2, floor(3p)) ;  for each b: n_b, p̄_b = Σp/n_b, ȳ_b = Σy/n_b
    supported_b iff n_b ≥ 5
    pass iff for every supported b: |ȳ_b − p̄_b| ≤ 0.10 + 1e-9   (e.g. |0.7−0.8| = 0.10000000000000009 must pass)
graduated_C(t) = G1 ∧ G2 ∧ G3        // no minimum supported-bin count; no sparse veto
supportedBins_C(t) = { b : supported_b }   // all passed, since graduated

Un-graduation: the same rule at the next weekly instant; any failure → words. No hysteresis.
Sums are taken in a fixed order (Film order) over the unrounded values. Same Film + same t → same verdict.
```

## 7. `calibratedFirstPass` semantic: Model A (authorization, scoped)

The trace:
- §12.1 defines Calibrated Confidence as *P(first-pass acceptance)*.
- §19.3 bins **`firstPass.mean`**.
- §5.3 says the posterior is "the whole statistical engine… no trained model."
- §20 says the percent is "**unlocked**" per class, not transformed.
- R6 already freezes exactly `option.scores.firstPass.mean` into the Film digest (`recommend.ts` `optionDigest`), and that is the p_i the gate tests.

So the number Dad sees is the same quantity the gate validated.

**Model B (a fitted recalibration map) is wrong for V1:**
- It is a trained model, which §5.3 excludes.
- A 3-bin map could only ever output 3 values.
- The gate would no longer validate the displayed number.
- An honest fit would need its own held-out evidence.

```
strength.calibratedFirstPass = primary.scores.firstPass.mean   (unrounded)
  present iff  graduated_C (latest weekly evaluation, C = this Play's taskClass)
          and  primary.kind ∈ {send, queue, handoff}          (only kinds the gate can bin)
          and  b(primary.scores.firstPass.mean) ∈ supportedBins_C
Dad view shows the percent iff calibratedFirstPass is present and the primary's resource evidence
is not UNKNOWN (§18.2/§21: price 'unknown' / RESOURCE_UNKNOWN). Otherwise it shows the words.
Always the posterior mean, never `lo`: SURE uses lo for ranking only (§5.4); §19.3 validates the mean.
```

**Residual, accepted by S57.1 and not new:** the percent is shown for the primary, but outcomes exist only for chosen routes (§19.3's own caveat). The same belief function produces both, and every USE click turns a primary into a chosen route. Dev should keep the caveat visible.

## 8. Rounding rule

- **Math:** no new rounding. Keep only the existing 1e-6 determinism rounding (`round()` in `belief.ts` and `recommend.ts`, which already feeds byte-identical replay and the Film digest).
  - `calibratedFirstPass`, Film p_i, Brier and bin statistics stay at that precision.
  - AGY's 2-decimal rounding is dropped. It would expose a number different from the one the gate validated, and it would move values across bin edges.
- **Presentation only:**
  - **Dad:** `pct = min(99, max(1, Math.round(100·x)))` + `%`. A Beta posterior mean is strictly inside (0,1), so "100%" or "0%" would state certainty that does not exist. Line budget: "Suggest Antigravity · 99%" = 25 ≤ 28.
  - **Dev:** Brier to 4 decimals and rates to 0.1 pp, format only.
