## Executive Decision

The Terminal substrate (S48–S50) is untouched. Everything below is presentation, projection, and routing policy around it.

1. **Discovery.** Hide raw unmanaged shells at the *one* existing projection seam (`projectDiscovery`, `src/running-players.ts:70`), gated by a new Dev-Mode-only `advancedPlayerDiscovery` preference. Discovery truth (`PlayerRoster.adoptableTerminals()`, `discoveryByGame` cache) is not touched. The curated Terminal recruit entry stays.
2. **Retention.** Terminal evidence gets its **own client-side lifetime**, independent of the server `ExecutionView.state`. This is the key new finding: a report-less Terminal Play projects `finished` for only `REPORT_GRACE_MS = 2 min` (`work-ledger.ts:23`, `execution-projection.ts:125-131`), and today's pin rescue and terminal eligibility both require `view.state === 'finished'` (`index.html:2653`, `:2763-2766`). Retention keyed on that state cannot be made reliable; it must be keyed on a small per-Player evidence record.
3. **Failure.** Failed / unknown-outcome Terminal evidence has **no timer**: it stays until the human dismisses it or the next Play starts. Successful evidence ages out on a configurable timer, and never while a human is actively reading it. The daemon and ledger stay truthful; `couldnt-finish` is still `couldnt-finish`.
4. **Copy.** Copy advances the checkpoint cursor and does nothing else. For every Player type, not only Terminal.
5. **Auto-expand.** Yes, for Terminal (`direct-shell`) output only, **desktop width only**, **no setting**. At ≤619px an expanded console is a fixed fullscreen overlay (`index.html:630-634`); auto-expanding that on every command would seize a phone screen.
6. **AUTO.** A separate **closed-grammar** classifier (`src/terminal-intent.ts`, pure) licenses direct Terminal routing. It is a strict subset of `checkTerminalCommand()`, which stays the final gate. Anything not positively recognised routes to reasoning exactly as today.
7. **Settings.** Two new settings only: `advancedPlayerDiscovery` (boolean) and `terminalRetention` (four-choice enum). Everything else is a rule, not a setting (North Star anti-pattern #13).

## S51 Consolidated Truth

S51 is the stronger authority and its core findings **stand**: raw shells leak because `projectDiscovery` ignores `adoptableTerminals`; fast failure vanishes because `stripCopy` returns `null` for non-Scout `couldnt-finish`/`unknown`; fast success vanishes because pinning only attaches to an already-expanded card; Copy dismisses after completion; Terminal has zero AUTO support; report and Terminal-evidence lifecycles must stay separate.

**Three points I corrected or added:**

1. **"Pinned evidence remains inspectable indefinitely" is not safe to rely on.** For a Terminal Play with no report, the server-projected `finished` lasts 2 minutes (`REPORT_GRACE_MS`), then projects `idle`. The pin rescue (`index.html:2653`) and eligibility (`:2763`) both require `finished`. The daemon has no grace-expiry rebroadcast (views are re-projected only when a status snapshot is built, `daemon.ts:3050`), so the exact moment the card dies depends on the next status event. *Source-derived, not field-observed* — but either way retention must stop depending on it. This is why Play 2 introduces its own evidence record.
2. **S51's Dad-safe seam #2 ("also suppress non-standard `externalCandidates`") is rejected.** Those are recognised supported agents (Claude/Codex/AntiGravity running elsewhere), governed by the existing `runningPlayers` preference. Only `adoptableTerminals` is the raw-shell leak.
3. **S51's AUTO seam is incomplete.** Its `isUnambiguousShellCommand(): boolean` inside `computeAutoRoute` alone would be bypassed: the Control Plane's real path is `computeContextAwareRoute`, which runs constraint parsing, the Scout route, and context-owner lookup *before* reaching `computeAutoRoute`, and filters terminals itself (`:580`). The wire-in must sit at **both** sites, mirroring how `computeScoutAutoRoute` is already called at both (`:325`, `:610`). A boolean also gives tests no reason codes, and S51's snippet omits busy / ownership / multi-Terminal rules.

Additionally carried from S50 Architecture Feedback: (a) the Terminal console contains no `RESULT`/exit-status line — completion is visible only in the strip; on a phone the expanded console **covers** the strip, so the exit code is invisible while reading (Play 2 fixes this in the console header); (b) flood policy keeps the *head*, not the tail, of a burst — a failing `npm test`'s summary can be lost (deferred; see Risks); (c) a Terminal closed mid-command is still unhandled (pre-existing).

## Terminal Retention Architecture

**Principle: retention is a client presentation concern; evidence lifetime ≠ view lifetime ≠ Player health.** Read is not dismissal. Copy is not dismissal. Opening evidence is not permission to destroy it.

### State (bounded, one record per Terminal Player)

```
terminalEvidence: Map<instanceId, { playRef, outcome: 'completed'|'failed'|'unknown',
                                    finishedAt /* server clock */, dismissed: boolean }>
```

- Created when the client first sees a `direct-shell` view in `finished` / `couldnt-finish` / `unknown` **that actually ran** (`Number.isFinite(view.durationMs)` — `not-sent` refusals have no `executionStartedAt`, so no evidence exists to retain). It is created on *first sighting*, so a command that finished before the human noticed still gets a record.
- **Human-open state is the existing `consoleExpandedByInstance`** (unchanged; LPT-27/29 semantics preserved). Auto-expand (Play 3) is *derived*, never added to that set, so "the human is reading" stays distinguishable from "Coach opened it".
- Mirrored to `sessionStorage` (try/catch; page renders correctly without it): survives rerender, SSE reconnect, and page reload; tab-scoped so a stale dismissal never haunts next week. Not `localStorage`. Records for instanceIds no longer on the roster are pruned; all cleared when either gate goes off.

### Rules

| Outcome | Card while retained | Timer | Released by |
|---|---|---|---|
| completed (exit 0) | `Finished` · command · `Completed · exit code 0` | **Yes** — `finishedAt + T` on the **server clock** (`serverNow()`), so reload/reconnect cannot restart it. Suspended while the human has it open. | Dismiss · timer · next Play · gates off |
| failed (exit ≠ 0) | `Command failed` · command · `Failed · exit code N` | **No** (D2) | Dismiss · next Play · gates off |
| unknown (exit not reported) | `Ended — result unknown` · command | **No** | Dismiss · next Play · gates off |
| not-sent | none | — | — |

- **Expand** (human) → keeps the card past the timer; released by Collapse-then-timer, Dismiss, or next Play.
- **Collapse** (on an expanded console) → back to the compact strip. Success evidence then follows its timer (likely already elapsed → goes quiet, which matches "I'm done"). Failure evidence stays as a compact strip.
- **Dismiss** (new small control, only on retained terminal-evidence strips) → sets `dismissed` for that `playRef`. Hides; never deletes the daemon store or any output.
- **Next Play** on the same Player → old record replaced; the console follows the new Play live. Human-open state carries over exactly as LPT-29 requires.
- **Timer fires** → one deterministic `renderPlayerStrips()` scheduled from `finishedAt` (existing `scheduleFinishedDecay` pattern), idempotent per `(instanceId, playRef)`.

### Retention does not read the server `finished` state after first sighting
`isTerminalEligible` and the pin-rescue gain a `direct-shell` branch keyed on the evidence record. AI-Player behavior (`consolePinnedByInstance`, report-ready durability) is untouched.

### Reload / reconnect / restart matrix

| Event | Result |
|---|---|
| Rerender | Idempotent (pure function of record + view + prefs + `serverNow()`). |
| SSE reconnect | Same; no timer restart. |
| Browser reload | `sessionStorage` restores dismissal; success timer recomputes from server `finishedAt`; a failed view is still projected `couldnt-finish` until acknowledged, so it re-creates its record. |
| Success evidence older than the server's 2-min `finished` window, after a reload | Not reconstructable — honest, bounded. |
| Daemon restart | Transcript is memory-only and gone (`epoch` rotates). A retained card with no lines must say so — **not** "Waiting for live execution activity…" (false for a finished Play). Play 2 replaces that placeholder for terminal-outcome states with "No output was kept for this command." |
| New tab / other device | Presentation-local; not synced. |

Rejected: daemon-side retention (violates presentation ownership, S48 guarantee); full history (needs a new durable transcript store — S48 NOT-V1, and it would duplicate the report system); merging with report retention.

## Auto-Expand Decision

**Yes, narrowly** (D4): for a `direct-shell` Play, the console renders expanded by default when Live Player Terminal is enabled, **only at desktop width**, with **no setting**.

Why: for AI Players the console is "guts"; for Terminal the output *is* the deliverable — every command otherwise costs a click and, when fast, a race (the field-proven blip).

Constraints (source-grounded):
- **Never on phone width.** At ≤619px `.play-console` is `position: fixed; inset: 0; z-index: 1000` (`index.html:630-634`) — auto-expanding would seize the screen on every command. Guard with `matchMedia('(min-width: 620px)')`, mirroring the CSS breakpoint. On phones the compact retained strip + explicit Expand is the design.
- Auto-expanded ≠ human-opened: it does **not** suspend the success timer and is never written to `consoleExpandedByInstance`.
- A human Collapse dismisses auto-expand for that Play only; the next Play defaults again.
- Own Play (3) so it can be dropped without touching Play 2 if the human rejects it.

## AUTO Terminal Intent Classifier Contract

### Placement
- New pure module `src/terminal-intent.ts`: no `vscode`, no `fs`, no I/O, deterministic. (A new file, not more code in `terminal-player.ts`, which is substrate and already carries uncommitted work.) Imports `checkTerminalCommand` read-only.
- Signature: `classifyShellIntent(prompt: string): { kind: 'shell'; command: string; intentClass: 'inspect' | 'project-command'; rule: string } | { kind: 'reasoning'; reason: ShellIntentReason }`.
- **Never rewrites text.** `command` is the trimmed prompt, byte for byte. What the human typed is what the shell receives.

### What licenses `shell` — ALL must hold (a closed grammar, not a score)

| Gate | Requirement | Else → `reason` |
|---|---|---|
| G0 shape | 1–160 chars after trim; **single physical line**; printable **ASCII only** (kills zero-width/homoglyph tricks); no NUL/control; no code fence; no leading prompt marks (`$ `, `PS>`, `>`) | `not-single-line` · `too-long` · `non-ascii-or-control` · `fenced` |
| G1 exact-command guard | `checkTerminalCommand(text).ok` — the classifier is a **strict subset** of the guard by construction | `refused-by-command-check` |
| G2 tokens | Every token matches an allowlist charset (`[A-Za-z0-9_@.+:\/\\-]`, `=` only inside `--flag=value`); quoted tokens allow only path-safe interiors. **Banned everywhere:** `\| & ; < > \` $ ( ) { } % * ? ! ~` | `metacharacter` |
| G3 executable | First token is an **exact, case-insensitive** row in the grammar table. No path prefix, no `.exe`. | `unknown-executable` |
| G4 homograph | A verb that is also an English word (`cat`, `type`, `find`, `date`, `which`, …) needs a flag-shaped or path-shaped argument; bare use → reasoning | `homograph-needs-shell-shape` |
| G5 grammar | Subcommand ∈ row's closed set; flags ∈ row's closed set; positionals ≤ row's max and shape-checked | `unknown-subcommand` · `unknown-flag` · `bad-argument` |
| G6 deny overlay | Belt and braces, independent of the allowlist: any token in `rm del rmdir rd format kill taskkill Stop-Process Remove-Item sudo runas curl wget iex Invoke-Expression Invoke-WebRequest powershell pwsh cmd bash sh ssh scp reg shutdown …`, any `--force / -f / --hard / -rf / -y`, or a secret-shaped path (`.env*`, `*.pem`, `*.key`, `id_rsa*`, `credentials*`, `secret*`) | `denylisted` · `secret-path` |
| G7 request veto | Any token in a request/prose set (`please why how what is are the a an my me it this that fix figure out explain help failing fails failed broken need want can could should would …`) — a **contradiction is a veto**, not a lower score | `request-language` |

### Seed grammar (Play 4 may shrink it; widening needs human ratification)

**`inspect`** — read-only.
`git status|diff|log|branch|show|rev-parse|remote -v` with closed flags (`-s --short -b --branch --porcelain --stat --name-only --name-status --oneline -n<N> --no-color --graph --decorate --all`), ≤2 ref/path positionals · `<tool> -v|--version` for `git node npm pnpm yarn python py dotnet cargo go` · `dir ls pwd whoami hostname tasklist` · `Get-ChildItem Get-Location Get-Process Test-Path` (≤1 path) · `cat|type|Get-Content <one path-shaped, non-secret file>` · `npm ls|list [--depth=N|--all]`.

**`project-command`** — bounded local mutation the human explicitly listed.
bare `npm|pnpm|yarn install|ci` · `npm|pnpm|yarn test|t` · `npm|pnpm|yarn run build|test|lint|check|compile|typecheck` · `cargo build|test|check` · `dotnet build|test` · `go build|test|vet ./...`.

**Recognised as Terminal-only but NOT auto-routed in v1 (D3):** server lifecycle (`npm start`, `npm run dev|serve`, `node server.js`, `kill`, `taskkill`, `Stop-Process`). **Ineligible:** every `git` mutation (`add commit checkout reset clean pull push …`); `npm install <pkg>` (supply chain); `npm run <arbitrary>` (may start a server); anything network-fetching; `cd pushd Set-Location` and env setters (**the Terminal is a persistent shell — state mutation would silently change every later command's working directory**); `node -e`, `python -c`, `node file.js` (arbitrary code); shells-in-shells; bare environment dumps (`env`, `printenv`, `Get-ChildItem env:` — secret-exposure surface; version/location probes cover "environment queries").

### Syntax policy

| Construct | v1 |
|---|---|
| Multiline, fenced blocks, pasted transcripts | **Reasoning.** (Also: multi-line falls to the *unobserved* `sendText` path, S48 R5.) |
| Pipes, redirects, chaining (`&& \|\| ;`), background `&`, subshells, backticks, variables, globs | **Reasoning.** Read-only pipelines are a future widening. |
| Quoted path arguments | Allowed, path-safe interiors only. |
| Natural language, questions, "check X", "run X for me" | **Reasoning.** |

## Safety / Ambiguity Rules

**False negative → AI reasoning (costs tokens). False positive → possible unintended shell execution.** So: uncertainty fails toward reasoning, **and there is no third "ask" outcome in v1** — an "ask" would hand the human a plumbing question (NORTH-STAR #4); falling to the existing AUTO path is the human-approved bias.

| Situation | Behavior |
|---|---|
| Classifier says `reasoning` | Existing AUTO, byte-identical to today. |
| **Explicit human routing wins.** Manual mode → classifier never consulted. AUTO with recognised route constraints (`Use Codex …`) → Terminal path skipped. | Unchanged. `Use Terminal` prose in AUTO still returns the existing "Terminal runs exact commands in Manual" message (`routing-policy.ts:599`) — out of scope. |
| `shell` + **exactly one** on-field, `ready`, **Coach-managed** Terminal | Route to it. |
| `shell` + no Terminal | Existing behavior (reasoning Player; or the existing "put a reasoning Player on field" error when only Terminals exist). |
| `shell` + Terminal **busy** | Fall through to existing AUTO. *Known cost:* a reasoning Player may spend tokens on `git status` while the shell is busy (Risks). |
| `shell` + **≥2** ready Terminals | Fall through — never guess which shell/cwd. |
| Adopted / external Terminal | Never auto-targeted (D5). Requires an additive optional `ownership` on the Terminal routing capability (today only a label string carries it). |
| Route chosen | `checkTerminalCommand()` **still runs at execution** (`runTerminalCommand`). A refusal after an AUTO route = a classifier bug; a property test makes it a test failure. |
| Staged preview | Same function as dispatch (`router.ts:113-125`), so the human sees **"Terminal · runs this command as typed"** before Send. No model/effort chips. No plumbing words. |

**Precedence when wired (both call sites):** explicit constraints → *Terminal shell-intent* → Scout need → context owner → existing AUTO. Placed before Scout and context ownership because a pure command is not reconnaissance and not a follow-up; the classifier is strict enough that a report follow-up can never satisfy it.

**Reversibility (NORTH-STAR #16):** one sentence — "AUTO runs an exact, recognised command in Terminal instead of paying an AI"; one obvious control — switch to Manual; and one code-level rollback — Play 5 wires through a single helper at two call sites.
