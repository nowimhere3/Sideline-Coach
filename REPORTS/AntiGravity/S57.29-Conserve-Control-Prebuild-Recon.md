## 1. Executive Verdict

The approved visual design (`TEMP/03b6508d-d1b3-45c6-b18b-933e2b976bba.png`) introduces a hardware-style square actuator with illuminated lamp and separate `CONSERVE ⓘ` label onto the existing Outgoing Play Dispatcher routing row.

**Key Finding:** 
The underlying Intelligent Routing engine **already has complete canonical architecture and mathematical weights for CONSERVE** (`RoutingPosture = 'conserve'` in `src/routing-intel/recommend.ts:59-78`, with $\lambda_C = 2.5, \lambda_D = 0.01, \lambda_R = 0.5$, weekly waits permitted).

**Crucial Architectural Distinction:**
- **CONSERVE Posture (Human Intent):** Managed by the new UI button. Sets `RoutingPosture = 'conserve' | 'balanced'`. Modifies utility weights.
- **Scarcity (Resource Fact):** Managed by `AlarmEngine` and `ResourcePolicyService` (Stage 2A `isConserveActive` / `conserveLevel`). Imposes price floors ($\pi \ge 1.5$ for LOW, $4.0$ for CRITICAL).
- As decreed in S57.1 §14: **CONSERVE posture $\neq$ Scarcity**. The new button controls the **posture**, not the alarm policy.

The implementation is narrow, clean, and requires **zero changes to the recommendation math or alarm engines**. Opus only needs to wire the UI actuator to a posture field on the daemon and pass it into the existing `recommendRoute()` call.

## 5. ResourcePolicy / Alarm Relationship & Authority Boundaries

### 5.1 Orthogonal Concepts (S57.1 §14)
| Concept | Layer | Values | Purpose |
|---|---|---|---|
| **Scarcity** | Automatic / Environmental | `none`, `low`, `critical`, `unknown` | Facts about current provider quota limits. Sets window **prices** ($\pi$ floors in §11). |
| **CONSERVE Posture** | Human / Policy Intent | `conserve` (vs `balanced`, `fast`, `sure`) | Strategic intent to protect capacity. Modifies **utility weights** ($\lambda_C = 2.5, \lambda_D = 0.01$). |

### 5.2 Why `ProviderResourcePolicy.isConserveActive` is NOT the Button State
In `src/control-plane/resource-policy.ts`:
- `isConserveActive: boolean` is a Stage 2A projection over AlarmEngine rules (`snapshot.rules[`${provider}:${window}`].state === 'LOW' | 'CRITICAL'`).
- S57.1 §14 explicitly warns:
  > *"Naming: keep Stage 2A's isConserveActive/conserveLevel untouched (it is a stable contract). In routing vocabulary and UI, the fact is called Scarcity. CONSERVE is reserved for the posture."*
- **Absolute Rule:** The new UI button **must not** modify or overwrite `ProviderResourcePolicy.isConserveActive` or `ResourcePolicyService`.
- If an alarm trips, Scarcity rises automatically.
- If the user toggles CONSERVE, Posture switches to `conserve`.
- If both occur simultaneously: the window prices are elevated by Scarcity AND the cost penalty is elevated by Posture $\rightarrow$ maximum capacity protection.

## 6. Recommended State Ownership & Persistence

### 6.1 Ownership Comparison
1. **Option A (Recommended): In-Memory on Daemon (Parity with `routingMode`).**
   - Property on `Daemon`: `private routingPosture: RoutingPosture = 'balanced';`
   - Included in `/api/status`: `routingPosture` (or `routing.posture`).
   - Mutated via `POST /api/route` (e.g. `{ posture: 'conserve' | 'balanced' }`).
   - Broadcasts `this.broadcast('status', { type: 'routing-change', at: Date.now() })`.
   - **Browser Refresh:** Restores automatically because the browser fetches `/api/status` on load.
   - **Daemon Restart:** Resets to `'balanced'` (unlit), exactly as `routingMode` resets to `'auto'`.
2. **Option B: Persisted in `preferences.json` (`CoachPreferences`).**
   - Extended in `CoachPreferences` (`src/running-players.ts`).
   - Survives daemon restarts.
   - S57.1 §3 defines Posture as "Coach preference (next to `routingMode`)". Since `routingMode` is currently daemon in-memory, Option A maintains exact behavioral symmetry.

**Adjudication:** Adopt **Option A** for the UI actuator. If Coach later wants daemon restart persistence for both `routingMode` and `routingPosture`, they can be migrated together into `preferences.json`.

## 7. MANUAL Mode Semantics

Under MANUAL mode:
- **Human Choice Wins:** Human routing selection (`terminalSelect`, `modelSelect`, `effortSelect`) is 100% authoritative.
- **CONSERVE Influence:**
  - `recommendRoute` continues to run in the background (shadow mode) with `advisoryOnly = true`.
  - In Dev Mode (`#devRoutingRationale`), the shadow recommendation reflects the `conserve` utility weights.
  - S57.1 §16 & `dad-advisory.ts:53`: The Dad advisory chip remains hidden under MANUAL mode (`if (rec.authority.mode !== 'auto' || rec.authority.advisoryOnly) return undefined;`).
- **Epistemic Rating:**
  - **VERIFIED:** Human route cannot be overridden by CONSERVE in MANUAL.
  - **VERIFIED:** Shadow recommendations use CONSERVE weights in MANUAL.
