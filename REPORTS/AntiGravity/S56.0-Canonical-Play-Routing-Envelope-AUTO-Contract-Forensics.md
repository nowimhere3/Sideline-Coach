## 1. Root Cause Analysis

### The Staged Field Failure
A Play was staged with the following Strategy Board header:
```text
AGENT: Claude
MODEL: Claude Sonnet 5
REASONING: Medium
DIFFICULTY: Architecture / Medium-High
ROLE: AI Health persistence architect
```

AUTO produced:
`Claude · Opus · Medium`  
Summary: `"Claude and Medium selected as you asked. Coach chose the model."`

### Root Cause Trace
1. **Header Parsing (`src/control-plane/route-constraints.ts`):**
   - `routeLines(prompt)` captures the first 15 unfenced lines.
   - `structuredRouteField`:
     - `AGENT: Claude` is recognized via `ROUTE_FIELD_ALIASES` -> dimension `player`. Matches known Player candidate `Claude` via `exactAlias`.
     - `REASONING: Medium` is recognized via `ROUTE_FIELD_ALIASES` -> dimension `effort`. Normalized `'medium'` matches `/^(low|medium|high|xhigh|max)$/i` and exists in Claude's supported efforts.
     - `MODEL: Claude Sonnet 5` is recognized via `ROUTE_FIELD_ALIASES` -> dimension `model` with raw text `"Claude Sonnet 5"`.
   - `modelAliases(relevantCandidates)` compiles literal catalog aliases `{ text: model.id, value: ... }` and `{ text: model.displayName, value: ... }` from Claude's live capability (`['opus', 'sonnet']`).
   - `exactAlias("Claude Sonnet 5", aliases)` compares normalized `"claude sonnet 5"` strictly against `["opus", "sonnet"]`. No match is found.
   - Because no alias matches, `model` is left `undefined`.
   - `recognizeRouteConstraints` returns:
     ```json
     {
       "source": "play",
       "playerType": "claude",
       "model": undefined,
       "effort": "medium",
       "recognized": ["player", "effort"]
     }
     ```
2. **Silent Fallback in Routing Policy (`src/routing-policy.ts`):**
   - In `computeContextAwareRoute`, `constraints.model` is `undefined`.
   - `constrainedCandidates` leaves all models of Claude in the candidate pool.
   - `constrainedSelection` falls back to `ClaudeRoutingPolicy.selectModel(task, snapshot)`.
   - `classifyTask(prompt)` classifies the prompt as `'architecture'` (triggered by `DIFFICULTY: Architecture...` and `AI Health persistence architect`).
   - `ClaudeRoutingPolicy` specifies: `if (task === 'architecture') return choose(['opus', 'sonnet'], ['high'], 'Hard architecture Play · Opus for depth')`. It selects **Opus**.
   - `requestedRouteReason` observes that `constraints.model` is absent from `recognized`, emitting: `"Claude and Medium selected as you asked. Coach chose the model."`

## 2. Current Contract vs Proposed Contract

### Current Contract
* `recognizeRouteConstraints` operates on an all-or-nothing model alias lookup. If a model string in an explicit `MODEL:` header does not strictly match a catalog `id` or `displayName`, it is silently discarded (`model: undefined`).
* `RouteConstraints` only carries successfully recognized constraints (`recognized: ['player', ...']`).
* `computeContextAwareRoute` treats an unresolvable model string identically to an omitted field, allowing provider policy heuristics (`selectModel`) to silently substitute an inferred model (e.g. Opus for architecture).
* Existing tests (e.g. `test/q2-10e-b-explicit-human-intent.test.mjs` Q2.10E-B-3 and Q2.10E-B.2-6) specifically assert that invalid model strings become `model: undefined` and permit AUTO to fill the omission.

### Proposed Contract (`CANONICAL-PLAY-ROUTING-ENVELOPE`)
> **Invariant:**  
> Assistant Coach routing instructions are product data. Sideline normalizes explicit routing metadata from a bounded prompt header before dispatch. Explicit valid values outrank inference. Explicit unresolved values never silently become inferred replacements. Only genuinely absent fields may be filled by the current AUTO policy. Future Intelligent AUTO is a separate routing policy.

Under the proposed contract, routing fields have three mutually exclusive states:
1. **FIELD ABSENT:**  
   The field does not appear in the bounded opening envelope. Current AUTO policy may fill it via provider defaults/task classification.
2. **FIELD EXPLICIT + RESOLVED:**  
   The field appears in the envelope and deterministically resolves to a known catalog item (including deterministic stripping of redundant provider prefixes or catalog aliases). The explicit value wins absolutely.
3. **FIELD EXPLICIT + UNRESOLVED:**  
   The field appears in the envelope but cannot be resolved to any known catalog entry. **It must NOT silently become an inferred replacement.** Dispatch must halt or return an explicit needs-attention error (e.g. `"Unrecognized model 'Claude Sonnet 5' requested for Claude. Coach did not choose another model because you explicitly constrained this Play."`).

## 3. Forensic Answers

### 1. Confirm the exact current route from prompt text → route constraints → model selection
- **Prompt text** enters `computeContextAwareRoute` (`src/routing-policy.ts:627`).
- `recognizeRouteConstraints` (`src/control-plane/route-constraints.ts:224`) takes `routeLines(prompt)` (first 15 lines).
- `structuredRouteField` parses:
  - `AGENT: Claude` -> `playerType: 'claude'` (recognized).
  - `MODEL: Claude Sonnet 5` -> `modelText: 'Claude Sonnet 5'` -> `exactAlias` against `['opus', 'sonnet']` -> `undefined` (unrecognized, dropped).
  - `REASONING: Medium` -> `effort: 'medium'` (recognized).
- `recognizeRouteConstraints` returns `{ playerType: 'claude', model: undefined, effort: 'medium', recognized: ['player', 'effort'] }`.
- `computeContextAwareRoute` calls `constrainedSelection` (`src/routing-policy.ts:561`).
- Since `constraints.model` is `undefined`, it evaluates `ClaudeRoutingPolicy.selectModel('architecture', snapshot)`.

- Decision staged: `Claude · Opus · Medium`.

### 2. Confirm why "Claude Sonnet 5" fails while Claude and Medium succeed
- **Claude succeeds:** `AGENT:` is an alias in `ROUTE_FIELD_ALIASES` (`dimension: 'player'`). Normalized string `'claude'` matches the candidate alias `'claude'` exactly.
- **Medium succeeds:** `REASONING:` is an alias in `ROUTE_FIELD_ALIASES` (`dimension: 'effort'`). Normalized `'medium'` matches `/^(low|medium|high|xhigh|max)$/i` and is in Claude's `supportedEfforts`.
- **"Claude Sonnet 5" fails:** `modelAliases` only populates literal IDs and display names from the candidate's discovered catalog (e.g. `sonnet` and `Sonnet`). `exactAlias` compares normalized `"claude sonnet 5"` to `"sonnet"` and fails. There is currently no catalog alias or prefix-stripping rule (e.g., removing redundant provider name `"Claude "` when matching models for Player `"Claude"`, or family alias matching `"sonnet 5"` -> `"sonnet"`).

### 3. Identify the smallest seam for distinguishing: absent vs explicit/resolved vs explicit/unresolved
- **Seam Location:** `src/capability-types.ts` (`RouteConstraints`) and `src/control-plane/route-constraints.ts` (`recognizeRouteConstraints`).
- **Mechanism:**
  - Add `unresolved?: readonly { dimension: 'player' | 'model' | 'effort'; rawText: string }[];` to `RouteConstraints`.
  - In `recognizeRouteConstraints`:
    - If `structuredModel` or `modelText` exists:
      - If resolved via alias -> `model = match.value.id`, add `'model'` to `recognized`.
      - If not resolved -> record `{ dimension: 'model', rawText: modelText }` in `unresolved`.
    - If `structuredModel` does not exist: field is genuinely **absent**.
  - In `src/routing-policy.ts` (`computeContextAwareRoute` and `computeAutoRoute`):
    - Check `constraints?.unresolved`. If any unresolved constraints exist, return an error rather than falling back to `selectModel`.

### 4. Determine whether model normalization should live in route-constraints.ts or another existing catalog seam
- **Boundary Responsibility:**
  - **Envelope parsing and provider prefix stripping belong in `src/control-plane/route-constraints.ts`:**
    When `AGENT: Claude` is established, stripping a redundant leading provider name (`"Claude "`) from `"Claude Sonnet 5"` yields `"Sonnet 5"`. This is syntactic envelope normalization identical to how `withoutPresentationPrefix` strips Markdown bullets/headers.
  - **Model alias catalog mapping belongs in the capability/catalog seam (`ModelDescriptor` / `modelAliases`):**
    Each provider capability snapshot can supply standard model family aliases (e.g. `sonnet` matching `["sonnet", "sonnet 3.5", "sonnet 3.7", "sonnet 4", "sonnet 5"]`).
  - **Recommendation:** Keep syntactic envelope extraction in `route-constraints.ts` (strip candidate provider prefix if present), and expand `modelAliases()` in `route-constraints.ts` to support family base matching against `candidate.capability.models`. If a model cannot be resolved even after normalization, it becomes explicitly **unresolved**.

### 5. Identify safe formatting variants worth accepting without becoming fuzzy NLP
All of the following can be parsed deterministically with small, bounded regexes without general NLP:
- **Presentation prefixes:** Markdown headings (`#`, `##`, `###`), bullets (`-`, `*`, `+`, `1.`), block separator rules (`---`, `===`).
- **Markdown emphasis:** `**AGENT:**`, `*AGENT:*`, `__AGENT:__`, `**AGENT**:`.
- **Punctuation & whitespace:** Colons with variable spacing (`AGENT : value`, `AGENT:   value`).
- **Case variation:** `agent:`, `AGENT:`, `Agent:`.
- **Known label aliases:** `AGENT`, `PLAYER`, `MODEL`, `TARGET MODEL`, `REASONING`, `REASONING EFFORT`, `THINKING`, `THINKING / EFFORT`, `DIFFICULTY`, `ROLE`.
- **Redundant provider prefix in model value:** `AGENT: Claude` + `MODEL: Claude Sonnet 5` -> normalize model text by removing `Claude` prefix when matching against Claude's models.
- **Envelope preamble:** Titles, subtitles, or blank lines appearing within the 15-line scan window before the metadata keys.

### 8. Compatibility risk review with other subsystems
* **MANUAL Routing:** **No risk.** MANUAL routing dispatches directly to the selected Player/Model. In `routing-policy.ts`, `resolveCoachAuto` only resolves if `requested.model === 'auto'`.
* **Explicit Exclusions (`don't use Opus`):** **No risk.** Exclusions narrow the set of eligible models in `constrainedCandidates`. They do not specify an explicit required model and are tracked under `excludedModels`.
* **Terminal AUTO (`classifyShellIntent`):** **No risk.** `computeTerminalAutoRoute` only evaluates when `!constraints`. Storing unresolved constraints in `RouteConstraints` guarantees Terminal AUTO is never accidentally triggered by a prompt with unresolvable routing fields.
* **Scout AUTO (`analyzeScoutNeed`):** **No risk.** Scout AUTO is explicitly gated by `if (!constraints && !scoutOwnsCurrentContext)`. Preserving unresolved constraints prevents unwanted Scout AUTO triggers.
* **Context Affinity & Handoffs:** **No risk / Positive fix.** Currently, if a prompt contains an unresolvable model, context affinity might hand off or queue a Play with an unexpected model (Opus). Halting on unresolved constraints ensures handoff preambles and queue state are only committed with truthful, valid model constraints.
