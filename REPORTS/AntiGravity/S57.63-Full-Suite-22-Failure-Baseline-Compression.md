# VM / DOM HARNESS CLUSTER

### Affected Tests (7)
- `test/game-foundation.test.mjs`: Tests 7 and 8
- `test/routing-intelligence.test.mjs`: Tests 29, 30, 31, 32, and 33

### Mechanism
In [`src/public/index.html`](file:///C:/Users/dmcal/Documents/GitHub/SidelineCoach/src/public/index.html#L8846-L8851), settings card drag-handle initialization was added:
```javascript
const handle = document.createElement('button');
handle.id = `settingsDragHandle-${sectionId}`;
handle.type = 'button';
handle.className = 'settings-drag-handle';
handle.textContent = '⋮⋮';
handle.setAttribute('aria-label', `Reorder ${sectionId.replaceAll('-', ' ')}`);
```
Both `test/game-foundation.test.mjs` (line 100) and `test/routing-intelligence.test.mjs` (line 425) construct a lightweight browser DOM mock for VM execution. In their `document.createElement: (tag) => ({ ... })` implementation, `setAttribute` was omitted:
```javascript
createElement: (tag) => ({
  tagName: tag.toUpperCase(),
  children: [],
  appendChild: (child) => { /* ... */ },
  addEventListener: () => {},
  // setAttribute is missing!
})
```
When `index.html` loads inside `runInNewContext`, `handle.setAttribute` throws `TypeError: handle.setAttribute is not a function`. This aborts execution before the tests can interact with any elements.

### Classification
**TEST HARNESS DEFECT**

### Smallest Safe Repair Surface
Add a 1-line method to the `createElement` factory in both test files:
```javascript
setAttribute(k, v) { this[k] = v; },
```

# REAL BEHAVIORAL REGRESSIONS

### Affected Tests (1)
- `test/remote-access-v1-stage3.test.mjs:1230` (RA3E-5)

### Mechanism & Root Cause
In `test/remote-access-v1-stage3.test.mjs`, test RA3E-5 sends requests from a remote tunnel client and expects local-only endpoints to return **HTTP 403 Forbidden**:
```javascript
const res = await remoteFetch('/api/preferences', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ remoteAccess: { enabled: false } }),
});
assert.equal(res.status, 403); // Fails: received 503 Service Unavailable
```
In commit `9376156e`, `POST /api/preferences` was classified as `remote-mutate` in [`src/control-plane/remote-routes.ts`](file:///C:/Users/dmcal/Documents/GitHub/SidelineCoach/src/control-plane/remote-routes.ts#L48). When the remote request reaches [`src/control-plane/daemon.ts`](file:///C:/Users/dmcal/Documents/GitHub/SidelineCoach/src/control-plane/daemon.ts#L328), the daemon updates preferences and executes:
```javascript
if (body.remoteAccess) {
  this.syncRelayClient();
}
```
Setting `enabled: false` shuts down the daemon's relay client connection. The remote proxy/relay connection is severed mid-flight, returning **HTTP 503** to the caller instead of the expected **HTTP 403 Forbidden**.

### Classification
**REAL REGRESSION**

### Smallest Safe Repair Surface
In `src/control-plane/daemon.ts`, within the `POST /api/preferences` handler: if the request originates from a remote principal (`req.headers['x-sideline-principal'] === 'remote'`), disallow mutations to the `remoteAccess` configuration block and return HTTP 403 Forbidden.

# ENVIRONMENT / TIMING FAILURES

### Affected Tests (2)
- `test/codex-usage-self-healing.test.mjs:302` (SH-9)
- `test/remote-access-v1-stage4e-idle-liveness.test.mjs:42` (RA4E-1)

### Mechanism & Root Causes
1. **SH-9 (Calendar Rollover in Test Fixture):**
   In `test/codex-usage-self-healing.test.mjs`, the mock clock anchor was hardcoded to:
   ```javascript
   const T0 = Date.parse('2026-09-29T16:00:00.000Z');
   const S0 = Math.floor(T0 / 1000);
   const codexLimits = () => ({ primary: { resetsAt: S0 + 4 * 3600 } });
   ```
   Now that the calendar has progressed to October 2026, `Date.now()` is past the fixture's 4-hour window from September 29. When `UsageFreshnessCoordinator.rearm()` executes against system time, the calculated delay is negative (`<= 0`), triggering an immediate second self-healing read during startup.
   - **Classification:** **TIMING / FIXTURE CALENDAR DRIFT**
   - **Repair:** Anchor `resetsAt` relative to the current mock clock / execution time (`Math.floor(Date.now() / 1000) + 4 * 3600`).

2. **RA4E-1 (Idle Liveness Measurement Race):**
   In `test/remote-access-v1-stage4e-idle-liveness.test.mjs`:
   ```javascript
   const makeDaemon = async () => {
     // ...
     await daemon.start();
     return { ..., startedAt: Date.now() }; // Recorded AFTER start()
   };
   // ...
   assert.ok(h.exits[0].at - h.startedAt >= IDLE * 0.8, 'not before the idle window');
   ```
   The idle timer starts counting inside `daemon.start()`. Under full-suite load, `daemon.start()` took ~72ms. The exit happened 300ms after the internal timer started, but `h.startedAt` was timestamped 72ms late, yielding an apparent duration of 228ms (`< 240ms = 300 * 0.8`).
   - **Classification:** **ENVIRONMENT / TIMING RACE**
   - **Repair:** Capture `startedAt` before `daemon.start()`.
