## 4. Static Gap Analysis

The pipeline fails on GS3 due to five specific gaps:

1. **Script Heuristic Myopia:** `detectPreviewCandidates()` exclusively inspects `package.json` scripts and framework CLI names. A project without `npm run dev` or a Vite/Next config produces zero candidates.
2. **Immediate Failure Exit:** Line 487 of [`src/preview-discovery.ts`](file:///C:/Users/dmcal/Documents/GitHub/SidelineCoach/src/preview-discovery.ts#L487) treats `candidates.length === 0` as a fatal condition: `reason: 'no-web-app'`. It performs no fallback check for static web content.
3. **Absence of HTML Discovery:** There is no logic to scan the workspace root or conventional public folders for `.html` entrypoints.
4. **Missing Static Server Bridge:** When no server is running, the Stadium has no mechanism to host static files over HTTP. Because `parsePreviewUrl()` correctly and strictly forbids `file://`, static files have no valid protocol to reach `buildEndpoint()`.
5. **Misleading Framework-Biased Copy:** Reporting `"Sideline couldn't find a web app in this Game"` falsely implies GS3 is unsupported or defective, rather than recognizing that GS3 is a static multi-page browser application awaiting a local host.

## 6. Multi-Page / Chooser Rule

When a Game contains multiple legitimate HTML files (e.g., GS3 with `index.html`, `index2.html`, `index3.html`, `settings.html`):

1. **Canonical Home Rule:**  
   `index.html` is the standard root entrypoint of the web. When `index.html` exists at the workspace root or inside `public/`, it **automatically wins** as the primary preview endpoint. Dad is taken directly to `index.html` without interruption or popups.

2. **Cataloging Alternates:**  
   The discovery engine catalogs secondary HTML files as `alternates: ['index2.html', 'index3.html', 'settings.html']` in the resolution payload.

3. **Active Editor Document Relationship:**  
   - **Invariant:** The active editor tab is a *contextual hint*, **NEVER a silent mutator of the Game's canonical identity**.
   - If Dad is currently editing `index3.html` and clicks "Preview Work", the primary preview still opens `index.html` (the canonical home), but the Preview Sheet header or status bar provides an instant one-click pill/chip:  
     `"Switch to active file: index3.html"`.
   - Alternatively, right-clicking `index3.html` in the file tree and choosing `"Preview This Document"` targets `index3.html` directly without changing the Game's default home.

4. **Chooser Activation Boundary:**  
   The interactive chooser (VS Code QuickPick or Dashboard dropdown) appears **only** when genuine ambiguity exists:
   - Multiple HTML candidates exist at the root, AND
   - None is named `index.html`, AND
   - No declaration exists in `.sideline/game.json`, AND
   - No choice has been previously remembered for this Game.
   When Dad selects a page, Sideline stores it in `workspaceState` so subsequent clicks immediately launch that page.

## 7. Static Serving Strategy

### Evaluation of Options

| Strategy | Security Boundary | Standards Compliance | Verdict |
|---|---|---|---|
| **Raw `file://` URLs** | ❌ Rejects origin isolation, blocks Web Workers, cookies, and localStorage. | ❌ Browsers block ES module imports (`import './js/state.js'`) and `fetch()` over `file://`. Breaks GS3 immediately. | **REJECTED** (Violates locked principles) |
| **Reuse `CoachServer` (Dashboard)** | ❌ **Severe security vulnerability.** Untrusted Game JS would run on the exact same origin as the Coach Dashboard (`http://127.0.0.1:54321`), gaining direct access to Coach session cookies, tokens, and internal `/api/*` management routes. | ✅ HTTP serving. | **REJECTED** (Violates origin isolation) |
| **VS Code Webviews** | ⚠️ Runs inside VS Code tabs under `vscode-webview://`, not system browser or Coach dashboard. | ⚠️ Complex postMessage bridges; breaks standard navigation links between multi-page HTML documents. | **REJECTED** (Creates second preview architecture) |
| **Stadium-Scoped Ephemeral Static Server (`StaticPreviewServer`)** | ✅ **Isolated origin.** Runs on an independent ephemeral port (`127.0.0.1:<random>`). Completely isolated from CoachServer and other Games. Path-traversal hardened. | ✅ Standard HTTP/1.1 server. Full support for ES modules, MIME types, CORS, and `fetch()`. Emits standard `PreviewEndpoint`. | **SELECTED (RECOMMENDED)** |

### Architecture of `StaticPreviewServer`

- **Implementation:** Built directly using Node's standard `http` module (`http.createServer`). Zero external dependencies (`express`, `serve`, etc. are not needed).
- **Binding:** Binds strictly to `127.0.0.1` on port `0` (OS-allocated ephemeral port). Never binds to `0.0.0.0`.
- **Root & Traversal Guard:** Rooted strictly at `ctx.binding.rootFsPath`. Every incoming request normalizes the URL path, decodes URI components, strips query strings, and verifies that the canonical resolved path starts with the Game root (`isWithin(targetPath, rootFsPath)`). Any attempt to access `..` or traverse outside returns HTTP `403 Forbidden`.
- **Protected Files:** Explicitly refuses requests for hidden files, `.git`, `.sideline`, and `.env*` (HTTP `404 Not Found`).
- **MIME Types:** Clean built-in dictionary mapping `.html` (`text/html; charset=utf-8`), `.js`/`.mjs` (`application/javascript`), `.css` (`text/css`), `.json` (`application/json`), `.svg` (`image/svg+xml`), `.png`, `.jpg`, `.woff2`, etc.
- **Lifecycle Management:** Owned by the Stadium extension host. Started lazily when a static Game requests preview. Stays alive while the Game is active, and is cleanly closed on extension deactivation or Game context switch.

## 9. Security Invariants

1. **No `file://` Scheme:** Enforced by [`parsePreviewUrl()`](file:///C:/Users/dmcal/Documents/GitHub/SidelineCoach/src/preview-discovery.ts#L110-L117).
2. **Strict Loopback Binding:** The static server binds to `127.0.0.1` only. It is completely inaccessible to other devices on Dad's LAN or WiFi.
3. **Origin Isolation:** The static server runs on an ephemeral port distinct from `CoachServer` (ports 54321 / 3100). The browser enforces the Same-Origin Policy: Game code cannot read Coach cookies, Coach localStorage, or issue requests to authenticated `/api/*` endpoints.
4. **Path Traversal Defense:** Strict rejection of `..`, null-byte injections, and path escapes outside `ctx.binding.rootFsPath`.
5. **Secret and Dotfile Exclusions:** Immediate HTTP `404` for any path containing `/.git/`, `/.sideline/`, `/.vscode/`, or matching `/\.env(\..+)?$/i`.
6. **Read-Only HTTP Methods:** Server only responds to `GET` and `HEAD`. Any `POST`, `PUT`, `DELETE`, or `PATCH` request immediately receives `405 Method Not Allowed`.
