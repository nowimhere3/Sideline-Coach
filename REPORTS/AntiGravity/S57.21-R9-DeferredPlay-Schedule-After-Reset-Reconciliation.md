## 4. CANONICAL DEFERREDPLAY STATE MACHINE

```
               [ Dad Contextual Action: "Schedule after reset" ]
                                      │
                                      ▼
                                ┌───────────┐
                ┌───────────────│  waiting  │───────────────┐
                │               └───────────┘               │
                │                     │                     │
    Dad clicks Cancel                 │ Reset Event         │ Dad clicks Cancel
                │                     │  OR Fallback Timer  │
                ▼                     ▼                     ▼
          ┌───────────┐         ┌───────────┐         ┌───────────┐
          │ cancelled │         │  firing   │         │ cancelled │
          └───────────┘         └───────────┘         └───────────┘
                                      │
                        Revalidation & Router Dispatch
                                      │
                         ┌────────────┴────────────┐
                         │                         │
                 Revalidation Pass         Revalidation Fail
                 Router Dispatched /       (stale, seat gone,
                 Enqueued to PlayQueue      daemon restart mid-flight)
                         │                         │
                         ▼                         ▼
                  ┌─────────────┐        ┌─────────────────┐
                  │ handed-off  │        │ needs-attention │
                  └─────────────┘        └─────────────────┘
                         │                         │
                 [ R9 Relinquishes ]        Dad clicks Retry
                 [    Ownership    ]               │
                                                   ▼
                                             ┌───────────┐
                                             │  firing   │
                                             └───────────┘
```

### State Definitions & Invariants

| State | Semantic Meaning | Allowed Transitions | Invariants |
|---|---|---|---|
| `waiting` | Play intent is armed and durably stored, waiting for provider reset horizon `cycleResetsAt`. | `→ firing`<br>`→ cancelled` | Never dispatched to router while in this state. |
| `firing` | Reset trigger fired; in-flight revalidation and router handoff currently executing. | `→ handed-off`<br>`→ needs-attention` | In-memory execution lock prevents concurrent triggers. Cannot transition directly to `waiting` or `cancelled`. |
| `handed-off` | Successfully revalidated and accepted by `router.dispatch` (either active dispatch or enrolled in `PlayQueue`). | **Terminal for R9** (none) | R9 ownership strictly ends. Cleaned up from active scheduler. |
| `needs-attention` | Revalidation failed (quota unconfirmed, seat gone/benched) OR daemon restarted during `firing`. | `→ firing` (via Retry)<br>`→ cancelled` (via Cancel) | Never auto-retries without human or explicit fresh recovery. Carries Dad-readable `attention` string. |
| `cancelled` | Human cancelled the schedule. | **Terminal** (none) | Purged or tombstoned. Never fires. |

## 5. TRIGGER, FALLBACK, AND STARTUP FLOW

```
                          ┌───────────────────────────┐
                          │   AlarmEngine onEvent     │
                          │ alarm:reset_boundary_reached │
                          └─────────────┬─────────────┘
                                        │
                                        ▼
┌─────────────────────────┐     Match (provider, window)     ┌────────────────────────┐
│     Fallback Timer      │────►   against 'waiting'    ◄────│   Startup Scan Audit   │
│  (cycleResetsAt + 2m)   │        DeferredPlays             │   (daemon start())     │
└─────────────────────────┘             │                    └────────────────────────┘
                                        ▼
                              Acquire Firing Lock
                           (Check state === 'waiting')
                                        │
                                        ▼
                           Transition to 'firing'
                           (Persist to atomic JSON)
                                        │
                                        ▼
                           Run Revalidation Contract
                                (Section 6)
```

1. **Authoritative Wakeup:** `AlarmEngine.onEvent` emits `alarm:reset_boundary_reached` or `alarm:recovered`. The scheduler inspects all `waiting` plays for `(provider, window)`.
2. **Precision Fallback Wakeup:** When a `DeferredPlay` is loaded or created, a timer is registered for `Math.max(0, cycleResetsAt + 120_000 - Date.now())`. If the event was dropped or delayed, the timer wakes up the scheduler.
3. **Startup Recovery Wakeup:** On daemon boot, `DeferredPlayScheduler.start()` audits all stored plays:
   - If `cycleResetsAt > now`: Remains `waiting`; re-arms fallback timer.
   - If `cycleResetsAt <= now`: Transitions to `firing` and invokes immediate revalidation against fresh startup health.
4. **Epistemic Truth Invariant:** **Neither events nor timers are the authority of resource truth.** Both are wakeups. The only authority is the **Revalidation Contract** executed at the moment of firing.

## 6. REVALIDATION CONTRACT

Before a `firing` play may be passed to the router, all six canonical checks must execute in sequence:

```typescript
async function revalidateDeferredPlay(
  play: DeferredPlay,
  economics: RoutingEconomicsSnapshot,
  policy: ResourcePolicyService,
  capabilities: PlayerRoutingCapability[]
): Promise<{ ok: true } | { ok: false; reason: string }>
```

| Check | Canonical Verification Rule | Source Authority / Function | Failure Outcome |
|---|---|---|---|
| **1. Freshness** | Window telemetry must not be stale or missing. | `economics.pools[provider].windows[window].stale !== true` | Refuse: `"Provider resource status is stale; awaiting fresh update."` |
| **2. Quota Recovery** | Window has genuinely reset; utilization/conserve dropped. | `policy.get(provider).conserveLevel === 'none'` AND `remainingFraction > criticalPercent` | Refuse: `"Provider reset could not be confirmed; quota still low."` |
| **3. Seat Operability** | Exact target instance (or equivalent sibling in same seat) must be ready or busy (eligible for queue). | `capabilities.find(c => c.instanceId === play.target.playerInstanceId)` exists and `state !== 'unavailable'` | Refuse: `"Target Player seat is no longer available on field."` |
| **4. Route Catalog** | Model and effort must still exist in Player's active catalog. | `capability.capability.models.includes(play.model)` | Refuse: `"Configured model is no longer supported by Player."` |
| **5. Cancellation** | Play was not cancelled during trigger processing. | `play.state === 'firing'` | Abort firing immediately. |
| **6. No Silent Substitution** | Target must remain the Coach's selected Player. | Strict identity check: never re-run candidate selection or substitute. | Transition to `needs-attention`. **Never substitute.** |

## 7. ROUTER / PLAYQUEUE HANDOFF

R9 ownership strictly terminates at the boundary of `router.dispatch(...)`.

```
DeferredPlay Revalidation PASS
               │
               ▼
Call router.dispatch({
  gameId: play.gameId,
  playerInstanceId: play.target.playerInstanceId,
  prompt: play.prompt,
  model: play.model,
  effort: play.effort,
  constraints: play.constraints,
  whenBusy: 'queue',
  deferredPlayId: play.id
})
               │
               ├─────────────────────────────────────────┐
               ▼                                         ▼
   Target Instance is READY                   Target Instance is BUSY
               │                                         │
       Direct Dispatch                             Enqueued to PlayQueue
  router returns { success: true }           router returns { status: 'queued' }
               │                                         │
               └────────────────────┬────────────────────┘
                                    │
                                    ▼
                     DeferredPlay marked 'handed-off'
                     Durable state flushed to disk
                                    │
                                    ▼
                     [ R9 RELINQUISHES OWNERSHIP ]
               (PlayQueue or WorkLedger owns execution)
```

- If `router.dispatch` returns success (whether immediate dispatch or PlayQueue enrolment), `DeferredPlay` transitions to `handed-off`.
- `PlayQueue` does not know about scheduling; it only knows its instance is busy.
- `DeferredPlay` does not manage queue draining; the router and PlayQueue own that completely.

## 9. RESTART, DUPLICATION, AND RACE CONDITIONS

| Scenario | Risk | Reconciled Safe Handling |
|---|---|---|
| **Restart while `waiting` (reset in future)** | Loss of timer or trigger. | Store loads `waiting` plays; recalculates fallback `setTimeout` relative to `Date.now()`. |
| **Restart when reset passed while offline** | Stalled intent or unsafe fire. | S57.1 compliant: Transitions to `firing` and runs immediate revalidation against startup health. If health confirmed, dispatches; if health unconfirmed, moves to `needs-attention`. |
| **Restart while `firing`** | Duplicate dispatch if send already occurred. | Exact analogue to PlayQueue `dispatching`: maps to `needs-attention` with message: *"Coach restarted while this Play was being dispatched. Check Player, then retry or cancel."* |
| **Double-click "Schedule" in UI** | Duplicate scheduled records. | Idempotency key: `sha256(gameId + ":" + playerInstanceId + ":" + cycleResetsAt + ":" + hash(prompt))`. Backend dedupes on key and returns existing record. |
| **Simultaneous Alarm Event + Fallback Timer** | Race condition / double dispatch. | Single-flight `firingSet` in memory. Atomic check-and-set: only transitions if current persisted state is strictly `waiting`. |
| **Duplicate Alarm Events from Daemon** | Spurious trigger attempts. | Once transitioned to `firing` or `handed-off`, subsequent alarm events for the same cycle token are ignored. |

## 10. SCOUT CLAIMS ACCEPTED / REJECTED / MODIFIED

### Claim 1: "Extend PlayQueue states to include `waiting`, `firing`, `handed-off`"
- **VERDICT: REJECTED.**
- **Rationale:** Directly violates S57.1 §15.1 and Coach Invariant. PlayQueue manages FIFO instance-busy queueing. Extending it couples provider-cycle scheduling into instance availability, corrupts PlayQueue restart semantics, and breaks existing tests. `DeferredPlayStore` must be completely separate.

### Claim 2: "R9 reset-trigger and revalidation flow already exists in codebase"
- **VERDICT: REJECTED (Clarified as Reusable Ingredients Only).**
- **Rationale:** The Scout confused raw ingredients (`AlarmEngine` events, `projectRoutingEconomics`) with completed machinery. `DeferredPlay` record types, durable store, scheduler daemon, fallback timer orchestration, and contextual UI bindings do not exist.

### Claim 3: "Reset passed while offline must always transition to `needs-attention`"
- **VERDICT: REJECTED / MODIFIED.**
- **Rationale:** S57.1 §15.1 explicitly mandates "condition passed while down → re-validate" semantics. If Sideline was closed during the reset and opened 10 minutes later, it should automatically re-evaluate fresh health. If fresh health confirms the window recovered, it safely dispatches. Only if health is stale/unconfirmed does it move to `needs-attention`.

### Claim 4: "Reuse atomic file store pattern and cancellation route structures"
- **VERDICT: ACCEPTED.**
- **Rationale:** `fileQueueStore` and `/api/queue/:id/cancel` provide battle-tested, identical patterns for atomic JSON persistence and REST cancellation.
