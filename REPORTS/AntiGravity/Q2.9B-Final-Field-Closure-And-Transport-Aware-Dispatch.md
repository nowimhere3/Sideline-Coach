## Executive Summary

During field testing of Q2.9A, human operators identified three functional/routing issues and one UI status conflict:
1. **MANUAL dispatch failure for terminal-backed Players:** Selecting an On-Field Claude, AntiGravity, or Terminal Player in MANUAL mode and dispatching a Play failed with the error: `"That controlled Player has left the field."`
2. **Bench → Put on Field ("Unknown instance"):** Putting an active player (such as AntiGravity) on the bench and subsequently returning it to the field returned an error, failing to restore terminal focus.
3. **Robotic AUTO routing explanation:** When a non-controlled Player (e.g. Claude) was on field, the AUTO dispatcher displayed confusing technical jargon: `"No controlled Player on field — Put a controlled Codex on field or switch to Manual."` despite Claude clearly standing On Field.
4. **Duplicate connection pill and missing Settings shell:** The top-right global connection pill read `"Connected"`, duplicating the adjacent Game row badge (`"Game: GS3 Connected"`), and there was no settings affordance for future stadium roadmap configuration.

All four areas have been diagnosed, resolved, and automated with regression tests.

## Detailed Forensic Diagnosis and Implementation

### 1. Transport-Aware MANUAL Dispatch (`src/stadium-client.ts`)

#### Root Cause
In `src/stadium-client.ts`, `executeDispatch()` previously inspected only `if (playerInstanceId && this.options.playerControlHost)`. Because Q2.9 assigned opaque `instanceId`s to every Player on the roster (both controlled agents and terminal-backed players), `StadiumClient` unconditionally forwarded all dispatches to `playerControlHost.deliver()`. For terminal-backed players (Claude, AntiGravity, Terminal), `playerControlHost` held no control binding and returned `{ kind: 'refused', reason: 'closed', message: 'That controlled Player has left the field.' }`. The method sent `dispatch.rejected` immediately, never reaching the legacy terminal transport branch.

#### Resolution
`StadiumClient.executeDispatch` is now transport-aware:
1. If `playerInstanceId` is present and `this.options.playerRoster` is available, it queries `playerRoster.resolve(playerInstanceId)`.
2. If `resolution.state === 'pending'`, it rejects with `"That Player is reconnecting — try again in a moment."`
3. If `resolution.state === 'unavailable'`, it rejects with `resolution.message`.
4. If `resolution.state === 'live'`:
   - If `resolution.transport === 'controlled'`, it delegates to `this.deliverControlled(params)`, routing through `playerControlHost.deliver()`.
   - If `resolution.transport === 'legacy'`, it delegates to `this.deliverTerminal(params, resolution.terminal.name)`, delivering text to the player's dedicated terminal via `this.options.sendTerminalText()`.
5. Fallbacks are preserved for standalone test environments where `playerRoster` is mocked or omitted.

### 2. Bench → Put on Field Lifecycle & Presentation Focus (`src/player-roster.ts`, `src/server.ts`, `src/extension.ts`)

#### Root Cause
1. In `src/player-roster.ts`, `putInstanceOnField(instanceId)` flipped `record.onField = true` in the instance book, but failed to restore presentation focus: it never called `.show(true)` on `this.terminalByInstance` or `this.controlledByInstance`.
2. In `putOnField(id)` and `takeOffField(instanceId)`, if an ID was passed without an exact match, methods did not cross-resolve between `instanceId` and `playerType`.
3. In `src/extension.ts`, `handlePlayerLifecycle` only read `params.playerInstanceId`, missing calls where `params.instanceId` or `params.playerId` was used.
4. In `src/server.ts`, `/api/players/instance/:instanceId/{field|bench|remove}` endpoints were absent. Direct requests to `/api/players/instance/antigravity_1/field` were incorrectly sliced as player ID `"instance/antigravity_1"`, failing with `"Unknown Player."`

#### Resolution
1. **`PlayerRoster.putInstanceOnField(instanceId)`** now:
   - Resolves by `instanceId`, with safe fallback to `this.book.byType(instanceId)[0]`.
   - Sets `record.onField = true`.
   - Restores terminal focus: calls `this.terminalByInstance.get(instanceId)?.show(true)` and `this.controlledByInstance.get(instanceId)?.terminal.show(true)`.
   - Fires `this.changed`.
2. **`PlayerRoster.putOnField(id)`** checks if `id` is an active `instanceId` in the book; if so, it delegates directly to `putInstanceOnField(id)`.
3. **`PlayerRoster.takeOffField(instanceId)`** cleanly flips `onField = false` without retiring the instance or closing the process/terminal.
4. **`src/extension.ts`** extracts `params.playerInstanceId ?? params.instanceId ?? params.playerId`.
5. **`src/server.ts`** explicitly handles `/api/players/instance/:instanceId/{field|bench|remove}`, matching the daemon implementation.

### 3. Dadified AUTO Staged-Route Explanation (`src/routing-policy.ts`)

#### Root Cause
In `src/routing-policy.ts`, `computeAutoRoute()` assumed any failure to find a controlled candidate meant a controlled Player was missing from the field, emitting:
`"No controlled Player on field — Put a controlled Codex on field or switch to Manual."`
This created confusion for users who had Claude or AntiGravity On Field.

#### Resolution
`computeAutoRoute()` now checks the on-field candidates truthfully:
1. **If nobody is on field (`candidates.length === 0`):**
   `"No Player is on field. Add a Player or put one on field to continue."`
2. **If one non-controlled Player is on field (e.g. Claude):**
   `"Claude is on field. AUTO is only available with Codex right now. Switch to Manual to send this Play to Claude, or add Codex for AUTO."`
3. **If multiple non-controlled Players are on field (e.g. Claude, AntiGravity):**
   `"Claude, AntiGravity are on field. AUTO is only available with Codex right now. Switch to Manual to send this Play, or add Codex for AUTO."`
4. **If a controlled Player is on field:** It proceeds with standard capability evaluation and task classification.

## WAS / IS / WILL BE

### WAS
Manual dispatch to terminal-backed players threw `"That controlled Player has left the field."` because all dispatches were routed through `PlayerControlHost`. Benching and returning players risked `"Unknown instance"` errors and failed to refocus terminals. AUTO routing displayed robotic jargon (`"No controlled Player on field..."`) when non-controlled agents were on field. The header had redundant `"Connected"` labels with no settings affordance.

### IS
Dispatch is transport-aware, correctly routing controlled players to `PlayerControlHost` and terminal players to live VS Code terminals. Benching and returning maintains stable `instanceId` identity and brings terminals to front focus. AUTO routing clearly explains why Codex is needed and suggests switching to Manual for on-field terminal players. Header displays `"Coach Online"` (green), and a restrained Settings panel provides future roadmap breadcrumbs with effortless return to Sideline.

### WILL BE
Next iterations can attach real configuration persistence to the Settings breadcrumbs (Game Setup, Providers, Routing, Budgets), expand multi-agent orchestration, and introduce custom adapter definitions.
