## Executive Summary

During human field testing of Q2.10A, clicking **Recruit Players → Check Players** failed immediately with:
```text
RPC request 'player.discover' to Stadium timed out.
```
This failure blocked all human player recruitment and roster management.

Forensic analysis proves that the failure is caused by a timing budget mismatch introduced in Q2.10A:
1. The Control Plane daemon enforces a hardcoded **5,000 ms (5.00-second)** deadline on all Stadium RPC calls.
2. Q2.10A added synchronous `probeClaudeControls` into the critical path of `player.discover`, running 3 concurrent PowerShell probes for Claude CLI controls (`/model`, `/effort`, `--version`).
3. On Windows, `claude -p` without stdin redirection incurs an internal 3.0-second delay waiting for piped input (`"Warning: no stdin data received in 3s, proceeding without it"`), plus ~2.6–3.0 seconds of process spawn and CLI bundle startup overhead.
4. The measured duration of `probeClaudeControls` is **6,011 ms (6.01 seconds)**.
5. Because **6,011 ms > 5,000 ms**, the Control Plane daemon reliably aborts the RPC request at 5.0 seconds and returns HTTP 500 to the browser before the Stadium finishes probing.

This is a deterministic runtime failure caused by coupling optional capability enrichment synchronously into the critical player discovery path. Stale daemons or zombie processes did **not** cause or contribute to this failure.

## 5. Blocking Call / Root Cause Analysis

- **A. Claude control probe exceeds RPC timeout:** **TRUE (Direct Trigger)**  
  `probeClaudeControls` requires ~6.01 seconds on Windows, directly exceeding the 5.00-second RPC deadline.
- **B. Claude CLI probe hangs:** **FALSE**  
  The probes do not hang. They exit cleanly with code 0 and return valid introspection data:
  - Probe 0 output: `"Current model: Opus 5 (effort: high)..."`
  - Probe 1 output: `"Usage: /effort <low|medium|high|xhigh|max|auto>..."`
  - Probe 2 output: `"2.1.270 (Claude Code)"`
- **C. Stadium player.discover handler never returns:** **FALSE**  
  The Stadium handler completes at ~6.01s and sends its JSON-RPC response, but the Control Plane daemon has already deleted the pending RPC ID from `pendingRpcRequests` at 5.00s and drops the late response.
- **D. RPC timeout is shorter than the new discovery budget:** **TRUE (Primary Architectural Cause)**  
  `daemon.ts` allows only 5 seconds, whereas `probeClaudeControls` allows up to 20 seconds and normally consumes 6 seconds.
- **E. One Promise/probe failure blocks the whole discovery result:** **TRUE (Product Invariant Violation)**  
  Because `probeControls` is awaited sequentially inside `discover()`, a slow capability probe on a single provider (Claude) blocks the entire discovery result, preventing discovery of Codex, Terminal, and Antigravity.
- **F. Stale Stadium host:** **FALSE** (Verified fresh, PID 15152/38904).
- **G. Stale detached Control Plane:** **FALSE** (Verified fresh, PID 23800).
- **H. Bridge/session mismatch:** **FALSE** (Diagnostic session routing verified).
- **I. Other Contributing Mechanics:**
  1. **Claude CLI `-p` Stdin Wait:** When executed in non-interactive print mode (`-p`) without piped stdin input or stdin redirection, the Claude CLI waits 3.0 seconds before proceeding:
     `"Warning: no stdin data received in 3s, proceeding without it. If piping from a slow command, redirect stdin explicitly: < /dev/null to skip, or wait longer."`
  2. **Process Overhead on Windows:** Launching PowerShell and initializing Node.js / Claude CLI takes ~2.6–3.0 seconds under normal load.
  3. Prepending `$null | ` to the PowerShell command reduces probe duration from 6.01s to **3.66s**, which is still dangerously close to 5.0s and susceptible to OS jitter.

## 8. Correct Architectural Fix

### Decouple Core Player Discovery from Capability Inspection (Asynchronous Enrichment)
1. **Fast Core Discovery (< 500 ms):**  
   `player.discover` RPC must only perform lightweight checks:
   - Command presence (`where.exe`)
   - Process table scan (`listProcesses`)
   - Return catalog entries immediately with `controls: undefined` (`Claude: Ready`, `Controls: Unknown`).
2. **Asynchronous Capability Enrichment:**  
   - Capability introspection (`/model`, `/effort`, version) must be initiated in the background or triggered on-demand (e.g. when a player is recruited or put on field).
   - When background probes complete, the Stadium emits `sendCapabilitySnapshot()` / `this.changed.fire()`.
   - The Control Plane updates its cache and pushes the enriched capability profile to the UI via SSE/WebSocket.
3. **Guarantees the Critical Product Invariant:**  
   Provider capability enrichment can **never** degrade or take down basic Player discovery and recruitment.

---

## 9. Smallest Safe Implementation Fix

If keeping the probe within the discovery flow in the immediate term:
1. **Eliminate Claude CLI 3-Second Stdin Delay:**  
   In `src/player-roster.ts:46-47`, pass empty input or redirect stdin (`$null | & claude ...` or `{ input: '' }` in `execFileAsync`) to skip the 3-second wait.
2. **Enforce a Strict Cap on Capability Probes in Discovery:**  
   Wrap `probeClaudeControls` in a short timeout race (e.g. 2,000 ms). If it does not complete within 2.0s, return `undefined` so discovery completes immediately.
3. **Increase Stadium RPC Timeout:**  
   In `src/control-plane/daemon.ts:1137`, increase the default `sendRpcToStadium` timeout from `5000` to `10000` or `15000` ms.
