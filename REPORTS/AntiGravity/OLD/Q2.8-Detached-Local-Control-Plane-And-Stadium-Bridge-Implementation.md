## 2. MODULE ARCHITECTURE & IMPLEMENTATION DETAILS

### 1. `src/control-plane/protocol.ts`
- Implements versioned (`CONTROL_PLANE_PROTOCOL_VERSION = 1`) typed JSON-RPC 2.0 frames.
- Framing types: `stadium.hello`, `stadium.welcome`, `stadium.heartbeat`, `game.connected`, `game.disconnected`, `roster.snapshot`, `roster.changed`, `capability.snapshot`, `capability.changed`, `report.snapshot`, `report.changed`, `turn.changed`, `dispatch.request`, `dispatch.accepted`, `dispatch.rejected`, `player.action`, and `capability.refresh`.
- Helper builders and type guards (`isJsonRpcRequest`, `isJsonRpcNotification`, `isJsonRpcResponse`, `isJsonRpcError`).

### 2. `src/control-plane/stadium-registry.ts`
- In-memory registry tracking live Stadium sessions (`StadiumSession`) by session `instanceId`.
- Manages Game bindings, historical known games, and active connections.
- Detects multi-window conflicts: if two active sessions claim the same `gameId`, marks connection status as `conflicted`.
- Provides Game-scoped queries: `getRosterForGame(gameId)`, `getCapabilitiesForGame(gameId)`, `getReportsForGame(gameId)`.

### 3. `src/control-plane/router.ts`
- Handles browser dispatches from `POST /api/dispatch`.
- Validates Game connectivity (`400 Bad Request` if offline; `409 Conflict` if conflicted).
- Rejects cross-stadium targeting mismatches (`409 Conflict`).
- Implements duplicate SEND guard: blocks subsequent dispatches while a target player dispatch is in flight.
- Enforces two-phase ingress acknowledgements:
  1. Emits `Sending…`
  2. Sends `dispatch.request` to Stadium session.
  3. Waits for `dispatch.accepted` from Stadium -> emits `Received`.
  4. If WebSocket drops before confirmation -> emits `Unknown` (C8/C9/P20/P21 certified invariant).

### 4. `src/control-plane/daemon.ts`
- Standalone HTTP server + `ws` WebSocketServer (`/stadium`).
- Serves static UI (`src/public/index.html`), SSE stream (`/api/events`), `/api/status`, `/api/games`, `/api/game/select`, `/api/dispatch`, `/api/reports`, `/api/report`, `/api/health`, and player action proxies.
- Authenticates requests against `~/.sideline/token` (`0600`).
- Writes discovery record to `~/.sideline/control-plane.json` upon binding port.
- Connected-refcount lifecycle: starts 30-minute idle timer when connected session count drops to 0.
- Cleans up discovery record and signal listeners on shutdown.

### 5. `src/control-plane/launcher.ts`
- Extension-side orchestrator: `ensureControlPlaneRunning()`.
- Discovers `control-plane.json`, verifies PID liveness via `process.kill(pid, 0)` and HTTP `GET /api/health`.
- Wins race via atomic lockfile `~/.sideline/control-plane.lock` with `O_EXCL` (`fs.openSync(lockPath, 'wx')`).
- Automatically cleans up stale lockfiles (>8s) and dead PID discovery records.
- Spawns daemon detached: `detached: true, windowsHide: true, child.unref(), stdio: ['ignore', logFd, logFd]`.

### 6. `src/stadium-client.ts`
- Outbound WebSocket client running inside VS Code extension host.
- Authenticates via token in `stadium.hello`.
- Immediately announces initial Game context, roster snapshot, capability snapshot, and report snapshot.
- Listens for local changes (`playerRoster.onDidChange`, `turnChanged`) and streams updates to Control Plane.
- Handles inbound RPC `dispatch.request`: invokes `playerControlHost.deliver(...)` for controlled players or terminal for legacy routes; returns `dispatch.accepted` only when downstream provider ingress is confirmed.
- Automatic reconnect with exponential backoff if connection drops.

### 7. `src/game-identity.ts` & `src/extension.ts`
- `getDurableStadiumId(dir?)`: reads/creates `~/.sideline/stadium-id`, prefixed with `stadium_`.
- `createSessionInstanceId(stadiumId)`: generates unique `inst_${stadiumId}_p${pid}_${timestamp}_${counter}`.
- `extension.ts`: extension activates `StadiumClient` and binds **zero** listener ports; status bar reflects connection to detached Control Plane.
