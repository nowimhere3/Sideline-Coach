## 2. INVARIANT ADHERENCE & CRITICAL CORRECTION

### Invariant: Game ≠ Stadium

| Concept | Definition | Lifetime / Scope | Example |
| :--- | :--- | :--- | :--- |
| **Game** | The durable logical project / codebase being coached | Spans machines, clones, branches, paths, and renames | `game-git-3b9a712f0e42d...` (`Sideline Coach`) |
| **Stadium** | The execution environment running that Game | Machine-, OS-, and mount-specific runtime context | `stadium-win32-desktop` (`Windows`) |

### Critical Architectural Correction: Provider Authority vs Game Identity

The approved architecture explicitly separated logical Game identity from provider session authority:

> **Rule:** `Stable Game identity ≠ automatic provider-session authority; same Game + changed root still requires provider authority re-proof.`

- **Codex Adapter Integrity:** The Codex provider adapter strictly enforces `validateStoredThread` checking `thread.cwd === gameRoot`. This validation is preserved without modification.
- **Zero Metadata Spoofing:** Coach never rewrites provider conversation metadata or edits provider-side configuration files.
- **Fail-Safe Quarantine:** When a project folder is moved or mounted under a different path, the logical Game identity is recognized, but any surviving provider thread recorded under the old path triggers `cwd-contradiction`, safely transitioning the Player instance to `needs-decision` with zero Plays dispatched.

## 3. IMPLEMENTATION DETAILS BY COMPONENT

### A. Game Identity Module (`src/game-identity.ts`)
- **Zero VS Code Dependency:** Pure TypeScript module; fully unit-testable outside the VS Code extension host.
- **Git URL Normalization (`normalizeGitUrl`):** Handles SSH (`git@github.com:org/repo.git`), HTTPS (`https://github.com/org/repo.git`), Git protocol (`git://github.com/org/repo.git`), file paths, SCP syntax, trailing slashes, `.git` suffixes, and case insensitivity.
- **Stadium Identity (`getStadiumIdentity`):** Resolves OS platform (`win32` → `Windows`, `darwin` → `macOS`, `linux` → `Linux`) and host hostname.
- **Git Remote Discovery (`readGitRemoteOriginFromConfig`):** Reads `.git/config` synchronously to extract remote origin URLs reliably without spawning external `git` processes.
- **Resolution Ladder (`resolveGameContextSync`):**
  1. Checks for `.sideline/game.json` marker.
  2. Reads `.git/config` remote origin URL and computes SHA-256 fingerprint (`game-git-<sha[:16]>`).
  3. Checks/registers non-Git directories in local registry (`game-local-<uuid>`).
  4. Returns `game-unknown` if no workspace folder exists.

### B. Player Control Bindings & Host (`src/player-control/`)
- **`bindings.ts`:**
  - Added optional `gameId?: string` to `ControlledBindingRecord`.
  - Schema validator `isControlledBindingRecord` whitelists 7-key (legacy) and 8-key records.
  - `planControlledRestores()` accepts `activeGameId?: string`. Mismatched games are quarantined to `needs-decision` with reason `cross-game-quarantine`. Legacy 7-key records without `gameId` are safely accepted and backfilled on restore.
- **`contract.ts`:**
  - Added `gameId?: string` to `ControlOpenRequest`.
- **`host.ts`:**
  - `open()` persists `gameId` into `ControlledBindingRecord`.
  - `restore()` validates `request.gameId === record.gameId`; if missing on legacy records, backfills `gameId` upon successful resume.

### C. Player Roster (`src/player-roster.ts`)
- Injected `getGameContext: () => GameContext` (backed by VS Code `globalState` and `resolveGameContextSync`).
- `planRestores()` passes `activeGameId` to prevent cross-game session resurrection.
- `putControlledPlayerOnField()` guards against unresolved Games (`isGameResolved()`).
- Passes `gameId` to `host.open()` and `host.restore()`.

### D. Coach Server & API (`src/server.ts`)
- `buildStatus()` exposes canonical `game: GameContext` and `stadium: StadiumContext`.
- `/api/dispatch` validates `payload.gameId === activeGameId`. Returns `409 Conflict` (`game-mismatch`) on mismatch, and `400 Bad Request` (`game-unresolved`) if active Game is Unknown.
- `describeReport()` attaches `gameId: this.gameContext.gameId` to discovered reports.
- Registers file watcher on `.sideline/game.json` to broadcast `status` on marker updates.

### E. Extension Entry Point (`src/extension.ts`)
- Wires `globalState` into `resolveGameContextSync` for non-Git workspace registry persistence.
- Injects `getGameContext` into `PlayerRoster` and `CoachServer`.

### F. Browser UI (`src/public/index.html` — Option A)
- Header displays canonical Game (`Game: GS3`) via `#projectName` and quiet Stadium chip (`Stadium: Windows`) via `#stadiumName`.
- `renderStatus()` updates Game and Stadium DOM elements.
- `dispatch()` includes `gameId: currentGameId` in dispatch payload.
- Guards against unknown Game: disables dispatch button and shows tooltip if active Game is unresolved.
