## 1. EXECUTIVE SUMMARY

The Sideline Coach Team / Roster UI previously exposed raw internal process and shell plumbing (e.g. `Command failed: powershell.exe -NoLogo -NoProfile ...`, `Get-Command`, `ConvertTo-Json`, `[pscustomobject]`, `stdout closed`, stack traces) directly on customer-facing Player cards whenever a Controlled Player failed to reopen or restore.

This defect was traced to failure normalization:
- `src/player-control/codex-app-server.ts`: In `restore()`, the unexpected / launch catch block blindly concatenated `${message}` into the customer string contract. In `open()`, unhandled `resolveLaunch()` rejections leaked raw Node child-process errors.
- `src/player-control/structured-print.ts`: Catch blocks in `describeSpawnError()`, `open()`, and `restore()` passed raw process error strings directly into user-facing fields.

This implementation normalizes customer-facing strings across all Controlled Player failure paths to concise, human-safe summaries (`Coach couldn't reopen this Player's conversation.`) while preserving technical evidence in internal diagnostics (`outcome.diagnostic` and Dev Mode notices).

All 957 tests in the full test suite pass with zero regressions.

---

## 2. ROOT CAUSE CONFIRMATION

1. **Codex Catch Path (`src/player-control/codex-app-server.ts`):**
   - Line 438 concatenated raw error text:
     ```typescript
     return { kind: 'needs-decision', message: `Coach couldn't reopen this Player's conversation. ${message}`, capabilities };
     ```
   - On Windows, binary lookup or child-process spawn errors produced Node `execFileAsync` messages containing the entire PowerShell script invocation.
2. **Structured Print Catch Path (`src/player-control/structured-print.ts`):**
   - `describeSpawnError()` stringified unknown spawn errors into customer-facing text without checking for plumbing tokens.
   - Session verification and creation failures returned unnormalized errors into customer-facing message fields.
3. **Roster Presentation Flow (`src/player-roster.ts`):**
   - `restoreControlled()` passed `outcome.message` directly into `binding.stateMessage` and `binding.presentation.unavailable()`, directly rendering raw shell commands on the customer Player card.

## 3. IMPLEMENTATION DETAILS

### 3.1 Normalized String Contract & Safety Helpers
**File:** `src/player-control/contract.ts`
- Added optional `diagnostic?: string` to `ControlRestoreOutcome` so adapters can preserve raw errors for Dev Mode/triage without polluting customer contracts.
- Added `containsTechnicalPlumbing(text: string): boolean`:
  - Detects shell command signatures: `command failed`, `powershell`, `cmd.exe`, `/bin/sh`, `Get-Command`, `ConvertTo-Json`, `[pscustomobject]`, `-erroraction`, `-nologo`, `-noprofile`.
  - Detects process/system error signatures: `ENOENT`, `EACCES`, `EPERM`, `ECONNREFUSED`, `ECONNRESET`, `spawn`, `exited with code`, `stdout closed`, `stderr closed`.
  - Detects stack traces: `\bat\s+(?:[A-Za-z]:\\|\/|\w+\.)`.
- Added `sanitizeCustomerMessage(message, fallback): string`:
  - Returns `fallback` if `message` is undefined, empty, or contains technical plumbing.
  - Retains domain-safe messages (e.g. Game CWD mismatch) that do not contain plumbing.

### 3.2 Codex Adapter Normalization
**File:** `src/player-control/codex-app-server.ts`
- In `open()`: Wrapped `resolveLaunch(options)` in a `try / catch` to cleanly catch missing CLI binaries and throw `ControlOpenError('failed', 'Codex is not installed or could not be found in this Stadium.')`.
- In `open()` catch block: Sanitized customer-facing error messages via `sanitizeCustomerMessage(message, 'Codex failed to start.')`.
- In `restore()` catch block: Checked `containsTechnicalPlumbing(message)`. If plumbing is present, normalized to `"Coach couldn't reopen this Player's conversation."` while preserving `message` in `outcome.diagnostic`. Non-plumbing domain errors (such as Game CWD mismatch) remain informative.

### 3.3 Structured Print Adapter Normalization
**File:** `src/player-control/structured-print.ts`
- In `describeSpawnError()`: When plumbing is detected in `messageOf(error)`, returns clean `${dialect.displayName} couldn't start.` instead of raw process errors.
- In `open()`: Sanitized session creation errors before throwing `ControlOpenError`.
- In `restore()`: Sanitized `verifyContract()` and `checkSession()` failures, returning `message: "Coach couldn't reopen this Player's conversation."` and storing the raw error in `outcome.diagnostic`.

### 3.4 Player Roster Diagnostic Preservation
**File:** `src/player-roster.ts`
- In `restoreControlled()`: When `outcome.diagnostic` is present on failure, emitted `binding.presentation.notice(\`Diagnostic: \${outcome.diagnostic}\`)` to ensure diagnostics remain available in Dev Mode / terminal logs without cluttering the Player card.
